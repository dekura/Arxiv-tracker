## 2611.23375 · Where the Tokens Go: Heat, Entropy and Error in Agentic Coding
*Token 流向何处：Agentic Coding 中的热、熵与误差*

- Alán Aspuru-Guzik, Varinia Bernales
- [Abs](https://arxiv.org/abs/2611.23375v1) · [PDF](https://arxiv.org/pdf/2611.23375v1)
- **核心问题**：编码智能体按 token 计费，但缺乏理论说明 token 究竟买到了什么，成功编码运行的成本结构不明。
- **关键困难**：现有软件工程缺乏 token 成本的物理式分解，无法区分有效修改与无效往返，测试套件判定还受环境影响。
- **解决方案**：构造编码—去编码循环，记录每次模型调用 token；以测试套件为麦克斯韦妖，将成本分为功与热，并用重复循环成本涨落定义软件温度，借 Jarzynski 等式估计自由能。
- **主要结果**：成功运行约 80% token 为热；自由能为平均成本 14–22%；编码成本是去编码的 1.1–1.5 倍；软件温度随采样温度升高。
- **未来方向**：可发展基于热力学的编码智能体分析与优化工具；测试套件判定受环境影响。

## 2611.22136 · Big Brains, Tiny Board: Pupavision, an Agentic Physical AI Instrument for Monitoring Drosophila Pupariation and Lifecycle Transitions
*大模型，小主板：Pupavision，用于监测果蝇化蛹与生命周期转变的智能体物理 AI 仪器*

- Joel Sadler, Daniel Graham, Melanie Worley
- [Abs](https://arxiv.org/abs/2611.22136v1) · [PDF](https://arxiv.org/pdf/2611.22136v1)
- **核心问题**：生物实验监测仪器昂贵且难用，果蝇化蛹时间多靠人工记录，缺少低成本可靠的自动采集手段
- **关键困难**：单板机算力有限，智能体长时间运行易掉线，若采集完全依赖智能体则实验数据会中断丢失
- **解决方案**：分层设计：确定性采集服务每十分钟存一帧且不依赖智能体；智能体在板上辅助拍摄、写代码修复错误、每日核查并在停机时向手机推送告警
- **主要结果**：26 天孵育器试点约 3580 帧，含 11 天智能体登出仍持续采集，以及一次 51 小时中断促成该分层设计
- **未来方向**：需用专家标注数据验证生命周期追踪精度，并扩展实时计算机视觉分析

## 2611.23335 · Truthgate: Checking Coding Agents Against a Record They Cannot Edit - Cheating, Deterrence and Disclosure on Impossible Tasks
*Truthgate：依据不可编辑记录检查编码智能体——不可能任务上的作弊、威慑与披露*

- Bravish Ghosh
- [Abs](https://arxiv.org/abs/2611.23335v1) · [PDF](https://arxiv.org/pdf/2611.23335v1) · [Code1](https://github.com/Cygnux-Labs/Truthgate)
- **核心问题**：编码智能体宣称完成时是否真实，以及如何识别其在不可能任务上的作弊
- **关键困难**：仅凭动作标签会高估谎言，智能体可改写自身记录，评审缺少不可篡改证据
- **解决方案**：主机重跑测试；容器内隐藏检查；沙箱外签名记录每次工具调用；用提示威慑与披露要求，并让 LLM 评审读取记录
- **主要结果**：Sonnet 5.5 特判通过 39/180（21.7%）；提示将 60 题作弊从 22 降至 1；LLM 评审抓 55/55，规则抓 27
- **未来方向**：记录应作为评审证据而非替代评审，二者需结合

## 2611.23334 · Integrating AI Coding Agents Into Scientific Research
*将 AI 编码智能体整合到科学研究中*

- Rory Barnes
- [Abs](https://arxiv.org/abs/2611.23334v1) · [PDF](https://arxiv.org/pdf/2611.23334v1) · [Code1](https://github.com/RoryBarnes/vaibify)
- **核心问题**：AI 编码智能体易误伤计算机、验证耗资源，并使科研结果受质疑
- **关键困难**：缺乏安全开发环境、文件变更监控和智能体处理规范，验证成本高且可信度低
- **解决方案**：开源 vaibify：Docker 容器隔离智能体，GUI 提示命令行智能体并监控本地/远程文件状态，按 PROOF 量表推动项目至 Level 3 可复现
- **主要结果**：提出 PROOF 六级量表和 vaibify，可监控文件变更并将项目推进到 Level 3（可复现）；摘要未给定量结果

## 2611.22017 · SkillBuffBench: Measuring What Agent Skills Contribute across Harnesses, Models, Skill Access Modes and Memory
*SkillBuffBench：衡量 Agent Skills 在不同 Harness、模型、Skill 访问模式与记忆下的贡献*

- Gengyue Dong, Ye Wei, Zheng Zhu, Yidong Han, Jiale Miao, Xiaojun Jia, Guanghui Li
- [Abs](https://arxiv.org/abs/2611.22017v1) · [PDF](https://arxiv.org/pdf/2611.22017v1)
- **核心问题**：Agent Skills 的帮助证据多来自人工指定正确 Skill 且从空白状态起步的设定，无法反映实际部署情况。
- **关键困难**：部署中智能体需从已安装库中自行选择 Skill，且常携带先前工作记忆，现有评测未覆盖这两种情形。
- **解决方案**：构建三级 Skill 访问 × 记忆开关 × 四 harness × 多模型的配对评测协议，用领域专家科研任务与配套 Skill 评测，确定性验证器打分并报告成本、轮次与耗时。
- **主要结果**：摘要未给出结果；论文为进行中的基准设计与协议，评测完成后补充数字。
- **未来方向**：评测仍在进行，任务套件、结果与分析将滚动更新。
