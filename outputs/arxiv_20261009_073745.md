## 2610.10478 · Before They Can Solve: Predicting Post-Training Coding-Agent Performance from Base Models
*在它们能解决之前：从基座模型预测后训练编码智能体性能*

- Tan Yu, Alexander Bukharin, Khushi Bhardwaj, Jennifer Williams, Zirui Liu, Jonathan Lingjie Li, Soumye Singhal, Joseph Jennings, Sanjeev Satheesh, Yash Jain, Ashish Vaswani, Venkat Krishna Srinivasan, Matthew Papakipos, Hyunwoo Kim, Jian Zhang, Oleksii Kuchaiev, Markus Kliegl, Mostofa Patwary, Mohammad Shoeybi, Bryan Catanzaro, Jonathan Cohen, Jiantao Jiao
- [Abs](https://arxiv.org/abs/2610.10478v1) · [PDF](https://arxiv.org/pdf/2610.10478v1)
- **核心问题**：如何从基座 checkpoint 预测其经智能体后训练后的编码表现，避免昂贵的端到端后训练尝试。
- **关键困难**：端到端 pass@K 要求基座可靠产生合法工具调用，多数基座做不到；单步任务又绕开了多步工具使用中的状态维持能力。
- **解决方案**：把后训练成功轨迹当作基座潜力的前瞻信号，重放轨迹并在每次改码后重跑测试，定位首个使仓库从失败转为通过的决定性步骤，在该步用 Decisive-Action BPB、Patch MCQ、前缀条件 pass@K 三项筛选评分。
- **主要结果**：10 对公开基座与后训练模型上，三种筛选的排序与后训练 SWE-bench Verified pass@1 高度一致。

## 2610.10426 · CoTrace: Data Recipes for Training Terminal Agents with Harness-Model Co-Evolution
*CoTrace：通过 Harness 与模型协同演化训练终端智能体的数据配方*

- Jixuan Chen, Jiaxin Zhang, Qinyuan Ye, Yada Pruksachatkun, Haoxiang Zhang, Jingming Zhuo, Yifan Zhang, Yutong Dai, Juntao Tan, Xiangyu Peng, Silvio Savarese, Zeyuan Chen, Lianhui Qin, Chien-Sheng Wu
- [Abs](https://arxiv.org/abs/2610.10426v1) · [PDF](https://arxiv.org/pdf/2610.10426v1)
- **核心问题**：终端智能体能力同时依赖模型权重与运行时 harness，但现有协同演化把 harness 搜索产出的轨迹混为无差别数据
- **关键困难**：把 harness 搜索轨迹当作统一回放缓冲，忽略轨迹价值取决于生成它的 harness，导致训练与评测运行时失配
- **解决方案**：交替协同演化框架解耦 harness 搜索与策略训练，按组件做晋升决策；反复执行失败驱动 harness 合成，SFT 只用匹配采纳运行时的验证 rollout，RL 用新鲜在线交互
- **主要结果**：Tmax 晋升划分上 Qwen3.5-9B 由 78 提升至 88 解出任务，在线 RL 变体达 90；小规模 harness 匹配语料计算量更低却优于跨 harness 汇总的大语料

## 2610.10394 · Kernel Autoresearch for Open-Ended Model Discovery
*面向开放端模型发现的 Kernel Autoresearch*

- Richard Cornelius Suwandi, Feng Yin, Kevin Murphy
- [Abs](https://arxiv.org/abs/2610.10394v1) · [PDF](https://arxiv.org/pdf/2610.10394v1)
- **核心问题**：自动化核设计面临有效性与表达力的两难：固定语法保证有效但限制搜索，无限制程序自由却不保证有效。
- **关键困难**：LLM生成的核在随机输入上通过数值检查，却在不同尺度或维度下失效，失败率22%–58%。
- **解决方案**：Kernaut把核设计视为开放端模型发现：编码智能体写程序，构造合约确保有效；质量-多样性存档保留高性能且行为各异的核，新颖性筛选引导探索功能新候选。
- **主要结果**：黑箱优化族上优于元学习深度核；十酶动力学核在五个未见机制上误差低于ARD/深度核基线；人改版再降预测误差5.7%、遗憾7.8%。

## 2610.10310 · RSIGym: A Flexible Environment for Recursive Self-Improvement
*RSIGym：用于递归自我改进的灵活环境*

- Fanqing Meng, Lingxiao Du, Haocheng Lu, Qiguang Chen, Ziqi Zhao, Zijian Wu, Jiayuan Zhuo, Mengkang Hu, Michael Qizhe Shieh
- [Abs](https://arxiv.org/abs/2610.10310v1) · [PDF](https://arxiv.org/pdf/2610.10310v1)
- **核心问题**：递归自我改进需把已接受改动带入后续周期，但研究 agent 改动缺乏基础设施，现有设置需重建设施或只探索单组件
- **关键困难**：现有设置让 agent 重建常规基础设施，或把探索限制在单个组件，难以联合优化数据、训练设置与执行 harness
- **解决方案**：RSIGym 用 EaaS 暴露训练、推理、rollout、评估与沙箱服务，共享预算/权限控制，支持 Data、Harness、Joint 三类改进轨道，并用 RSI-Index 度量剩余性能差距闭合比例
- **主要结果**：Opus 5 在独立 Joint 运行中 RSI-Index 最高 0.4809（每基准 $500）；SWE-bench Verified 17.67%→50.33%，AIME 31.67%→97.78%
- **未来方向**：开源 RSIGym 代码与结果，支持复现与进一步研究

## 2610.10263 · When Sub-Agents Work in Parallel: The Promises and Pitfalls of Dynamic Concurrency in Long-Horizon Coding Tasks
*当子智能体并行工作：长程编码任务中动态并发的潜力与陷阱*

- Han Li, HanHaoNing Li, Ziqian Jiang, Yiling Lou
- [Abs](https://arxiv.org/abs/2610.10263v1) · [PDF](https://arxiv.org/pdf/2610.10263v1)
- **核心问题**：现有工作只关注短任务上的编码 agent 失败或预定义多智能体协作，缺少对前沿 agent 动态并发随任务复杂度变化的洞察
- **关键困难**：短任务上模型能力主导结果，长程开发中编排才决定成败，动态并发何时有益、为何失败缺乏受控证据
- **解决方案**：对 Codex、Claude Code、Kimi Code 做开/关动态并发的匹配执行对比（354 任务、2,124 次执行），分析调度行为并归纳 13 类并发特有失败模式与 28 种可观测模式
- **主要结果**：动态并发的端到端效果随任务复杂度与执行时长而异，仅在特定条件下占优，并伴随 13 类并发特有失败模式

## 2610.10242 · TestGRAD: Evolving Test Suites via Failure Pattern Momentum for SWE-Agent Ensemble
*TestGRAD：通过失败模式动量演化测试套件以用于 SWE-Agent 集成*

- Pengfei He, Jiayuan Zhou, Shaowei Wang, Ruiqi Pan
- [Abs](https://arxiv.org/abs/2610.10242v1) · [PDF](https://arxiv.org/pdf/2610.10242v1)
- **核心问题**：SWE-agent 集成需通过测试生成与执行，在多个候选补丁中选出真正正确的那一个
- **关键困难**：现有测试生成缺少面向集成选择的显式损失，只能新建或删除测试，一次性生成且无重复失败反馈
- **解决方案**：以执行定义的差分损失为目标，将测试更新扩展为读现有基础设施、建新测试、改过时断言、删废弃测试四类梯度，并从记忆中挖掘频繁失败序列作为动量，避开重复无效方向并压缩历史上下文
- **主要结果**：SWE-bench Verified 上 4-agent 集成 Pass@1 达 84.2%，较最强基线 80.6% 绝对提升 3.6 个百分点，失败历史上下文压缩超 100 倍

## 2610.10226 · Why Software Engineering Is Indispensable in the Age of Coding Agents
*为什么在编码智能体时代软件工程不可或缺*

- Alfonso Fuggetta
- [Abs](https://arxiv.org/abs/2610.10226v1) · [PDF](https://arxiv.org/pdf/2610.10226v1)
- **核心问题**：能力强大的 AI 编码智能体是否会让软件工程学科与软件工程师变得多余
- **关键困难**：LLM 的概率生成、不可知与语义无状态形成结构性真空，训练无法消除，导致 AI 辅助开发产出貌似合理却不可验证、不可信
- **解决方案**：把方法论知识、领域知识、设计选择与流程选择四类知识杠杆物化为持久制品，由软件工程师担任方法学家、中介与守护者
- **主要结果**：定性结论：AI 编码智能体的兴起使软件工程与软件工程师更为必需而非过时

## 2610.09681 · Cost-Efficient Theorem Proving via Agent Orchestration in Program Verification
*程序验证中通过 Agent Orchestration 实现成本高效的定理证明*

- Shuangjie Yao, Nikolaus Holzer, Mark Paul Santolucito, Baishakhi Ray, Suman Jana, Dongdong She
- [Abs](https://arxiv.org/abs/2610.09681v1) · [PDF](https://arxiv.org/pdf/2610.09681v1)
- **核心问题**：现有定理证明器只优化通过率而忽略成功-成本前沿，难以经济地完成大量相互依赖的证明义务
- **关键困难**：真实软件常有数百个相互依赖证明义务，现有方法为单定理不惜采样或搜索预算，缺乏成本约束
- **解决方案**：CoCo-Prover 构建两级证明图：声明内 AND/OR 超图连接跨声明引理依赖图；符号拓扑选开放目标，元层 agentic router 按定价匹配异构专家代理与配置，并随证据演化路由。
- **主要结果**：在 Lean 4 的 CLEVER、VERINA、AlgoVeri、NTP4VC、Vero 上均达最佳求解率，两个基准达 100%，成本较最强基线最多降 30.9%。

## 2610.09633 · Coding-Agent Benchmarks Should Match Their Users' Task Flows

- **关键困难**：真实长会话（≥3 条用户消息）任务类型更广且类型间频繁切换，任何单一交互分布都无法普遍代表真实场景
- **解决方案**：采集 4,782 条 JetBrains IDE 生产会话刻画 Task Flow；SWE-TaskFlow 保留已验证任务与测试，用 prompt splitting 和可验证仓库 QA 引导交互至目标 Task Flow，以 TFAS 筛选轨迹

## 2610.09264 · Package Hallucination Attacks on Coding Agents through Prompt Injection in Rule Files
*通过规则文件中的提示注入对编码智能体进行包幻觉攻击*

- Yupu Wang, Zhengyuan Jiang, Reachal Wang, Neil Zhenqiang Gong
- [Abs](https://arxiv.org/abs/2610.09264v1) · [PDF](https://arxiv.org/pdf/2610.09264v1)
- **核心问题**：社区共享规则文件（如 AGENTS.md、.cursorrules）被广泛用于引导自主代码生成，但其安全风险尚未被充分研究
- **关键困难**：现有工作未探索规则文件注入路径，且注入提示需在不同模型与智能体框架间保持有效
- **解决方案**：PackHallu 迭代改写注入规则文件的恶意提示，利用轨迹级反馈与 LLM 引导变异，诱导编码智能体用攻击者控制的包替换合法依赖
- **主要结果**：在多基准、多 LLM、多智能体框架上取得高攻击成功率，并具跨模型与跨框架迁移性；摘要未给出具体数字
- **未来方向**：需在自主编码系统中加强安全防护

## 2610.09159 · SpecGuard: Proving a Task Is Broken Before the Agent Cheats
*SpecGuard：在 Agent 作弊之前证明任务本身是坏的*

- Param Biyani, Krishnamurthy Dvijotham
- [Abs](https://arxiv.org/abs/2610.09159v1) · [PDF](https://arxiv.org/pdf/2610.09159v1) · [Code1](https://github.com/prmbiy/specguard)
- **核心问题**：编码 Agent 遇到描述与测试相冲突的任务时往往不作声而作弊（改测试、硬编码输出），甚至造成删除安全防护等实际损害。
- **关键困难**：此前依赖模型判断，冲突漏检率高，且无法在 Agent 行动前给出独立、机器可验证的证据。
- **解决方案**：仅凭任务描述与代码库，用 LLM 将预期行为自动形式化为 Lean 4 规范，测试独立形式化，Lean 内核检查是否存在同时满足两者的实现，若无则产出机器检验的证书。
- **主要结果**：在冲突的 SWE-bench 任务上检测出最高 72.8% 的冲突、正式证明最高 51.1%，冲突漏检率比模型判断低近五倍。

## 2610.09088 · RippleCP: Measuring Counterfactual Checkpoint Advantage in Coding Agents
*RippleCP：衡量编码智能体中反事实检查点的优势*

- Mayur Akewar, Ravi Ranjan
- [Abs](https://arxiv.org/abs/2610.09088v1) · [PDF](https://arxiv.org/pdf/2610.09088v1)
- **核心问题**：现有检查点系统只判断哪些状态安全、如何快照、能否回滚，却不判断哪些安全边界值得实际落盘。
- **关键困难**：恢复是重新推导而非重放，已保存工作量不能代表可节省工作量，按已耗时定价会误算第二个检查点。
- **解决方案**：在匹配的模型、工具、验证器与停止条件下，驱动CP分支与SKIP分支到达同一逻辑失败并各自恢复，测量候选检查点带来的未来恢复成本下降。
- **主要结果**：SWE-bench Verified 12任务106条恢复分支：每任务省49.4s；首检查点省100.0s/保护156.5s（转化0.64），后一步为-1.1s/41.8s（-0.03）。
- **未来方向**：试点仅12个任务、106条分支，规模有限；放置策略需在更大范围验证其是否越过收益门槛。
