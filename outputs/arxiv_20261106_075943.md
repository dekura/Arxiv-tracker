## 2611.05609 · On the Generalization Limitation of On-Policy Distillation for Post-RL Consolidation
*论策略内蒸馏在RL后整合中的泛化局限性*

- Yichen Wang, Yufa Zhou, Siqi Zhu, Haozheng Luo, Jingzhi Bao, Zhichao Liu, Zijun Wei
- [Abs](https://arxiv.org/abs/2611.05609v1) · [PDF](https://arxiv.org/pdf/2611.05609v1)
- **核心问题**：多教师策略内蒸馏在RL后整合中分布内表现接近教师，但分布外泛化与组合能力巩固不足
- **关键困难**：监督分布内数据会掩盖能力整合不完整，蒸馏未充分迁移教师泛化能力并导致OOD遗忘
- **解决方案**：考察教师能力与数据覆盖两个瓶颈并联合缓解，提出基于更新几何的修补和基础保留回放以提升OOD性能
- **主要结果**：外推设定OOD分数低于基座2.45-16.25%；组合设定低于最佳教师18.19-24.34%；缓解后消除OOD遗忘
- **未来方向**：需设计显式支持OOD保持与泛化的能力整合算法

## 2611.05345 · Adversarial Speculative Reasoning Improves Long Horizon Agents
*对抗式投机推理提升长时程智能体*

- Hongyin Luo, Wei Fang, Lijie Yang, Owen Stepan, Daniel Suit, Jeff Krapf, Dana Wensberg, Jack O'Brien
- [Abs](https://arxiv.org/abs/2611.05345v1) · [PDF](https://arxiv.org/pdf/2611.05345v1)
- **核心问题**：投机解码被视为纯加速手段，但长程智能体中验证窗口噪声会随机影响推理准确率
- **关键困难**：现有草稿模型训练只追求接受率，忽略思考过程接受结果在约30步后改变输出分布
- **解决方案**：在智能体轨迹中识别关键决策点，以对抗偏好训练草稿模型使其在这些点被拒，验证重启后关键 token 由目标模型在最不噪条件下采样
- **主要结果**：复杂智能体编码基准端到端成功率提升，目标模型及输出分布不变，仅训练0.06%至0.28%托管参数

## 2611.05320 · PyRUA-DataFarm: LLM Agent as a Cost-Efficient Teleoperator for Real-Ready Robot Data
*PyRUA-DataFarm：LLM Agent 作为低成本遥操作员生成真实可部署机器人数据*

- Kewei Zhang, Juncheng Ma, Guodong Lv, Duomin Wang, Feixiang Ruan, Ruiyang Si, Chuanrui Zhang, Yuxuan Chen, Hao Chen, Yichen Liu, Yintianrun Zhang, Yufan Deng, Enze Xie, Daquan Zhou
- [Abs](https://arxiv.org/abs/2611.05320v1) · [PDF](https://arxiv.org/pdf/2611.05320v1) · [Code1](https://github.com/DAGroup-PKU/PyRUA-Lean/tree/DataFarm)
- **核心问题**：遥操作采集机器人示范成本高、每新任务从头开始，能否由编码 Agent 替代遥操作员生成真实可部署数据
- **关键困难**：每一步都消耗机器人和操作员时间，新任务无法复用，仿真到真实存在视觉与动力学差距
- **解决方案**：给定数据请求与一次标定 episode，Agent 在仿真中写场景、专家控制器和成功判定；仿真提供精确动作，视频模型条件于真实图像一致渲染多视角，独立评审准入
- **主要结果**：五个真实任务 93 vs 84/100 成功，分布偏移下 87 vs 46；每任务适配 $21，每 episode $0.80

## 2611.05094 · A Gated Spec-Driven Workflow: An Audit-Trail Study of Coding-Agent Work
*门控式规格驱动工作流：编码智能体工作的审计追踪研究*

- Rodrigo Figueiredo Abdo, Pedro Carvalho Brom
- [Abs](https://arxiv.org/abs/2611.05094v1) · [PDF](https://arxiv.org/pdf/2611.05094v1)
- **核心问题**：编码智能体按规格、计划、任务列表工作的工作流是否可控可审计，尤其是未声明的文件改动
- **关键困难**：几乎所有控制都是同一模型执行的指令，缺少外部强制，智能体易偏离协议
- **解决方案**：每阶段须用户批准才进入下一阶段；审查子智能体按阶段专属缺陷清单核查产物；执行子智能体只能改任务列出的文件；每块任务后编排器做文件清单检查检测未声明改动
- **主要结果**：7个项目9个特性、581个计划任务完成288个；5个特性全部任务完成；交付目录仅1处未声明改动且被检出；编排器247次块检查记录11次未声明改动，仅4次中止
- **未来方向**：编排器自行运行并判定检查，缺乏独立校验，是工作流薄弱点

## 2611.04977 · GeoFaham: Domain-Specialized Multi-Agent Geospatial Analytics for Disaster Response
*GeoFaham：面向灾害响应的领域专用多智能体地理空间分析*

- Muhammad Sohail Danish, Gilles Q. Hacheme, Akram Zaytar, Satej S. Soman, Inbal Becker-Reshef, Juan Lavista Ferres, Salman Khan, Girmaw Abebe Tadesse
- [Abs](https://arxiv.org/abs/2611.04977v1) · [PDF](https://arxiv.org/pdf/2611.04977v1) · [Code1](https://github.com/microsoft/GeoFaham)
- **核心问题**：灾害响应需多源地理空间多步工作流，单步检索或代码生成难以保持空间范围、时间上下文与中间执行状态
- **关键困难**：LLM 编码智能体易选错证据源、丢失空间与时间元数据、执行非法几何操作，且难以处理大型产物
- **解决方案**：按矢量、地图要素、影像、栅格拆分专家智能体；Orchestrator 用双账本循环做依赖规划、校验与重规划；Response Store 外置完整产物与类型化元数据，智能体只传标识符与摘要
- **主要结果**：在 GeoFaham-Bench（40 任务，17 条真实灾害记录）上总体得分 0.940，次优基线 0.879，token 用量少 7.5 倍

## 2611.02566 · CR-Bench-v2: Evaluating the Real-World Utility of AI Code Review Agents
*CR-Bench-v2：评估 AI 代码审查智能体真实世界效用的基准*

- Kristen Pereira, Neelabh Sinha, Rajat Ghosh, Debojyoti Dutta
- [Abs](https://arxiv.org/abs/2611.02566v2) · [PDF](https://arxiv.org/pdf/2611.02566v2)
- **核心问题**：代码审查难以完全自动化：需 diff 之外的上下文、作者意图与主观设计判断；现有基准缺乏标准化，依赖含噪评论文本相似度打分。
- **关键困难**：文本相似度指标奖励表面重合、无法衡量精确率，人工评审评论噪声大且专家之间意见不一致，导致评测不可靠。
- **解决方案**：过滤出可被审查发现的缺陷并锚定到单一来源 PR，构建 584 条实例（含 174 条 Verified 子集），标注缺陷类别、影响与严重度；用 KDDR 测已知缺陷检出，用有用率测可执行评论比例，三位独立 LLM 评审。
- **主要结果**：在 8 个审查智能体、4 个骨干模型及 Gemini Code Assist 上评测：最强系统 KDDR 仅约 33%，Gemini Code Assist 为 8.1%。

- **解决方案**：冻结底座与持久必需层处理定位、主动触发和稀缺通道；统一插件契约使扩展可组合、可检查、可替换；Web 编码代理生成候选工件并在设备端按同一契约验证准入

## 2611.04466 · From Watching to Steering: Enabling Human-Coding Agent Collaboration through Execution Traces
*从旁观到引导：通过执行轨迹实现人类与编程智能体的协作*

- Xiaoke Yan, Jiaying Lei, Danqing Shi, Zichen Wang, Nan Cao
- [Abs](https://arxiv.org/abs/2611.04466v1) · [PDF](https://arxiv.org/pdf/2611.04466v1)
- **核心问题**：长时运行的编程智能体执行过程难以被用户检查、理解与引导
- **关键困难**：仅靠日志难以呈现中间状态与失败原因，出错往往需重启整个任务，已完成的进度被浪费
- **解决方案**：基于 OpenCode 实现 Observe-Understand-Intervene-Evolve 流程：交互式轨迹可视化、从历史步骤分叉注入局部修正、轨迹与反馈蒸馏为技能

## 2611.04383 · Disposable Implementations: What Is Software Engineering For?
*一次性实现：软件工程究竟为了什么？*

- Christoph Treude
- [Abs](https://arxiv.org/abs/2611.04383v1) · [PDF](https://arxiv.org/pdf/2611.04383v1)
- **核心问题**：智能体能否以再生成取代维护，以及替换后如何保持行为连续性、保留隐性知识
- **关键困难**：现有代码含失败后加入的防护与未记录假设，再生成或通过测试却丢失生产关键行为
- **解决方案**：以实践者文献做探索性综述，辨析再生成相对维护的成本、安全性，以及支撑再生成的工件与流程
- **主要结果**：公开案例显示智能体可替换现有实现，但未证明重复再生成安全或经济
- **未来方向**：需明确替换间连续性如何建立，再生成是降低还是转移维护成本

## 2611.03998 · Dory1.0-4B: A Looped Normalized-GPT

## 2611.03575 · VeriHarm-Bench: Measuring Harmful Success in LLM Coding Agents Verifiably
*VeriHarm-Bench：可验证地度量 LLM 编码代理的「有害成功」*

- Wei-Lin Chen, Zhepei Wei, Xinyu Zhu, Yu-Min Tseng, Tzu-Han Lin, Yu Meng
- [Abs](https://arxiv.org/abs/2611.03575v1) · [PDF](https://arxiv.org/pdf/2611.03575v1)
- **核心问题**：编码代理可能在完成用户良性任务的同时误删文件、削弱访问控制或损坏数据，形成「有害成功」
- **关键困难**：常规任务成功率指标看不到有害副作用，现有安全评测又只看有害结果，无法度量成功与伤害共存的情形
- **解决方案**：对编码任务做最小扰动以在不破坏任务良性和原目标的前提下诱发有害行为，自动合成可执行危害测试，与原有正确性测试共同计算安全成功率
- **主要结果**：VeriHarm-Bench 上 GPT-5.6-Sol、Claude-Opus-5 等前沿代理平均任务准确率 95%，但安全成功率平均仅 37%

## 2611.03551 · Can LLM Agents Be Forward-Deployed Engineers? Requirement Discovery and Delivery for Enterprise Text-to-SQL
*LLM agent 能成为前向部署工程师吗？企业 Text-to-SQL 的需求发现与交付*

- Marianne Menglin Liu, Rongguang Wang, Zheng Wang, Yewen Wang, Leonid Boytsov, Tao Sheng, Sujith Ravi, Dan Roth
- [Abs](https://arxiv.org/abs/2611.03551v1) · [PDF](https://arxiv.org/pdf/2611.03551v1)
- **核心问题**：LLM agent 能否像前向部署工程师一样，从模糊客户请求中发现需求并完成企业 Text-to-SQL 部署
- **关键困难**：现有 coding agent 评测多关注代码生成，缺少对需求发现、权限/硬件约束与交付验收的端到端考察
- **解决方案**：模拟客户从模糊请求出发，agent 在发现阶段挖掘验收标准、数据权限与硬件约束，在交付阶段规划并执行后训练配方；跨 15 个模型和 8 种 coding-agent 配置评测
- **主要结果**：最强模型发现超 80% 隐藏需求，开源权重模型 40–50%；8 种 coding-agent 配置仅 25% 运行通过全部验收标准
- **未来方向**：建议人工复核发现的需求、执行中监控计划，并明确硬件、预算与生产检查的实验环境规范
