## 2610.21283 · Mallea: Building, Steering, and Memorizing Worlds with Coding Agent
*Mallea：用编码智能体构建、操控与记忆世界*

- Xuanyi Liu, Ruiqi Li, Siwei Ma
- [Abs](https://arxiv.org/abs/2610.21283v1) · [PDF](https://arxiv.org/pdf/2610.21283v1)
- **核心问题**：如何在代码世界模型中协调对象表示、行为修订与视觉记忆，实现从文本构建、操控并记忆世界
- **关键困难**：结构、规则与外观常分开处理，文本编辑后难以保持未受影响状态与外观一致
- **解决方案**：编码智能体从提示推断交互需求，联合规划紧凑对象结构、属性与规则；世界按规则演化，文本编辑保留未受影响状态；渲染器结合当前结构与纹理记忆生成观测
- **主要结果**：支持文本编辑属性与扩展能力且保留未受影响状态，纹理记忆仅用于白盒对象并随其变化适配

## 2610.21244 · System1-Arena: Which Decisions Can Be Left to System 1?
*System1-Arena：哪些决策可以交给 System 1？*

- Tianyu Chen, Xinyang Liu, Ruyi An, Zhendong Wang, Mingyuan Zhou
- [Abs](https://arxiv.org/abs/2610.21244v1) · [PDF](https://arxiv.org/pdf/2610.21244v1) · [Code1](https://github.com/TianyuCodings/S1-Arena) · [Code2](https://huggingface.co/datasets/C-Tianyu/S1-Arena)
- **核心问题**：哪些离散决策可由单次前向返回概率的 System-1 模型处理，哪些必须依赖生成式推理
- **关键困难**：缺乏同一决策请求下统一概率评分、且同时覆盖静态任务与实时闭环环境的对比基准
- **解决方案**：构建 92k 问题、105 任务、268 来源、四组任务及 138 个闭环环境；统一给 30 个模型（闭源/开源 LLM 与 System-1）相同请求并比较概率校准、准确率与延迟
- **主要结果**：最大 System-1 在非智能体任务上追平快速闭源 LLM，概率校准更好、延迟约 1/4；推理 LLM 最准但成本约 70 倍；闭环中大型开源 LLM 最高成功率 32.9%

## 2610.21218 · AutoOnboarder: Autonomously Onboarding LLM Agents
*AutoOnboarder：自主完成 LLM 智能体入职适配*

- Tanay Arora, Cong Liu
- [Abs](https://arxiv.org/abs/2610.21218v1) · [PDF](https://arxiv.org/pdf/2610.21218v1)
- **核心问题**：智能体接入 harness 后推理能力下降，需大量人工调优提示与脚手架代码才能适配具体任务
- **关键困难**：人工 onboarding 依赖专家反复试错，性能与成本难以兼顾，且评测数据易泄漏导致结果失真
- **解决方案**：Onboarder 编码智能体仅凭数十示例，迭代调整基座模型、提示与 harness 源码；评测数据隔离在独立虚拟机防止泄漏
- **主要结果**：基因组测序预授权表单提交任务上，自主 onboard 智能体匹配或超过 Gemini 3.5 Flash 基线，成本最高降低 29×，但最终性能波动大
- **未来方向**：需为 Onboarder 提供稳健环境：结构化思考接口、受控联网与更宽的模型搜索空间

## 2610.21073 · Skip the Compressor: Coding Agents Fix More Issues When They Pick Whole Files
*跳过压缩器：编码智能体挑选整份文件时能修复更多 Issue*

- Xiaocong Yang, Rishit Chatterjee, Himanshu Udupi, Vikram Ramavarapu, ChengXiang Zhai
- [Abs](https://arxiv.org/abs/2610.21073v1) · [PDF](https://arxiv.org/pdf/2610.21073v1)
- **核心问题**：仓库规模远超上下文窗口，需在有限 token 预算下同时给出需修改的文件与其精确原文
- **关键困难**：检索器按与 issue 的相似度排序而非按是否需改，常漏掉目标文件；压缩器保留文件却改写文本，导致补丁无法应用
- **解决方案**：CQ2-CARE 把每条 issue 的等量 token 预算全部用于挑选需编辑的文件，并按仓库原样完整呈现其代码，不压缩、不检索代码块
- **主要结果**：SWE-rebench 300 条上解决率 43.7%/46.7%（GPT-5.6/Opus 5），超最佳压缩器 6.3 点、最佳检索器 9.3/12.7 点

## 2610.21029 · SCARCE: Emergent Institutions in Long-Horizon Multi-Agent Coding Systems
*SCARCE：长时程多智能体编码系统中的涌现制度*

- Abhinav Kumar, Rediet Abebe, Eugene Bagdasarian, Sahar Abdelnabi
- [Abs](https://arxiv.org/abs/2610.21029v1) · [PDF](https://arxiv.org/pdf/2610.21029v1)
- **核心问题**：长时程多智能体任务中，智能体如何自发形成协调共享资源的非正式制度仍不清楚
- **关键困难**：以往研究多用程式化博弈与模拟议价，无法反映持续长时程任务中的真实协调行为
- **解决方案**：搭建 SCARCE 竞技场：智能体在各自截止期内完成编码任务，须协商共享执行资源的访问时段与时长，据此决定何时检查程序、编译与运行测试
- **主要结果**：审计8个模型、1500余条轨迹；新前沿模型制度行为更多，并出现排他联盟与分而治之策略

## 2610.20673 · HPCAgent-Bench: A Framework for Sound Benchmarking of Code-Optimizing Agents, Harnesses, and Skills
*HPCAgent-Bench：用于代码优化 Agent、Harness 与 Skills 可靠基准测试的框架*

- Yakup Koray Budanaz, Lorenzo Paleari, Marcin Copik, Alexandru Calotoiu, Timo Schneider, Benjamin Chen Ming Choong, Shriram Chandran, Lars Hulsbergen, Levi Widmer, Torsten Hoefler
- [Abs](https://arxiv.org/abs/2610.20673v1) · [PDF](https://arxiv.org/pdf/2610.20673v1)
- **核心问题**：编码 Agent 被用于优化代码，但现有基准固定加速器、编程模型或 harness，无法分离各组件贡献，也无法判断新增技能与工具是否值得其成本
- **关键困难**：固定单一加速器与 harness 使跨组件归因失效，且缺少防作弊的正确性校验与透明的成本核算口径
- **解决方案**：689 个内核分三条赛道，统一 C ABI/Python 提交接口，支持 CPU/GPU 单多节点；外部判题用隐藏模糊输入验证正确性并计时；提出 intervention efficacy 与加权 token 成本两项指标
- **主要结果**：Agent 相比自动并行器最高 4.2× 加速；93–99% 无设备特定代码的答案跨机器仍正确，每内核加速比秩相关 r_s≥0.84；40 组配对设置中干预仅 2 次显著改变加速比，但 token 成本最高变化 3.0×

## 2610.19596 · JevCoder: When Does Decision Delegation Pay Off in Code Repair?
*JevCoder：代码修复中决策委托何时才划算？*

- Jiahao Zhang, Yifan Zhang, Yu Huang
- [Abs](https://arxiv.org/abs/2610.19596v1) · [PDF](https://arxiv.org/pdf/2610.19596v1)
- **核心问题**：哪些代码修复决策可委托给低成本 judge，从而减少 token 消耗又不降低修复质量
- **关键困难**：收益取决于干预所改变的工作量而非判断本身成本，只按 judge 成本决定委托会失效
- **解决方案**：JevCoder 围绕概率型 judge Jev 构建工作流：结合代码片段推荐与动作类型引导，并用判断结果决定何时提交
- **主要结果**：三个修复模型各 400 任务（SWE-bench Verified 与 Pro Verified 各 200）：token 用量降低 21.6%–50.6%，修复率均上升

## 2610.19447 · BenchChecker: Assessing the Credibility of Bug-Fixing Benchmarks for LLMs
*BenchChecker：评估面向 LLM 的缺陷修复基准的可信度*

- Di Wu, Xu He, Shu Wang, Kun Sun · 35th USENIX Security Symposium (USENIX Security 26), pp. 5077-5096, 2026
- [Abs](https://arxiv.org/abs/2610.19447v1) · [PDF](https://arxiv.org/pdf/2610.19447v1)
- **核心问题**：现有自动程序修复基准存在数据污染，测试样本出现在训练集中，虚高 LLM 性能
- **关键困难**：训练集可能包含测试样本，闭源模型训练数据不可见，难以判断基准污染
- **解决方案**：仅用模型文本输出与公开仓库历史，两阶段检测：仓库存在性测试推断训练包含，补丁存在性测试验证补丁在仓库快照中持久存在
- **主要结果**：在六个基准上 AUC 约 0.9；过滤污染样本后，多数 LLM 在 SWE-bench Verified 与 Multi-SWE-bench 中等难度任务解决率相对下降超 20%

## 2610.19302 · DTDD: Divergence-Triggered Dynamic Distillation for Reliable On-Policy Supervision
*DTDD：面向可靠 on-policy 监督的分歧触发动态蒸馏*

- Qijia He, Zequn Li, Spencer Luo, Tianle Chen, Pradyumna Narayana, Zixian Ma, Ranjay Krishna, Lan Nie, Sugato Basu
- [Abs](https://arxiv.org/abs/2610.19302v1) · [PDF](https://arxiv.org/pdf/2610.19302v1)
- **核心问题**：on-policy 蒸馏在师生分歧大或长程推理误差累积时监督不可靠
- **关键困难**：初始策略差距大、长程推理与工具调用误差累积，使学生 rollout 上的 token 级监督失真
- **解决方案**：按段计算师生分歧，超阈值时教师从学生前缀生成恢复后缀，学生用交叉熵行为克隆学习；未触发段保持标准 OPD 监督
- **主要结果**：峰值梯度范数降8.6×；更新少2.6×达21.3%数学准确率（OPD约22%）；ALFWorld提升4.8/4.1个百分点
- **未来方向**：教师接管仅在特定条件下有益，干预率与触发设计需调参

## 2610.19025 · How Far Can Coding Agents Go in Visual Generation?
*编码智能体在视觉生成上能走多远？*

- Hengguang Zhou, Yuanhao Ban, Jiaqi Feng, Xiaohuan Pei, Justin Cui, Cho-Jui Hsieh
- [Abs](https://arxiv.org/abs/2610.19025v1) · [PDF](https://arxiv.org/pdf/2610.19025v1)
- **核心问题**：专用生成模型把图像构建隐于参数，通用编码智能体能否通过可执行程序完成视觉生成与推理？
- **关键困难**：零样本程序绘图感知丰富度有限且受接口影响，智能体是否具有跨绘图程序的共享场景表征尚不清楚。
- **解决方案**：构建200提示AgentDrawBench零样本评测；将重建视觉代码用于VQA；用跨harness绘图、单像素查询和视角变化探测内部表征一致性。
- **主要结果**：AgentDrawBench上结构与约束有竞争力、感知丰富度受限；重建视觉代码VQA部分领域超原图；跨接口布局色调相关。
- **未来方向**：程序绘图感知丰富度有限，需提升视觉表现力并厘清共享表征机制。

## 2610.18933 · The Agentic Scientist: Orchestrating Coding Agents for Automated Scientific (Co-)Discovery
*Agentic Scientist：编排编码智能体以自动化科学（协同）发现*

- Robert Tjarko Lange, Luca Grillotti, Yutaro Yamada, Rujikorn Charakorn, David Ha
- [Abs](https://arxiv.org/abs/2610.18933v1) · [PDF](https://arxiv.org/pdf/2610.18933v1)
- **核心问题**：全自主研究智能体构思半径有限、搜索短视，难以可靠完成计算科学研究
- **关键困难**：现有自主科研智能体局限于狭小想法空间和短视爬山搜索，且难跨异构领域复用
- **解决方案**：把研究拆为选题、构思、规划、沙箱实验、结果聚合、基线与消融、后验分析和报告写作；元控制器管理并行智能体并逐阶段做 rubric 验证
- **主要结果**：开发版系统提交的论文被 ALIFE 2026 接收；全自主求解开放 ML 问题，消融表明可靠性依赖跨智能体编排层
