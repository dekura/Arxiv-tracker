## 2609.35557 · The Compiler May Read It, the Agent May Not: Keeping Part of a Research Code Away from a Coding Agent
*编译器可以读，Agent 不可以读：将研究代码的一部分与编码 Agent 隔离*

- Shobhan Roy
- [Abs](https://arxiv.org/abs/2609.35557v1) · [PDF](https://arxiv.org/pdf/2609.35557v1)
- **核心问题**：如何让编译器读取构建所需模块，同时阻止编码 Agent 读取其中的知识产权代码
- **关键困难**：现有容器、权限规则和沙箱只按路径或用户授权，无法判断当前读取程序是编译器还是编码 Agent
- **解决方案**：将十五种读取路径与容器、权限规则、沙箱逐一对照分类，检验三者能否把代码访问限制到编译器而非编码 Agent
- **主要结果**：分类十五种读取路径；容器、权限规则和沙箱均无法判断哪个程序在读取

## 2609.35530 · AutoRef: Harness Optimization for Agentic Multi-Reference Image Generation
*AutoRef：面向智能体式多参考图像生成的 Harness 优化*

- Yuta Oshima, Ku Onoda, Yusuke Iwasawa, Masahiro Suzuki, Yutaka Matsuo, Hiroki Furuta
- [Abs](https://arxiv.org/abs/2609.35530v1) · [PDF](https://arxiv.org/pdf/2609.35530v1) · [Code1](https://github.com/KuOnoda/AutoRef)
- **核心问题**：多参考图像生成常遗漏或重复参考主体、拼接不自然；手工 harness 性能差异大，改动收益难预测。
- **关键困难**：各参考图角色不同，输出须同时满足对每张参考的保真度与整体自然性等多重标准，手调难以预判。
- **解决方案**：冻结生成与推理模型，由编码智能体迭代重写 harness 代码；将提供反馈的任务与选择候选的任务分离，并从排名靠前的 harness 组成的 beam 继续搜索。
- **主要结果**：MultiBanana 四参考留出任务上 FLUX.2 [klein] 4B 由 5.72 升至 7.37，超过 Nano Banana Pro 与 GPT-Image-1.5，跨设置无需重优化。

## 2609.35367 · From Input to Output: A Flexible Agent for Dual-End Interpretation of Sparse Autoencoder Features
*从输入到输出：用于稀疏自编码器特征双端解读的灵活智能体*

- Dewen Liu, Zixuan Li, Jonathan Pan, Zhao Wu, Zijun Yao, Juanzi Li, Xiaozhi Wang
- [Abs](https://arxiv.org/abs/2609.35367v1) · [PDF](https://arxiv.org/pdf/2609.35367v1) · [Code1](https://github.com/THUAIS-Lab/DAFI)
- **核心问题**：现有SAE特征解释割裂输入侧激活模式与输出侧干预效应，二者功能联系隐含
- **关键困难**：输入侧证据依赖昂贵的大规模语料扫描，且两端解释缺乏显式连接
- **解决方案**：DAFI按组件反馈迭代精炼输入侧、输出侧与功能解释；短上下文token探测按需收集激活证据，免全语料扫描；蒸馏成功精炼技能
- **主要结果**：GemmaScope上Input score较SAGE +13.1pp，Output score较Token Change +38.9pp；蒸馏技能使联合通过率从58.0%升至92.0%；AxBench改善steering特征选择

## 2609.35357 · Do Coding Agents Reuse Existing Code or Reinvent the Wheel?
*编码智能体是复用现有代码还是重新造轮子？*

- Dongsheng Ma, Sizhe Wang, Xinyi Huang, Zhengren Wang, Yuhan Wang, Luyang Si, Xincheng Wei, Wentao Zhang
- [Abs](https://arxiv.org/abs/2609.35357v1) · [PDF](https://arxiv.org/pdf/2609.35357v1)
- **核心问题**：编码智能体在真实仓库迭代开发中，是复用现有代码还是重复实现？现有评测仅看通过率，无法回答该问题。
- **关键困难**：重复实现会累积为未被审查的冗余，但通过率几乎不变，现有基准缺乏对复用行为与跨轮结构冗余的度量。
- **解决方案**：多轮基准 RepoReuse：自动流水线结合 AST 依赖图、引导证据与执行验证合成任务；逐轮揭示需求、跨轮累积工作区，并测复用率、召回与跨轮结构冗余。
- **主要结果**：3,000 轮审计：到第5轮50.8%任务链留下重复逻辑，通过率几乎不变；智能体减少探索仓库代码并更少复用自身历史。

## 2609.35328 · Hyper Algorithm Design Agent: Evolving Learnable Optimizer from Zero
*Hyper Algorithm Design Agent：从零进化可学习优化器*

- Zipei Yu, Yue-Jiao Gong, Zeyuan Ma, Yuncheng Jiang, Zhiguang Cao
- [Abs](https://arxiv.org/abs/2609.35328v1) · [PDF](https://arxiv.org/pdf/2609.35328v1)
- **核心问题**：MetaBBO 算法设计依赖人工逐案定制，引入主观性，限制性能上限与实用性
- **关键困难**：现有 MetaBBO 需针对不同优化问题手工定制，缺乏开放式自动设计能力与跨域泛化
- **解决方案**：把 MetaBBO 设计循环视为编码任务：task agent 通过代码演化精化目标算法代码库，hyper agent 逐步修改 task agent 与自身，执行信息全部回馈实现递归自改进
- **主要结果**：给定朴素 MetaBBO 模板即可自动演化出优于现有人工 MetaBBO 基线的新变体，并支持跨优化域快速适配

## 2609.35199 · Trajectory-Level Security Debt in LLM Coding Agents
*LLM 编码智能体中的轨迹级安全债*

- Prateek Kumar Rajput, Abdoul Kader Kabore, Yewei Song, Melissa Tessa, Tailia Malloy, Jacques Klein, Tegawendé F. Bissyandé
- [Abs](https://arxiv.org/abs/2609.35199v1) · [PDF](https://arxiv.org/pdf/2609.35199v1)
- **核心问题**：仅评估最终代码产物，无法度量 LLM 编码智能体在数百个中间代码状态演化中的安全发现
- **关键困难**：安全发现随轨迹演化而终态评估遗漏；不同 SAST 工具及等价 API 改写会扰动测量结果
- **解决方案**：定义 SDLI，在智能体刷新最佳测试通过比时累积静态分析风险；用四个 SAST 工具在 830 个 SWE-bench 通过运行、712 个 ProgramBench 工作区上实例化，大样本用终态特例
- **主要结果**：两工具 CWE 类一致率：SWE-bench 3.9%，官方测试≥90% 的 ProgramBench 运行 26.2%，剔除三个建议密集类别后降至 6.2%
- **未来方向**：SDLI 对引导智能体与确认可利用漏洞的价值尚未确立

## 2609.35182 · Research-Native by Construction: Minimal Nodes, Re-verifiable Workflows, and Compounding Memory for Long-Horizon Scientific Agents
*按构造的研究原生：最小节点、可复验工作流与面向长周期科学智能体的复利记忆*

- Di Wang, Yu Liu, Bing Cui, Chaoqun Ji, Dongyuan Ni, Jingyu Lu, Kunlei Cui, Pu Qin
- [Abs](https://arxiv.org/abs/2609.35182v1) · [PDF](https://arxiv.org/pdf/2609.35182v1)
- **核心问题**：科学智能体长周期运行中，完成压力下会伪造、跳过或掩盖证据，研究可信度难保障。
- **关键困难**：通用编码智能体附技能文件夹继承其失败模式，模型行为约束不可靠，缺少机械可验证流程。

- **未来方向**：局限：无基准量化比较，今日仅能测机械开销；过程完整性套件在建。

- **关键困难**：智能体只用静帧和转录稿感知素材、只查渲染缺陷而不评判剪辑手艺，故多数仅质量测试不通过

## 2609.34924 · Audit the Scaffold, Not the Checkpoint: A Stationarity Dichotomy for Recursive Self-Improvement in Agentic Coding
*审计脚手架，而非检查点：Agentic Coding 中递归自我改进的平稳性二分法*

- Sebastian Bobadilla-Suarez, Bob Suh, Ryan Fortin
- [Abs](https://arxiv.org/abs/2609.34924v1) · [PDF](https://arxiv.org/pdf/2609.34924v1)
- **核心问题**：递归自我改进系统常以权重是否冻结判断平稳性，混淆搜索、测试时训练与脚手架重写三种机制，缺乏可判定的收益上限准则。
- **关键困难**：冻结权重只能保证最终上限，无法说明中间是否平稳；Best-of-k 只提升速率不增加预算，固定池投票受限于真实工人缺乏多样性而失败重叠。
- **解决方案**：将精化读作对 draft 与 target 残差（patch 或 git diff）的梯度提升，并测其失效点：patch 可组合而非独立投票、失败重叠；由此按可达编辑集是否扩展区分三种机制，审计脚手架而非检查点。
- **主要结果**：SWE-bench 每轮提升趋零；401 会话 churn 几何衰减；同族 worker 失败重叠最大，多数投票 23/55 任务失败。
- **未来方向**：两个失效点属工程选择而非代码规律，未来需构建对应 harness，摘要未给出具体方案。

## 2609.35918 · Evaluating Name-Only Directory Routing for One-Shot Code Search
*评估 One-Shot 代码搜索中的纯名称目录路由*

- Manoj Bajaj
- [Abs](https://arxiv.org/abs/2609.35918v1) · [PDF](https://arxiv.org/pdf/2609.35918v1)
- **核心问题**：编码智能体在仓库中定位正确文件困难，固定词法查询会漏掉相关标注文件，纯名称层级路由能否补回尚不明确
- **关键困难**：FTS5、固定 rg 等词法查询对 issue 措辞敏感，无法利用目录与文件名的层级命名线索
- **解决方案**：在 11 个仓库的预修复固定 commit 上，用语言模型仅看目录/文件名做一次性路由检索，并在 16K token 共享上下文预算下与 FTS5 配对评测文件级与行级召回
- **主要结果**：82 个 issue 中八候选内 gold 文件召回 0.465，FTS5 0.352、rg 0.245，配对增益 0.113（CI 0.053–0.168）；16K 预算行召回 0.443 vs 0.246
- **未来方向**：无法将增益归因于层级结构，也不能证明提升 issue 解决率；扁平路径控制召回 0.572 但每 issue 需 24.6 次模型调用

## 2609.34683 · AgentPerfBench: A Benchmarking and Evaluation Suite for Inference Performance of Agentic LLMs
*AgentPerfBench：面向智能体 LLM 推理性能的基准测试与评估套件*

- Cheuk Hang Lau, Zeyu Cao, Kevin Wong Cheuk Yin, Yao Lai, Haoran Wu, Nicholas D. Lane, Robert D. Mullins, Ilia Shumailov, Yiren Zhao
- [Abs](https://arxiv.org/abs/2609.34683v1) · [PDF](https://arxiv.org/pdf/2609.34683v1)
- **核心问题**：现有推理 benchmark 主要覆盖单轮聊天，无法反映 agentic 多轮、工具调用、上下文持续增长的真实负载。
- **关键困难**：已有基准未考虑真实上下文长度增长，也未在硬件饱和点测量，结果无法反映真实硬件性能。
- **解决方案**：用 SWE-Bench、TerminalBench 真实 trace，按输入/输出长度与轮数分布采样生成合成 profile，采集 kernel 级 NCU trace 构建多维 roofline 模型，并附脚本自动识别瓶颈。
- **主要结果**：量化了当前推理基准的 chat-to-agentic 差距，并用 roofline 分析刻画每 kernel 的 GPU 资源利用率。

## 2609.34661 · Codoku: Renewable Program-Reasoning Challenges for Frontier Coding Agents
*Codoku：面向前沿编码智能体的可再生程序推理挑战*

- Cong Li, Hao Sun, Zenan Li, Zhendong Su
- [Abs](https://arxiv.org/abs/2609.34661v1) · [PDF](https://arxiv.org/pdf/2609.34661v1) · [Code1](https://github.com/connglli/Codoku)
- **核心问题**：现有程序推理基准要求模型预测程序在给定输入下的行为，无法约束编码智能体通过执行程序直接得到答案。
- **关键困难**：部分程序无法执行，且合法填法在指数级相互依赖的选择空间中极为稀疏，工具调用与枚举均无法替代程序推理。
- **解决方案**：将谜题设计为满足预设控制流图、执行路径等静态与动态约束的类型化填空；用语义具体化从零合成，按需生成可控复杂度新题，每题附保证可解性的 witness；智能体在固定预算内可自由用工具。
- **主要结果**：5 个前沿模型、300 道谜题：小规模题已难倒开放权重模型，即便专有模型也仅解出约一半的大规模题。

## 2609.34422 · Coding Agent Memory Post-training: Unlocking the Memory Potential of Pre-trained File Operations for Long-Horizon Tasks via Reinforcement Learning
*编码智能体记忆后训练：通过强化学习解锁预训练文件操作能力以完成长时程任务*

- Lirui Luo, Kelong Mao, Heming Xia, Rongqing Li, Xinwei Yang, Luyu Chen, Kieran Wong, Yudong Guo, Xinrui Wang, Jiayin Zhu, Simiu Gu, Sulong Xu, Cong Fang
