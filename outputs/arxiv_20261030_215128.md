## 2610.38244 · Precedent or Intent? What Coding Agents Follow When Evolving Existing Code
*先例还是意图？编码智能体在演进既有代码时遵循什么*

- Haichao Zhu, Geyang Xu, Zhaorui Yang, Jiyuan Wang, Qian Zhang
- [Abs](https://arxiv.org/abs/2610.38244v1) · [PDF](https://arxiv.org/pdf/2610.38244v1)
- **核心问题**：多个实现都满足功能需求时，编码智能体是跟随既有代码先例还是新任务指令
- **关键困难**：既有代码只留实现决策不解释理由，与新指令冲突时缺乏可依据的优先级信息
- **解决方案**：在定制仓库做双向对照实验并在开源仓库验证，比较默认偏好、先例来源与明文优先级规则的影响
- **主要结果**：先例冲突时 359/360 跟先例；3 个支持性本地文件采纳率 96%，同级资源文件仅 4%；明文规则联合成功率 59/60 vs 38/60，开源仓库 0/120 升至 117/120
- **未来方向**：推动设计决策可追溯，保留实现选择及理由与未来修改的优先级

## 2610.38214 · Skeleton Coding: Program Structure as a Specification for Agents
*Skeleton Coding：以程序结构作为智能体的规范*

- Aditya Golatkar, Alessandro Achille, Renos Zabounidis, Vlad Sobal, Yangruibo Ding, Baishakhi Ray, Jonathan Buck, Guy Van den Broeck, Maryam Fazel, Pietro Perona, Wei Xia, Stefano Soatto
- [Abs](https://arxiv.org/abs/2610.38214v1) · [PDF](https://arxiv.org/pdf/2610.38214v1)
- **核心问题**：开发者需提供多少条、哪些行为规范（测试、输入输出样例），才能让编码智能体产出预期程序，无法先验确定
- **关键困难**：所需测试取决于智能体自选的结构，一种结构下充分的测试在另一种结构下严重欠定，需指数级样例
- **解决方案**：将 AI 辅助编码建模为控制问题，证明骨架可使所需测试数指数级下降；开发者在高层类代码格式中同时给出结构与行为规范，联合约束候选程序类
- **主要结果**：四模型三基准：测试误差降 48.4%（有参考实现时仍降 27.0%），代码侵蚀降 24.7%

## 2610.38175 · DecompGym: Benchmarking LLM Agents on Designing Decomposition Algorithms
*DecompGym：评估 LLM 智能体设计分解算法的基准*

- Sikai Cheng, Tinghan Ye, Arnaud Deza, Xiaonan Qi, Miao Li, Litong Liu, Changkun Guan
- [Abs](https://arxiv.org/abs/2610.38175v1) · [PDF](https://arxiv.org/pdf/2610.38175v1) · [Code1](https://github.com/SIKAI-C/DecompGym)
- **核心问题**：现有编码智能体能否正确设计并实现 Benders 分解与列生成求解器，以及失败模式为何
- **关键困难**：分解算法需主问题与子问题交换割、列和对偶值，正确实现困难，仅检查输出会放过方法错误
- **解决方案**：构建 81 个实例、九类问题族的 DecompGym；要求 60 秒执行、数值可行性与 LLM 代码审计、目标值 1% 内；比较重生成与反思重试
- **主要结果**：首轮两模型全解，七个>90%；反思重试成功率66% vs 重生成39%；仅输出检查会接受93/108方法审计失败尝试
- **未来方向**：仅作为第一步，需扩展到更多分解算法与实际建模场景

## 2610.38027 · METATRON: A Promptable Whole-Body Execution Layer for Humanoids
*METATRON：面向人形机器人的可提示全身执行层*

- Chen Tessler, Yifeng Jiang, Alec Otto, Yi Shi, Umar Iqbal, Gal Chechik, Xue Bin Peng
- [Abs](https://arxiv.org/abs/2610.38027v1) · [PDF](https://arxiv.org/pdf/2610.38027v1)
- **核心问题**：人形控制器通常需按任务单独训练，无法复用共享的平衡与全身协调能力
- **关键困难**：任务特定策略难以同时覆盖行走、跌倒恢复、物体抓取与坐姿等差异极大的行为
- **解决方案**：基座策略接收定时身体部位目标、速度指令与风格提示，由动捕、合成恢复轨迹和重定向交互动作训练后冻结；技能为普通代码，每步输出提示，并由编码智能体分析运动数据拟合紧凑规则
- **主要结果**：Unitree G1 上单一冻结检查点支持行走、恢复、遥操作取物与坐家具，到达成功率与抗推鲁棒性优于参考跟踪管线

## 2610.34577 · Rethinking Verification in Agent Harnesses
*重新审视 Agent Harness 中的验证*

- Zhengxin Zhang, Erkang Zhu, Yin Lin, Claire Cardie, Bolin Ding, Jingren Zhou
- [Abs](https://arxiv.org/abs/2610.34577v1) · [PDF](https://arxiv.org/pdf/2610.34577v1)
- **核心问题**：Agent harness 应如何组织验证工作，包括何时介入、由谁检查、检查如何转化为修订，目前缺乏指导
- **关键困难**：验证设计缺少系统化对比，收益与输出 token、成本之间的权衡不清晰
- **解决方案**：将验证视为测试时扩展的一个维度，在 TB、SWE-bench Verified 上跨 7 个编码模型比较 17 种设计，并提出 VisualBench 做专家评测
- **主要结果**：独立评审在 TB 上平均准确率提升 5.9-9.5 个百分点，在 SWE 上提升 3.9-6.6 个百分点，成本为基线的 1.13-1.25 倍和 1.00-1.04 倍；VisualBench 净偏好 13.2-23.8 分

## 2610.34425 · CTXAgent - Self-Controlled Context Management of LLM Agents
*CTXAgent —— LLM Agent 的自主上下文管理*

- Matthias Busch, Marius Tacke, Roland C. Aydin, Christian Feiler, Christian J. Cyron
- [Abs](https://arxiv.org/abs/2610.34425v1) · [PDF](https://arxiv.org/pdf/2610.34425v1)
- **核心问题**：长会话需在超出 token 阈值时压缩历史，但压缩时机与内容取舍完全由 agent harness 硬编码决定
- **关键困难**：此前发现开放权重模型在无脚手架时无法自我管理上下文，压缩频率与保留内容难以把握
- **解决方案**：给模型两个上下文工具与一段指引，在 35–212 轮混合任务会话（编码练习、SciCode、SWE-bench Pro、Terminal-Bench 4.0 并植入事实与指令）中对比七个前沿模型的 token 成本与得分，并与三种常用 harness 比较
- **主要结果**：多数强模型能自主压缩，活跃上下文多低于 100k token 且得分无显著下降；Claude Opus 5.5 上成本比 200k 窗口配置低 34%、比默认低 49%

## 2610.34422 · From GPU to TPU with Coding Agents: What Works, What Fails, and What It Costs?
*从 GPU 到 TPU 的编码智能体：什么有效、什么失败、成本多少？*

- Hui Sun, Anderson Uchôa, Wesley K. G. Assunção
- [Abs](https://arxiv.org/abs/2610.34422v1) · [PDF](https://arxiv.org/pdf/2610.34422v1)
- **核心问题**：编码智能体可报告迁移成功却改变模型训练行为，TPU 迁移能否可信及成本未知
- **关键困难**：迁移常出现编译低效、无报错静默失败，第三方库交互会悄然改变计算，仅凭成功报告难以信任
- **解决方案**：构建148个PyTorch研究项目数据集，用Claude Code迁移10个到TPU，独立核验可运行、数值一致、硬件正确、目标保持与性能，并统计失败、人工干预和成本
- **主要结果**：8/10达目标，均需2.4次人工干预；70次执行53败(76%)，26次静默；准确率86.53→84.89；TorchTPU快1.86倍省25%
- **未来方向**：需独立参考运行、目标硬件验证、按负载设验收与停止准则，并计入人力成本
