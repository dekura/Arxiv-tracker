## 2610.11366 · SpatialOPSD: Self-Distilling Spatial Intelligence from Verified Coding Agent Traces
*SpatialOPSD：从已验证的编码智能体轨迹中自蒸馏空间智能*

- Rongxue Li, Meng Yang, Yiru Mao, Yongliang Tao, Lulu Hu, Bin Yang, Zhao Xu, Weihua Luo, Bowen Xu
- [Abs](https://arxiv.org/abs/2610.11366v1) · [PDF](https://arxiv.org/pdf/2610.11366v1)
- **核心问题**：空间编码智能体依赖外部工具，推理开销大且需外部依赖，能否让 MLLM 无工具内化该能力
- **关键困难**：直接用智能体轨迹提示会带来在线推理开销；蒸馏特权信息时易发生泄漏，学生模型可能照搬轨迹而非学到推理
- **解决方案**：以摘要化的已验证智能体轨迹作为特权信息，对 MLLM 做 on-policy 自蒸馏，并引入 Repetition-Aware Distillation：重复掩码结合 unlikelihood 正则化，抑制特权信息泄漏
- **主要结果**：在多个空间与 OOD 基准上平均准确率高于 SFT 和 GRPO，性能与泛化更优

## 2610.11358 · RaReCache: Bridging the Gap in Cross-Model KV Cache Reuse via Rank disagreement-based Selective Recomputation
*RaReCache：通过基于秩不一致的选择性重计算弥合跨模型 KV Cache 复用的差距*

- Sreetama Sarkar, Saptarshi Mitra, Sitao Huang, Souvik Kundu, Peter A. Beerel
- [Abs](https://arxiv.org/abs/2610.11358v1) · [PDF](https://arxiv.org/pdf/2610.11358v1)
- **核心问题**：跨模型复用 KV cache 时，同族闭合线性映射的迁移精度随源-目标模型规模差距增大而下降
- **关键困难**：KV cache 含模型特有表示，切换模型通常需整段上下文重新 prefill；线性映射在大规模差距下失效
- **解决方案**：以秩不一致度量（映射后 KV 在标定数据弱支持输出方向上的能量）逐 token 打分，选出关键位置重计算，其余直接复用映射缓存
- **主要结果**：23x 差距（0.6B→14B）重算 30% 位置保留 95-99% 精度；8.8x 差距（8B→70B）重算 40% 保留 96.5%；prefill 最高提速 3.04x

## 2610.11299 · DuplexAgent-RSI: Recursive Harness Improvement for Full-Duplex Voice Agent Collaboration
*DuplexAgent-RSI：面向全双工语音智能体协作的递归式 Harness 改进*

- Yingda Shen, Yuxiang Wang, Kunyu Feng, Qinke Ni, Jiaqi Li, Minghao Hsu, Junan Zhang, Dekun Chen, Yutong Bian, Zhizheng Wu
- [Abs](https://arxiv.org/abs/2610.11299v1) · [PDF](https://arxiv.org/pdf/2610.11299v1)
- **核心问题**：全双工语音模型实时交互强但推理与工具使用弱，编码智能体能力强却不适合实时对话，二者协作缺乏可系统改进的协调层
- **关键困难**：现有 harness 依赖耦合的启发式规则，难以依据证据系统性地定位并改进协作模块
- **解决方案**：将协作工作流写成六个可编辑模块；模拟器自动生成定时对话并产出失败轨迹，Exam Planner 按弱点与修复档案选测试，Harness Editor 提出针对性模块改动
- **主要结果**：智能、智能体与全双工基准上 spoken-knowledge 与 executable-tool 分数高于对比的委派系统，打断响应强；消融显示该闭环优于初始 harness 与无诊断档案的编辑

## 2610.11179 · Who Pays the Review Cost? Triage, Fairness, and Accountability in AI-authored Pull Requests
*谁来支付评审成本？AI 撰写 Pull Request 中的分流、公平与问责*

- Md Shamimur Rahman, Khairul Alam, Banani Roy, Chanchal K. Roy
- [Abs](https://arxiv.org/abs/2610.11179v1) · [PDF](https://arxiv.org/pdf/2610.11179v1)
- **核心问题**：AI 编码代理进入 pull-based 工作流后，评审者如何把关 AIPR 的准入，AI 署名如何改变可信度与公平
- **关键困难**：已有研究多停留在刻画 AIPR 特征，缺乏对评审准入机制、问责分配与评审可持续性的实证证据
- **解决方案**：对 31 个国家 239 名有代码评审经验的从业者开展混合方法问卷，通过情景与自述提取受理条件、新手 AIPR 与指导/转交行为
- **主要结果**：AI 署名并非一刀切的拒绝信号；是否受理取决于范围受限、有项目依据的理由、CI 之外验证、贡献者响应性与合并后可识别归属

## 2610.11169 · Skill Constellations: Tracing the Supply Chain of Agent Skills on GitHub
*技能星座：追踪 GitHub 上 Agent Skills 的供应链*

- Fahd Seddik
- [Abs](https://arxiv.org/abs/2610.11169v1) · [PDF](https://arxiv.org/pdf/2610.11169v1)
- **核心问题**：Agent 技能靠仓库间复制传播，却无注册表、版本与来源信息，复制源头、修复覆盖范围与待审计仓库均未知
- **关键困难**：单时点快照式研究只能记录哪些仓库持有技能，无法揭示谁复制了谁
- **解决方案**：用 GitSkills 中每个 SKILL.md 的 git 历史构建带日期的复制网络（219 万次技能采用），拟合复制来源模型对仓库排序，并提供交互式查看器
- **主要结果**：排名最高的 100 个仓库可预防 14.9% 后续高风险技能采用，而 star 最多的 100 个仅 0.5%
- **未来方向**：平台应分发带版本的引用而非副本

## 2610.08900 · Humanize: Judgement Engineering for Agentic Coding
*Humanize：面向智能体编程的判断工程*

- Sihao Liu, Ligeng Zhu, Zijian Zhang, Dongyun Zou, Zhengyang Zhang, Changye Li, Song Bian, Song Han, Tony Nowatzki
- [Abs](https://arxiv.org/abs/2610.08900v2) · [PDF](https://arxiv.org/pdf/2610.08900v2)
- **核心问题**：智能体编程让写代码变廉价，但可靠完成仍难：写代码的智能体无法判断任务是否真做完
- **关键困难**：builder 是自身工作的弱判断者，缺少独立验证，未完成的实现容易被误判为已完成
- **解决方案**：人类批准计划契约，builder 分轮实现，来自另一厂商的 reviewer 判定完成，确定性钩子负责角色间路由并执行 72 项机械门禁
- **主要结果**：108天68个版本获1468 GitHub stars；IOI/IMO/IPhO 2026满分，IChO 2026 418.5/437，PutnamBench 672/672，Lean-Eval 251/303第一
- **未来方向**：独立评审能抓出无依据声明，但停止时机仍是弱点，且证据为观察性而非受控对比

## 2610.11050 · AgentHorizon: Evaluating Agentic Judges for Long-Horizon Computer-Use Tasks
*AgentHorizon：评估长时程计算机使用任务的智能体裁判*

- Xing Han Lù, Dheeraj Vattikonda, Sina Hajimiri, Fatemeh Pesaran Zadeh, Parishad BehnamGhader, Ghazwa Darwiche, Amirhossein Kazemnejad, Christopher Pal, Alexandre Drouin, Siva Reddy
- [Abs](https://arxiv.org/abs/2610.11050v1) · [PDF](https://arxiv.org/pdf/2610.11050v1)
- **核心问题**：计算机使用智能体的自动裁判在跨多个应用的长任务上可靠性不明确。
- **关键困难**：长截图与动作序列看似完成，实际可能违反指令约束或引入副作用，证据常隐藏在历史中。
- **解决方案**：构建1373条指令-轨迹对、166小时人工录制、覆盖三个操作系统的基准，用指令互换配对构造负任务，划分AH/AH-S/AH-D三个split，以直传全轨迹和五种harness作编码智能体两种方式评测11个裁判。
- **主要结果**：最佳智能体裁判GPT-5.5在AH子集达80.9% balanced accuracy；工具使用提升部分模型却降低开源权重模型表现，裁判接受与拒绝能力差异大。
- **未来方向**：需要能定位并验证长交互历史中隐藏完成证据的裁判。

## 2610.10961 · Cross-Provider Review as a Runtime Contract for Coding Agents: A Controlled Pilot and Fault-Injection Study
*Cross-Provider Review 作为编码代理的运行时契约：受控试点与故障注入研究*

- Bowen Xu, Boyu Chen
- [Abs](https://arxiv.org/abs/2610.10961v1) · [PDF](https://arxiv.org/pdf/2610.10961v1)
- **核心问题**：编码代理共享工作站但按提供方分配资源，第二代理审查会消耗另一资源池且可能无实质发现
- **关键困难**：审查调用消耗另一资源池且可能无发现；部分输入截断导致假成功；退出状态未按次记录致暴露无法回溯
- **解决方案**：定义咨询式跨提供方审查契约：独立资源池、有界执行、受限审查能力、完整输入、可用语义输出、显式失败状态与按次持久证据
- **主要结果**：20配对轮中8有实质发现(95%CI 19.1-63.9%)；修复截断假成功与取消缺陷；未报门控结果
- **未来方向**：仅覆盖指定路径与版本，非现场可靠性；元数据审查队列因运行时回归重启，尚无门控结果

## 2610.10619 · TestJack: Should you trust the results in coding benchmarks? Agentic Coding Benchmarks Auditing via Evaluator Evolution
*TestJack：你应该相信编码基准的结果吗？通过评估器演化进行智能体编码基准审计*

- Shuangjie Yao, Hao Wang, Koushik Sen, Simin Chen, Baishakhi Ray, Dawn Song
- [Abs](https://arxiv.org/abs/2610.10619v1) · [PDF](https://arxiv.org/pdf/2610.10619v1)
- **核心问题**：固定单元测试无法覆盖任务要求，智能体可通过 reward hacking 或遗漏必要行为仍通过测试，导致基准分数失真
- **关键困难**：现有静态测试增强只在任务前一次性强化测试，未考虑真实 trial 的失败模式，无法发现通过测试但违规的补丁
- **解决方案**：对每个 trial 生成针对提示要求的测试，仅保留真值补丁通过的测试并复查失败，每条确认失败都有可回放测试；轻量变体随机抽样审计并复用测试降低成本
- **主要结果**：6 个模型后端、5 个基准（含 DeepSWE、SWE Marathon）上，约 34.4% 判正 trial 违反要求，总体解决率从 50.6% 降至 33.2%
- **未来方向**：评估器需随模型优化能力演化而自适应

## 2610.10610 · Code Understanding is a Bottleneck for Coding Agents
*代码理解是编码智能体的瓶颈*

- Nishant Balepur, Kiran Tomlinson, Tobias Schnabel
- [Abs](https://arxiv.org/abs/2610.10610v1) · [PDF](https://arxiv.org/pdf/2610.10610v1)
- **核心问题**：仓库级基准(如SWE-bench)用编辑行数代理任务难度，但对代码和任务类型控制差，无法判断哪些能力真正导致智能体出错。
- **关键困难**：现有基准难度与能力归因混杂，难以区分错误来自代码理解还是代码编辑。
- **解决方案**：构建CABRA：以调用图变换从零生成任务，在函数遍历、搜索、运行时解析、指令遵循四轴按任务规模扩展难度；在6,840个任务上评测8个LLM与6个编码智能体。
- **主要结果**：LLM准确率随任务规模下降，智能体靠grep等工具近满分；SWE-bench Verified中工具调用数比编辑行数更能预测准确率。
