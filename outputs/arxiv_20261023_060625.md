## 2610.30114 · The End of Consensus Research?
*共识研究的终结？*

- Clément Burgelin, Rachid Guerraoui, Zicong Hong, Yinan Hu, Anne-Marie Kermarrec, Rafael Pires, Rasmus Moorits Veski, Martijn de Vos
- [Abs](https://arxiv.org/abs/2610.30114v1) · [PDF](https://arxiv.org/pdf/2610.30114v1)
- **核心问题**：地理复制状态机共识协议的低延迟实用设计仍需人工结合协议知识、正确性推理、实现与实验
- **关键困难**：共识协议设计依赖专家经验，需同时兼顾正确性证明、实现与性能评测，自动化搜索难以保证安全
- **解决方案**：AI-greement 将概念化协议知识库、模块化实现骨架和含可复用安全定义与证明的 Lean 验证框架整合，让编码 agent 自主提出、实现、实验并验证候选协议
- **主要结果**：六种部署上写密集/读密集平均延迟较最快基线降12.2%/33.3%，只读持平；Lean形式化发现已有协议未报告漏洞
- **未来方向**：人类共识专家在搜索前后仍不可或缺；需探索领域专用 harness 的通用化

## 2610.30047 · SWE-DIVE: Multi-Turn Coding Agent Evaluation with Dynamic User Simulation
*SWE-DIVE：带动态用户模拟的多轮编码智能体评测*

- Lorenz Brehme, Benjamin Steenhoek, Ruth Breu · NeurIPS 2026
- [Abs](https://arxiv.org/abs/2610.30047v1) · [PDF](https://arxiv.org/pdf/2610.30047v1) · [Code1](https://github.com/lorenzbrehme/swe-dive_usersim)
- **核心问题**：现有编码智能体评测使用一次性、表述良好的 GitHub issue 提示，无法覆盖真实多轮追加需求的交互
- **关键困难**：真实用户提示表述不清且会话中不断追加新需求，静态单轮基准无法衡量智能体在多轮澄清与增量任务下的表现
- **解决方案**：用户模拟器模拟多种行为模式与智能体多轮对话，对话验证器检查模拟器输出是否满足初始需求并引导任务完成，Harbor 环境编排三者并执行测试判定是否解决
- **主要结果**：构建了多轮交互编码智能体评测框架，代码与结果已在 GitHub 开源；摘要未给出具体基准数字

## 2610.29870 · PAUSE: Search-Free Steering of Coding Agents Before Their First Source-Code Edit
*PAUSE：在编码 Agent 首次修改源码前的无搜索引导*

- Viral Patel, Boyin Tan, Jason Xue, Youcheng Sun
- [Abs](https://arxiv.org/abs/2610.29870v1) · [PDF](https://arxiv.org/pdf/2610.29870v1)
- **核心问题**：编码 Agent 大量探索测试后仍产出失败补丁，缺少低成本且可靠的在线纠偏时机
- **关键困难**：周期性审查成本高，且未检测到异常行为并不代表 Agent 方向正确
- **解决方案**：以首次源码编辑为固定干预点，无需学习型监控器、检查点搜索或额外模型调用；Planner 输出单份修复计划，Executor 保留上下文与工作区继续执行，支持在线与离线轨迹前缀
- **主要结果**：SWE-bench Verified 用 OpenHands 提升 16.8%，Multilingual 用 SWE-agent 提升 14.7%；优于 LivePlan 3.2%/3.7%，与 SICA 相当但 Planner 成本约 11-15%；离线挽回 35.4% 失败…

## 2610.29823 · MemoryTax: The Bitter Lesson of Agent Memory
*MemoryTax：Agent 记忆的苦涩教训*

- Zedong Peng
- [Abs](https://arxiv.org/abs/2610.29823v1) · [PDF](https://arxiv.org/pdf/2610.29823v1)
- **核心问题**：当模型自身足够强、能用工具检索原始历史时，预先设计的记忆系统是否还值得其开销
- **关键困难**：记忆构建本身成本高昂，且记忆质量受写入模型能力上限约束，强读取模型无法补回弱写入模型漏掉的信息
- **解决方案**：在LoCoMo单个419轮、152问的对话上，对比full context、BM25、Mem0、Zep四种记忆方法与Pi、Codex、Claude Code三种coding agent，各配三个模型，记录每次rollout成本
- **主要结果**：Pi+Claude Opus 5.5达99%准确率且成本不足full context一半；Mem0仅在GPT-4o-mini上胜过全上下文；在88个无照片证据问题上Pi与全上下文仅差1答
- **未来方向**：仅一个对话、每格一次运行，结论需更多对话与重复实验验证

## 2610.29822 · UserSWE: Evaluating Coding Agents in Multi-Turn Conversations with Dynamic Users
*UserSWE：在动态用户多轮对话中评测编码代理*

- Zhan-Yu Wu, Ji Luo, Alyssa Wu, Junjielong Xu, Richeng Xuan, Zhichao Hu, Chongming Gao, Xinting Hu
- [Abs](https://arxiv.org/abs/2610.29822v1) · [PDF](https://arxiv.org/pdf/2610.29822v1)
- **核心问题**：现有编码代理基准多为单轮完整报错、无交互，无法评测多轮修复能力
- **关键困难**：单轮评测既可能接受错误补丁，也可能拒绝正确补丁，产生假正例与假负例
- **解决方案**：将仓库历史与单轮基准转为多轮任务；每轮跑测试，以测试结果为主要证据，由不同模型族的两个代理分别撰写与把关裁决
- **主要结果**：在 42 个仓库的 72 个任务上评测 11 个代理，排名随交互预算变化：Claude Fable 5.1 单轮最优，GPT-6-Astra 第八轮最优，Claude Opus 5 在多数中间预算领先
- **未来方向**：结果表明单轮表现不足以刻画交互式编码能力

## 2610.29758 · AssureCode: Structured Justification for Trustworthy Agentic Coding

- Logan Murphy, Wilson Sy, Rhys Balevicius, Kelsie Fung, Karenna Kung, Aren A. Babikian, Marsha Chechik

- **核心问题**：AI 生成代码需与开发者意图对齐并获得适当验证，但缺少可检查的正确性论证
- **关键困难**：自然语言提示与形式规格、意图假设、分析证据彼此割裂，难以形成可验证的代码正确性依据
- **解决方案**：定义 justification rationales 语言，将非正式提示、形式规格、开发者意图假设和程序分析证据结构化关联，并以工具支持在 agentic 代码生成中创建与检查这些论证
- **主要结果**：实证分析显示可支持 AI 生成代码正确性的可论证保障；摘要未给出基准或数字

## 2610.29695 · Benchmarking Coding Agents for System-Level Performance Optimization

- Yanze Zhang, Maggie Yongqi Guan, Shudong Liu, Qi Hao, Kanye Ye Wang, Meng Qu, Xiaobo Zhou
- [Abs](https://arxiv.org/abs/2610.29695v1) · [PDF](https://arxiv.org/pdf/2610.29695v1) · [Code1](https://github.com/zyzcjnb/microperf)
- **核心问题**：现有编码智能体基准多限于函数或仓库级，缺乏对分布式微服务系统级端到端性能优化的评测
- **关键困难**：可复现的系统级性能修复样本稀疏且难以归因，难以构建可靠基准
- **解决方案**：向真实开源系统注入有实证依据的性能反模式，保持功能并造成可测性能退化；含65个实例、7个系统、9类反模式，配可执行环境、功能测试与混合负载评估

## 2610.29332 · Do Coding Agents Understand Why Systems Crash---and Why They Don't?
*编码智能体是否理解系统为何崩溃——以及为何不崩溃？*

- Chenxi Huang, Haonan Wang, Jinghe Zhang, Aleksandr Nogikh, Franjo Ivančić, Petros Maniatis, Eugene Wu, Kostis Kaffes, Junfeng Yang, Baishakhi Ray
- [Abs](https://arxiv.org/abs/2610.29332v1) · [PDF](https://arxiv.org/pdf/2610.29332v1)
- **核心问题**：编码智能体能否真正推理系统级代码库的执行行为，而非仅凭可疑代码猜测崩溃
- **关键困难**：单看崩溃代码无法区分真实执行推理与启发式的可疑代码匹配，误报被掩盖
- **解决方案**：构建 SysRB：934 对仅差一个 commit 的 Linux 与 OSS-Fuzz 源码树，同一输入仅一棵树崩溃，比较智能体在两棵树上的崩溃预测率
- **主要结果**：四个智能体偏向预测不崩溃，最佳者仍漏报超四分之一真实崩溃；定位到决定崩溃的代码也常误判其效果，崩溃点越远越差；仅在崩溃树上测试会掩盖误报

## 2610.29303 · ExpEvolve: Structuring and Reusing Experience for Open-Ended Discovery

- Yongqiang Chen, Chenxi Liu, Deyu Zou, Zhenhao Chen, Tongliang Liu, Bo Han, Kun Zhang

## 2610.29143 · VeeReview: Measuring Build-Verify Pairs in Agent-Authored Pull Requests from a V-Model Perspective
*VeeReview：从V模型视角度量 Agent 撰写 Pull Request 中的构建-验证对*

- Gabriel Dautovi, Jie JW Wu
- [Abs](https://arxiv.org/abs/2610.29143v1) · [PDF](https://arxiv.org/pdf/2610.29143v1)
- **核心问题**：PR 评审需要能对应改动的验证证据，但编码 Agent 基准与 PR 结果研究并不直接评估这种对应关系
- **关键困难**：现有评测只看 PR 结果不看验证过程；纯语言模型判定易反映 PR 呈现方式而非背后的验证工作
- **解决方案**：四组构建-验证对中三组由确定性仓库信号约束 LLM 判定，Module Design-Unit Test 由 diff 与仓库树规则判定，并用 25 个双人标注 PR 参照集校准
- **主要结果**：在 741 个仓库 1454 对匹配 PR 上，Agent PR 四组「仅构建」率均更低（混合效应 OR 0.52–0.86）；但校准未达标，与裁定标签一致率 4%–60%，评分者间 kappa=0.154
- **未来方向**：此类过程度量需含机械化判定成分与经验证的人工参照，方能支持验证实践比较

## 2610.29121 · Recursive Self-Improvement on a Budget: Scoring Code Edits Before They Run
*预算约束下的递归自我改进：在运行前给代码编辑打分*

- Erfan Darzi, Sree Bhargavi Balija, Sheng He
- [Abs](https://arxiv.org/abs/2610.29121v1) · [PDF](https://arxiv.org/pdf/2610.29121v1)
- **核心问题**：自改写代码智能体需在编辑运行前选择扩展哪个候选，并在预算内返回一个智能体
- **关键困难**：候选编辑尚未评测，无法直接判断质量；全量搜索成本高，需在有限预算下选择
- **解决方案**：用96个编辑标注拟合父代steering解率与8维diff的线性评分并冻结；Thompson采样按已评测节点steering计数选父代扩展，返回steering解数最大的最早节点
- **主要结果**：GPT-4o在留出HumanEval+达87.0%，父代率消融84.2%；Claude Sonnet 4.5为86.6%，根脚手架81.2%

## 2610.29052 · Our Own Jev: Typed Decisions in One Forward Pass, from an In-House Judge to Open LoRA Models
*我们自己的 Jev：一次前向传播中的类型化决策，从内部评审器到开放 LoRA 模型*

- Yuchuan Weng, Chi Liu, Xin Chen, Srinivasan Manoharan
- [Abs](https://arxiv.org/abs/2610.29052v1) · [PDF](https://arxiv.org/pdf/2610.29052v1)
- **核心问题**：如何用一次前向传播完成类型化决策，替代昂贵的前沿 LLM 评审与文本生成解析，并验证无参数读出是否具竞争力
- **关键困难**：前沿 LLM 评审每次约 $1000，存储标签与双评审共识仅 26.9% 一致；生成后解析文本慢、贵且难私有化
