## 2611.23216 · Higher-Scoring Coding Models Did Not Get More Work Done
*得分更高的编码模型并未完成更多工作*

- Yining Hua
- [Abs](https://arxiv.org/abs/2611.23216v1) · [PDF](https://arxiv.org/pdf/2611.23216v1)
- **核心问题**：编码基准得分更高的模型是否真能提升开发者的实际工作效率，此前缺乏因果证据
- **关键困难**：基准分数与真实生产力之间的关系受模型自选等混杂影响，观察数据难以因果识别
- **解决方案**：以19天模型访问禁令为自然实验，追踪297名受影响用户的PR，以8,908名未切换开发者为对照，拟合带开发者与日期固定效应的双重差分模型；并对2026年五次模型升级重复比较
- **主要结果**：7天PR合并率仅提升1.4个百分点[-1.4,+4.3]不显著；五次升级加权均值-0.9个百分点，全部为负；每周合并PR数+2.4%不显著

## 2611.23203 · Identifying and Repairing Energy Smells with Agent Skills
*用 Agent Skills 识别并修复能耗坏味*

- Mohammadjavad Mehditabar, Saurabhsingh Rajput, Tushar Sharma
- [Abs](https://arxiv.org/abs/2611.23203v1) · [PDF](https://arxiv.org/pdf/2611.23203v1)
- **核心问题**：能耗坏味检测与修复应左移到编码阶段，但现有工具难以发现能耗热点并可靠地确认节能效果
- **关键困难**：静态规则工具不度量节能，LLM 优化器多针对执行时间且改动缺乏具体坏味定义作依据
- **解决方案**：将 12 类坏味、65 根因与 230 个实测案例的修复指导注入编码智能体，并内置静态分析器与独立验证器确认行为保持和节能
- **主要结果**：258 次修复中 68.6% 节能，中位节能 24.9%；相比无分类法基线，在三个仓库和两个模型上都发现更多可验证节能的坏味

## 2611.23174 · Inference after coding agents
*编码智能体之后的推断*

- Florian Gunsilius, David Van Dijcke, Kaspar Wüthrich
- [Abs](https://arxiv.org/abs/2611.23174v1) · [PDF](https://arxiv.org/pdf/2611.23174v1)
- **核心问题**：AI 编码智能体自动开展实证分析时产生超强选择性推断，在零效应数据上仍频繁报告显著结果
- **关键困难**：智能体在隐式估计器空间中进行开放式搜索，且分析过程可程序化复现，传统选择后推断难以刻画
- **解决方案**：智能体完成分析后重置，并在数据子样本上回放，估计其在结果统计有利时选择该分析的概率，构造渐近有效且条件一致的校正检验；校正从黑箱实际选择中学习
- **主要结果**：零效应模拟中，四个前沿智能体有54%–98%的情况下报告显著 p 值；校正后假拒绝率稳健降至接近名义 5%

## 2611.23067 · Values Shape What Self-Improving Coding Agents Build
*价值观塑造自我改进编程智能体所构建的内容*

- Jason Liang, Dylan Waldner, Risto Miikkulainen
- [Abs](https://arxiv.org/abs/2611.23067v1) · [PDF](https://arxiv.org/pdf/2611.23067v1)
- **核心问题**：自我改进智能体只被优化为产出结果，设计师缺少塑造其工作方式的手段，开放式任务尤甚。
- **关键困难**：现有指令对智能体工作方式的控制有限，价值观是否影响性能与构建产物缺乏实证。
- **解决方案**：在持久指令文件写入简短价值观陈述，单次运行内跨多轮自我改进固定不变，比较开放变革、保守、自我增强、自我超越四类价值观在多种编程任务上的性能与所生成算法。
- **主要结果**：开放变革类提升留出集性能，保守类低于无价值观基线；价值观改变所建算法的规模、复杂度与方法。
- **未来方向**：价值观设计仍需人类监督；如何提炼出有效价值观尚待解决。

## 2611.22967 · CodeReel: Accelerating Code-to-Video Agents with Exact Frame Reuse and Blocking-Aware Scheduling
*CodeReel：利用精确帧复用与阻塞感知调度加速代码到视频智能体*

- Junyi Shen, Yao Lu
- [Abs](https://arxiv.org/abs/2611.22967v1) · [PDF](https://arxiv.org/pdf/2611.22967v1)
- **核心问题**：代码到视频智能体反复构建渲染，构建阻塞导致长等待且大量帧重复可复用
- **关键困难**：现有缓存按时间位置或场景匹配，难复用移位/编辑场景中的帧；构建是否停在检查未知，无法提前调度
- **解决方案**：以绘制命令为键精确匹配任意时间位置帧并复用；先跑检查，同时以空闲优先级启动渲染，除非近期构建不太可能通过；精确键让失败版本已渲染帧可供后续版本使用
- **主要结果**：EditLoop 等待降 36.3%/57.9%（vs Rebuild/Sequential）；Claude Code/Codex CLI 中位等待 0.62x/0.67x

## 2611.22901 · Done, But Still Working: Anytime Evaluation of When Coding Agents Should Stop
*完成了，但仍在工作：编码智能体何时应停止的 anytime 评测*

- Zerui Yang, Quan Xue, Miaomiao Dong, Chaorui Zhang, Xuanyu Zheng, Xiyuan Wang, Haolin Ruan, Xueyan Niu, Guangcheng Song, Weixi Zhang, Wei Han, Bo Bai
- [Abs](https://arxiv.org/abs/2611.22901v1) · [PDF](https://arxiv.org/pdf/2611.22901v1)
- **核心问题**：编码智能体在自测通过后仍继续修改，这些额外工作是否真的改善补丁、提前停止能省多少成本尚不清楚
- **关键困难**：需在不重新生成轨迹的前提下比较不同停止策略；早停收益随模型与脚手架差异极大，且停止后质量是否保持难以保证
- **解决方案**：重放约6000条 SWE-bench Verified 轨迹（8个开源模型×2种脚手架），用隐藏测试对中间补丁打分并累计每步成本，测量停止规则触发率与补丁后续修复/破坏，再微调智能体模仿该规则
- **主要结果**：自测通过后可节省成本 <1%–57%（依模型与脚手架）；同一补丁连续两次通过即停止的规则节省23%，但质量非劣性未成立；微调模仿该规则节省30%

## 2611.22897 · Born for the Task: Rethinking Quantum Chemistry with Foresighted Agentic Computing
*为任务而生：用前瞻式智能体计算重新思考量子化学*

- Haozhi Han, Junjie Yang, Ruge Zhang, Zihe Huang, Pengyi Xu, Bo Zhang, Yunquan Zhang, Ting Cao, Yunxin Liu, Yifeng Chen, Kun Li
- [Abs](https://arxiv.org/abs/2611.22897v1) · [PDF](https://arxiv.org/pdf/2611.22897v1)
- **核心问题**：通用量子化学软件导致大规模计算超出资源预算，而按需编写的专用程序在运行前无法判断精度与速度是否达标
- **关键困难**：策略的精度和速度只有真正在目标规模上跑过才清楚，缺少执行前的误差与运行时间预测，难以快速找到达标程序
- **解决方案**：把现有软件预设方案拆为可独立配置的算法组件；用小体系外推误差、按目标规模负载与实测硬件吞吐预测运行时间；在精度-运行时间帕累托前沿选最快策略，并指导编码智能体生成程序
- **主要结果**：50,024基函数Hartree-Fock单CPU节点1.41h，快于通用基线估计77×(含开发时间9.8×)；单GPU泛素2.1h≈Mako 64 GPU；B-DNA由约两月降至8.1h(173×)

## 2611.22835 · When Passing Checks Do Not Establish Completion: Evidence Interpretation in Coding Agents
*检查通过并不等于完成：编码智能体中的证据解释*

- Xueping Gao
- [Abs](https://arxiv.org/abs/2611.22835v1) · [PDF](https://arxiv.org/pdf/2611.22835v1)
- **核心问题**：编码智能体通过检查时，如何解释证据范围并确认检查义务已完成，而非仅报告正确事实
- **关键困难**：现有验证只关注检查是否通过，正确报告的事实未必产生所需有限结论，且可能误报事实或越权
- **解决方案**：构建十三任务因子研究、留出回执供给实验与118个修复回合，使用受控证据消费者和可执行工作流检验事实、范围与义务
- **主要结果**：留出回执研究中122个交付标签全对，但16个回答误报事实、11个越权；修复回合分离启动可达性与修复
- **未来方向**：不主张通用诊断优势，Skill退化与部署折叠效应未获一致支持

## 2611.21152 · From Repositories to Training Environments: Scaling Long-Horizon Coding Agents with Environment Evolution Loop
*从仓库到训练环境：通过环境演化循环扩展长程编码智能体*

- Yang Tian, Tianyu Zheng, Xiyuan Yang, Yaxin Du, Chengran Yang, Bo Zhao, Jian Yang, Bryan Dai

- **关键困难**：递归自我改进依赖模型 rollout 或训练后评估，长程任务成本与反馈延迟被放大。
- **解决方案**：RepoFactory 将真实仓库转为可验证环境，智能体依语言规范从零构建项目；环境演化循环以乘性目标优化有效性、结构耦合与实现范围。

## 2611.22299 · Harnesses That Improve Themselves: A Unifying Framework for Self-Improving Agent Harnesses
*自我改进的 Harness：自我改进智能体 Harness 的统一框架*

- Deep Shah, Nehal Kathrotia
- [Abs](https://arxiv.org/abs/2611.22299v1) · [PDF](https://arxiv.org/pdf/2611.22299v1)
- **核心问题**：静态 agent harness 难以适配不同模型与任务，易停滞、浪费 token 或迁移时性能回退
- **关键困难**：各模型工具使用与失败模式不同，为单一模型调好的静态 harness 换模型或任务即失效
- **解决方案**：四类可编辑运行时组件（上下文与状态、控制、动作接口、验证与恢复）配合诊断失败、生成代码补丁、验证候选、部署更新的闭环，并以模块化更新与验证门控约束改动
- **主要结果**：SWE-bench Lite 上，门控模块化演化优于 prompt 反思与整体 harness 重写，且 token 成本更低

## 2611.22291 · When the World Is the Test Suite: Agentic Intelligence for the Physical World
*当世界成为测试套件：面向物理世界的智能体智能*

- Kaixin Li, Meng Luo, Yanlin Li, Yuchen Tian, Xiang Liu, Xiangru Jian, Yan Yang, Zhiheng Xi, Yang Zhang, Ziyang Luo, Mingfei Cheng, Hongzhan Lin
- [Abs](https://arxiv.org/abs/2611.22291v1) · [PDF](https://arxiv.org/pdf/2611.22291v1) · [Code1](https://github.com/PhysicalWorldAgent/Awesome-PhysicalWorldAgent)
- **核心问题**：代码智能体生成的机器人、实验室与工控程序缺少配套测试套件，程序是否有效只能靠高成本且可能出错的物理试验来判断。
- **关键困难**：物理试验证据获取代价高且本身可能错误，软件测试实践难以直接迁移到执行器与仿真环境。
- **解决方案**：按编写、测试、学习三问组织：区分机器人策略程序与生成奖励/任务/训练世界的支撑程序，比较物理试验、执行轨迹、学习评判器、仿真与形式检查，并将验证过的程序沉淀为技能库与模型权重。
- **主要结果**：综述83页，梳理从软件工程智能体与机器人语言模型汇合的脉络，提出物理版持续集成需求：验证需足够廉价可频繁运行、可靠可支撑搜索，并与经验同步维护。
- **未来方向**：建立物理世界持续集成式验证体系，兼顾安全性与任务成功之外的评估。

## 2611.22238 · Context Has a Price: Adding and Removing Context for LLM Coding Agents under Prefix Caching
*上下文有代价：前缀缓存下 LLM 编码智能体的上下文增删*

- Zerui Yang, Miaomiao Dong, Quan Xue, Chaorui Zhang, Xuanyu Zheng, Xiyuan Wang, Haolin Ruan, Xueyan Niu, Guangcheng Song, Weixi Zhang, Wei Han, Bo Bai
- [Abs](https://arxiv.org/abs/2611.22238v1) · [PDF](https://arxiv.org/pdf/2611.22238v1)
- **核心问题**：增删上下文是否降低 LLM 编码智能体解题成本，现有评估未区分缓存 token 价格与智能体后续行为
- **关键困难**：缓存折扣改变成本结构，移除旧观察可能诱发更多步骤，短提示未必省钱，并发实验共享前缀干扰比较
- **解决方案**：在 SWE-bench Verified、SWE-bench、Loc-Bench 上运行 2 万余次开放模型，分计未缓存输入、缓存输入、输出 token，比较检索代码与删除旧观察
- **主要结果**：检索代码降读/搜索命令18–34%，但缓存价1/10时成本升33–42%且解决率无提升；删旧观察无缓存省19–36%、有缓存增38–116%
