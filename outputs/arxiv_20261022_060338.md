## 2610.28612 · TraceLite: Efficient Trace Reduction for SWE Agents via Optical Compression and Redundancy Removal
*TraceLite：通过光学压缩与冗余移除实现 SWE Agents 的高效轨迹缩减*

- Jingyu Xiao, Qianxi Liu, Yintong Huo, Yuan Jiang, Michael R. Lyu
- [Abs](https://arxiv.org/abs/2610.28612v1) · [PDF](https://arxiv.org/pdf/2610.28612v1) · [Code1](https://github.com/xjywhu/TraceLite)
- **核心问题**：SWE agent 迭代工具调用产生的交互轨迹持续增长，造成大量 token 消耗与推理开销
- **关键困难**：现有压缩方法常需模型训练、辅助 LLM 调用，或依赖源码等特定内容假设
- **解决方案**：近期观察保留高保真文本；历史观察转为紧凑图像；删除跨步重叠内容；代码编辑后丢弃阶段过期观察载荷；无需离线训练或辅助 LLM 推理
- **主要结果**：SWE-bench Verified 解决率 78.25%，平均输入 token 降 33.05%，API 成本降 21.30%，每次观察压缩延迟 0.438 秒

## 2610.26636 · Revision-Based Learning from Interactive Experience and Feedback
*基于修订的交互经验与反馈学习（RELIEF）*

- Jiawen Li, Chenming Ge, Alice Gao, Rishab Vempati, Yi-Hao Peng, Jason Wu
- [Abs](https://arxiv.org/abs/2610.26636v2) · [PDF](https://arxiv.org/pdf/2610.26636v2)
- **核心问题**：交互式代码生成模型难以利用只有在真实交互中才显现的界面可用性属性进行训练
- **关键困难**：界面可用性依赖真实交互，反馈难以转化为训练信号，且效果受基座模型能力影响
- **解决方案**：收集网站、交互录像与用户反馈，生成代码检查、自动交互、显式反馈和录像推断批评，用编码代理修订后回填轨迹微调
- **主要结果**：200网站/355录像/24用户；由人类交互录像推断的批评带来最大可用性提升，效果随基座模型能力变化

## 2610.28354 · S-Agent 2.0: Spatial Reasoning with a General Coding Agent
*S-Agent 2.0：用通用编程智能体进行空间推理*

- Rui Gong, Ruoyu Wang, Yalun Dai, Hao Li, Sidi Yang, Qihao Zhao, Hongyu Li, Zeyang Guan, Fangzhou Hong, Zhaoxi Chen, Kim-Hui Yap, Ziwei Liu
- [Abs](https://arxiv.org/abs/2610.28354v1) · [PDF](https://arxiv.org/pdf/2610.28354v1)
- **核心问题**：空间推理要求判断三维物体的位置、相互关系与运动，现有 VLM 智能体工具给出了正确证据，模型却仍答错
- **关键困难**：模型与工具之间存在鸿沟：原始读数无法转成可用结论，从获取证据到解读结论的证据链没有闭合
- **解决方案**：围绕“闭合证据环”设计接口：获取场景证据、存入持久场景记忆、用平实的空间语言解释每次读数，读数始终以工具的几何结果为依据
- **主要结果**：MMSI-Bench/ReVSI 上 Qwen3.8-27B 分别 +13.9/+20.5，Gemini-3.8-Flash +11.2/+9.6；开源主干模型达 66.5/82.3，超 SpatialClaw 的 62.6/74.5
- **未来方向**：工具带来的增益随主干模型能力增强而缩小，需研究如何在更强的模型上保持收益

## 2610.26342 · VibeTraining-Bench: Data-Trainer-Harness Co-Design for Iterative System Improvement
*VibeTraining-Bench：面向迭代系统改进的数据-训练器-脚手架协同设计*

- Ruotian Peng, Yuanyi Ren, Shuaiqi Liu, Xin Guo, Fang Zhu, Yangyi Huang, Yue Wu, Zheng Wang, Yandong Wen, Zhihang Fu
- [Abs](https://arxiv.org/abs/2610.26342v2) · [PDF](https://arxiv.org/pdf/2610.26342v2) · [Code1](https://github.com/D2I-ai/VibeTraining-Bench)
- **核心问题**：现有基准无法评估智能体诊断系统瓶颈并联合优化训练数据、训练器和推理脚手架以实现递归自我改进的能力
- **关键困难**：数据、训练器与推理脚手架高度耦合，单组件优化难累积收益，且开放式研究易发生测试集奖励黑客
- **解决方案**：各任务从相同初始系统和固定资源预算出发，研究智能体依据验证反馈迭代改进数据、训练器和推理脚手架并提交最终系统；用测试隔离、研究/评分容器分离和网络限制防作弊
- **主要结果**：SWE-bench Verified 上 GPT-6-Astra 将目标智能体系统从 32.9% 提升至 53.7%，接近人工 instruct 模型的 55.4%
- **未来方向**：跨组件协同设计与迭代精炼数据、训练器和脚手架以实现累积性能提升的能力仍有提升空间

## 2610.24611 · HSPR: Recovering Software-Agent Benchmark Scores via Hierarchical Posterior Inference
*HSPR：通过分层后验推断恢复软件智能体基准分数*

- Wanyi Chen, Wanqin Shen, Yuanchen Shi, Zhensu Sun, Fang Kong
- [Abs](https://arxiv.org/abs/2610.24611v2) · [PDF](https://arxiv.org/pdf/2610.24611v2)
- **核心问题**：全量评测软件智能体成本高，小子集虽可保持排名但分数不准确
- **关键困难**：相同源响应的任务对新目标智能体可有不同结果，历史响应结构不足以直接定分
- **解决方案**：用源拟合响应因子和组成功率后验建模目标潜在状态；观测结果更新后验，按全分数后验方差期望下降选任务，最终取后验中位数并校准
- **主要结果**：SWE-bench 四任务库 10% 预算：三库 MAE 最低、四库 MaxErr 最低；消融使 macro MAE 升高，5–20% 预算 MAE 下降

## 2610.28069 · Training the Whole Agent, Not Just the Model
*训练整个智能体，而不仅是模型*

- Lingxiao Tang, Wei Tao, Yiwen Guo, Lingfeng Bao
- [Abs](https://arxiv.org/abs/2610.28069v1) · [PDF](https://arxiv.org/pdf/2610.28069v1)
- **核心问题**：训练 coding agent 时只更新策略而固定 harness，忽略轨迹暴露的错误修复策略与交互缺陷
- **关键困难**：轨迹暴露的修复缺陷随任务而异、随策略漂移，静态或人工设计的 harness 难以匹配训练动态
- **解决方案**：冻结教师按任务生成机制级技能；另一教师模型演化工具与钩子，仅在观测通过率或可训练率提升且不降低另一项时保留改动，新轨迹驱动进一步演化
- **主要结果**：9B 模型在 SWE-bench Verified、Multilingual、Pro 上 pass@1 比 GRPO 高 9.8、12.6、6.4 个百分点，并优于配 OpenHands harness 的 GRPO
- **未来方向**：部署时移除机制级技能与演化工具最多损失 7.7 个百分点，需权衡对演化 harness 的依赖

## 2610.27911 · MMEnterprise-Bench: Evaluating Enterprise Agents over Evolving Multimodal Records
*MMEnterprise-Bench：评估面向持续演化多模态记录的企业智能体*

- Seohyun Lee, Jongha Kim, Dohwan Ko, Ji Soo Lee, Seoung Choi, Jayun Ku, Hyunwoo J. Kim
- [Abs](https://arxiv.org/abs/2610.27911v1) · [PDF](https://arxiv.org/pdf/2610.27911v1)
- **核心问题**：企业工作区中同一信息存在跨文档、聊天、图表的多个版本，智能体需在充分证据上推理并识别证据不足
- **关键困难**：现有评测缺乏随时间演化、跨来源冲突的多模态记录，模型难以处理跨源或时序冲突及多图证据
- **解决方案**：用模拟协作项目生成持续演化的多模态记录，按证据推理、冲突消解、不可回答三类构造问题，评测 10 个多模态 LLM
- **主要结果**：最强模型在跨源/时序冲突与多图证据上仍显著吃力；提高检索预算或换更大检索器提升证据召回但不稳定提升答案准确率

## 2610.27797 · Toward Agentic AI for the 6G Physical Layer: From Algorithm Discovery to Verified Baseband Silicon
*面向6G物理层的Agentic AI：从算法发现到经硅验证的基带硅*

- Eric Mittag, Lukas Brechtel, Maximilian Stark, Hans D. Schotten
- [Abs](https://arxiv.org/abs/2610.27797v1) · [PDF](https://arxiv.org/pdf/2610.27797v1)
- **核心问题**：AI能高速发现6G物理层算法，但将单个算法落到嵌入式基带硅上仍依赖专家，且受内存与数值限制。
- **关键困难**：仅在GPU上设计无法感知目标芯片的内存/数值约束与独特成本结构，硬件盲搜索难以找到可利用芯片成本的结构。
- **解决方案**：LLM编码智能体以实测平台知识库引导，用禁止修改的评测器逐步检查并按阶段计量，在商用基带SoC上实现、优化至手写向量汇编并硅验证。
- **主要结果**：6G4All上12个OTFS内核硅上周期精确运行，优化版18k–405k cycles（30–660 μs）/帧；新检测器较移植版省13.9% cycles且误码率相当。

## 2610.27693 · Knowledge as Code

## 2610.26770 · HarnessPro: Recursive Harness Self-Improvement with Pareto Optimization for Performance-Cost Trade-offs
*HarnessPro：面向性能-成本权衡的帕累托优化递归 Harness 自我改进*

- Zhuoshi Pan, ZhiYuan Feng, Yukuo Cen, Honglin Lin, Junru Lu, Zhongxia Chen, Shuo Yang, H. Vicky Zhao, Jie Tang
- [Abs](https://arxiv.org/abs/2610.26770v2) · [PDF](https://arxiv.org/pdf/2610.26770v2) · [Code1](https://github.com/pzs19/HarnessPro)
- **核心问题**：现有 harness 递归自我改进虽提升任务表现，但执行成本同步升高，缺少可控的性能与成本权衡。

- **主要结果**：在 Terminal-Bench 2、SWE-Bench Pro、ProgramBench 上，GPT-5.5+Codex 的 heavy 模式相对 RHO 平均通过率 +2.0 个百分点，单任务成本 -26.1%；GLM-5.2+Claude Code 同样有效。

## 2610.27524 · MemDev-Bench: Does Memory Help Code Agents?Benchmarking Memory Systems over Real Repository Histories
*MemDev-Bench：记忆对代码智能体有帮助吗？在真实仓库历史上基准测试记忆系统*

- Guorui Chen, Tao Liu, Zhenzhen Huang, Yidan Zhang, Liyu Jiang, Shuoyuan Wang, Hanchen Sun, Xu He, Dong Li, Yihan Hu, Jianye Hao, Lei Feng
- [Abs](https://arxiv.org/abs/2610.27524v1) · [PDF](https://arxiv.org/pdf/2610.27524v1)
- **核心问题**：记忆系统如何组织代码智能体的历史经验并影响其表现尚不清楚
- **关键困难**：现有基准缺少时间有效的仓库历史，或无法控制先前任务与当前任务的相关性
- **解决方案**：将任务与同仓库相关性标注的历史任务配对，构建受控历史；自动流水线保证历史任务可执行可验证，产出4869个历史任务、555个基础任务并系统评测记忆系统
- **主要结果**：记忆主要提升细粒度定位与编辑及功能正确性；也会导致可解任务失败，无关历史加剧；直接给原始历史轨迹比记忆系统显著减少步骤
- **未来方向**：未来记忆系统应保留过程信息，并依据当前任务上下文重新评估记忆适用性

## 2610.27381 · Documentation Drift in AI-Generated Pull Requests
*AI 生成的 Pull Request 中的文档漂移*

- Will De Michele, Kla Tantithamthavorn
- [Abs](https://arxiv.org/abs/2610.27381v1) · [PDF](https://arxiv.org/pdf/2610.27381v1)
- **核心问题**：AI 编码代理大规模提交 PR，但其文档更新行为及文档漂移的后果尚未被刻画
- **关键困难**：有文档的 PR 规模大 3.9 倍，原始 PR 级比较会得出相反结论，须控制规模暴露
- **解决方案**：在 AIDev 的 29,669 个 AI PR 上计算代码与文档共变，按任务类型分组，控制规模后比较未文档化文件的后续修复与再文档化率
- **主要结果**：63.2% 的 AI PR 改代码不更新文档；未文档化文件后续修复率高 8.6–11.7%，90 天内再文档化率 24% vs 48%

## 2610.27377 · REM: What to Store, When to Recall, What to Forget in Experience Memory for Coding Agents
*REM：编码智能体的经验记忆中存什么、何时召回、何时遗忘*

- Xinyi Lisa Chen, Pedro Herrero-Vidal, Xiaohan Chen, Xiaojing Yu, Cris Liu, Bingqing Song, Bin Xu, Suleiman A. Khan, You-Lin Chen · NeurIPS 2026
- [Abs](https://arxiv.org/abs/2610.27377v1) · [PDF](https://arxiv.org/pdf/2610.27377v1)
- **核心问题**：长程编码任务每次运行产生的经验很少被复用，现有记忆系统只关注检索。
- **关键困难**：检索无法观察运行中的智能体，无法判断是否需要经验、何时需要、保留多久。
- **解决方案**：将完成轨迹压缩为阶段结构化文档，任务开始时注入；实现记录由循环内门控在智能体受阻时注入，单次暴露后驱逐。
- **主要结果**：SWE-ContextBench Lite 上 match@1 68.7% vs 55.6%，解决率 27.6% vs 24.9%，成本低 17%；消融任一决策均下降。

## 2610.27293 · Vulnerability Analysis for Safe Multi-Agent Reinforcement
*安全多智能体强化学习的脆弱性分析*

- Taozheng Zhu, Shixiong Jiang, Fanxin Kong
- [Abs](https://arxiv.org/abs/2610.27293v1) · [PDF](https://arxiv.org/pdf/2610.27293v1)
- **核心问题**：安全多智能体强化学习策略在推理时对观测扰动攻击的脆弱性尚未被充分研究
- **关键困难**：现有SMARL方法只关注策略优化中的安全约束，忽视推理阶段观测攻击及良性智能体协同抵抗
- **解决方案**：MinMax Attack 在推理时扰动部分智能体观测，联合选择对抗目标动作并计入良性智能体协同抵抗，推导安全成本上界及其与攻陷/扰动预算关系
- **主要结果**：多个安全关键基准上，MinMax Attack 比基线产生更高安全成本，同时保持任务奖励，隐蔽性更好
