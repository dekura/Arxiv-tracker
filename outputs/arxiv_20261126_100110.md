## 2611.32718 · Seeing to Drive on a Single Board: Attention-Free Depth for Onboard Robot Navigation
*单板视觉驾驶：面向板载机器人导航的无注意力深度*

- Itai Mizlish, Boaz Ben-Moshe
- [Abs](https://arxiv.org/abs/2611.32718v1) · [PDF](https://arxiv.org/pdf/2611.32718v1) · [Code1](https://github.com/itaim18/DANIEL)
- **核心问题**：深度基础模型是GPU级ViT，难以在单板摄像机和低功耗算力上实时运行，int8量化后深度大面积缺失
- **关键困难**：int8量化下多数softmax权重低于一个步长却仍承载注意力质量，Depth Anything V2在边缘芯片丢失大面积场景
- **解决方案**：把Depth Anything V2-Large蒸馏成24.5M无注意力ResNet-34 U-Net，全整数跑在Hailo-8L；以地面交点测距，规划与SLAM用Pi CPU
- **主要结果**：27.1 FPS，int8与float Pearson 0.99993；仿真AbsRel 0.269，真实户外与V2-Small无显著差异且更快

## 2611.33148 · CoT-Proxy: Cross-Format Transfer for Distilling Long-Horizon Policies
*CoT-Proxy：面向长时程策略蒸馏的跨格式迁移*

- Dawid J. Kopiczko, Tijmen Blankevoort, Yuki M. Asano
- [Abs](https://arxiv.org/abs/2611.33148v1) · [PDF](https://arxiv.org/pdf/2611.33148v1)
- **核心问题**：闭源强教师的思维链不可见、仅暴露动作，如何只靠动作蒸馏长时程策略
- **关键困难**：标准微调需模仿教师思维链，但闭源教师的 CoT 藏在 API 之后，学生无法获取
- **解决方案**：学生以空推理块在教师轨迹上微调，并用自身生成回放缓冲区的 KL 损失限制漂移；再以 CoT-proxy 短摘要替代隐藏思维链
- **主要结果**：AppWorld 上 Qwen3-4B 7%→18%、加 CoT-proxy 至 35%；SWE-bench Verified 3%→28%

## 2611.33093 · AIChipBench: Benchmarking LLM Agents for Automated AI Accelerator Design
*AIChipBench：评测用于自动化 AI 加速器设计的 LLM Agent*

- Guangyuan Wang, Chengran Li, Minchen Luo, Jichen Feng, Mengdi Wang, Yifan Zhang
- [Abs](https://arxiv.org/abs/2611.33093v1) · [PDF](https://arxiv.org/pdf/2611.33093v1)
- **核心问题**：LLM 编码 agent 能否正确实现带跨步存储状态的量化解码器 RTL，现有评测只检查输出
- **关键困难**：状态更新出错时当前 token 仍正确、数个 token 后才暴露，设计可通过输出测试却是错的
- **解决方案**：给出规定每步输出与存储状态的可执行整数参考；agent 在固定预算内用公开测试调试，冻结设计在留出 token 序列、复位、内存停顿与综合上评分，另设近等面积加速赛道
- **主要结果**：9136 次尝试；状态失配反馈在全部 12 个 agent–任务组合中使接受率升 25.0–46.9 个百分点、每设计工时减半；69 个被接受设计中 45 个在新序列与条件下失败

## 2611.32931 · Reading Decisions Before Spans: Efficient Generative Verification
*在 Span 之前读取决策：高效的生成式验证*

- Yanbin Gong, Lei Chen
- [Abs](https://arxiv.org/abs/2611.32931v1) · [PDF](https://arxiv.org/pdf/2611.32931v1)
- **核心问题**：生成式验证器为判断声明是否有错，需继续解码以引用并分类错误，输出冗余
- **关键困难**：决策出现在定位之前，但自回归解码仍须先生成固定的语法前缀 token
- **解决方案**：冻结 2B span verifier；Native8 在分支处停止生成；Prefill1 将前七个固定语法 token 作为输入预填，只生成无约束的分支 token，沿用同一原生指令
- **主要结果**：2,015 条代码代理 TEST 响应上，常驻服务开销较完整生成降 84.84%，F1 83.43 对 83.41；较 Native8 再省 31.98%，编译执行下额外省 6.74-26.73%
- **未来方向**：受控证据干预与首位置解码显示，短读出不保留全部信息，部分情形仍需继续生成

- **关键困难**：规划的空间关系未被显式实例化，难以在图像合成前检查、核对和精修，导致主体组织不可靠

## 2611.32246 · SkillCore: Internalizing Generalizable Skills via Scaffolding-Removed Fine-Tuning
*SkillCore：通过移除脚手架微调内化可泛化技能*

- Yi Liu, Changqing Ai, Peijie Dong, Xiankun Lin, Yongkang Yang, Zhezheng Hao, Xilin Xia, Hande Dong, Qiang Lin, Qiang Xu
- [Abs](https://arxiv.org/abs/2611.32246v1) · [PDF](https://arxiv.org/pdf/2611.32246v1)
- **核心问题**：可泛化技能需用户主动调用，多数用户不会加载，导致能力只惠及少数人
- **关键困难**：技能内容与执行过程耦合，模型一旦不加载外部技能就无法自主复用流程性知识
- **解决方案**：将真实 agent 轨迹中的技能加载片段移除但保留任务上下文与后续动作做 SFT，并混入少量保留技能调用的原始轨迹以维持任务专属技能调用
- **主要结果**：无技能 held-out 评测上任务完成质量较 Qwen3-8B 提升 54.4%、较 Qwen2.5-72B 提升 24.8%，并保持技能调用与 SWE-bench Verified 性能

## 2611.32195 · When Answering Is Administering: Permission Replies That Rewrite Coding-Agent Policy
*当回答即管理：重写编码智能体策略的权限回复*

- Zeming Fei, Hongming Fei, Jingwen Chen, Xiaoyang Wang, Prosanta Gope, Biplab Sikdar, Ying Zhang
- [Abs](https://arxiv.org/abs/2611.32195v1) · [PDF](https://arxiv.org/pdf/2611.32195v1)
- **核心问题**：一次权限提示的回答可改写后续所有回答所依据的策略，令无文件访问的远程服务删除deny规则并读取秘密
- **关键困难**：逐决策校验漏掉跨运行策略改写；只检查新增/替换 allow 规则，且删除记录与本地编辑不可区分
- **解决方案**：证明两个紧致边界：无法识别规则作者时只接受保持所有当前被拒调用仍被拒的更新；能记录作者时各方可只删除属于自己的限制；在共享更新步骤执行

## 2611.32064 · Fix How It Acts, Not How It Thinks: Surgical Fine-Tuning of Frontier LLMs
*修复行为而非思维：前沿 LLM 的外科式微调*

- Sandeep Singh Sandha, Prann Bansal, Arvind Sundararajan
- [Abs](https://arxiv.org/abs/2611.32064v1) · [PDF](https://arxiv.org/pdf/2611.32064v1) · [Code1](https://huggingface.co/abacusai/Smaug-Nemotron-3.5) · [Code2](https://huggingface.co/abacusai/Smaug-Nemotron-3.5-NVFP4)
- **核心问题**：开放权重 LLM 具备软件工程能力，却会在长轨迹中因重复失败步骤或未满足需求就结束等小失误而失败，并非推理失败。
- **关键困难**：LoRA 更新太小，合并进 BF16/FP8/NVFP4 发布检查点后大部分范数丢失，标准 LoRA 训练时看不到舍入后权重。
- **解决方案**：提出 merge-aware fine-tuning：每步将基座权重与适配器更新之和按发布格式舍入并保留量化 scale，前向匹配服务引擎，梯度直通舍入，只优化动作损失。
- **主要结果**：在 Nemotron-3.5 上，BF16 与 NVFP4 发布版的智能体编程均提升，Terminal-Bench 2.1 最高提升 8.4 分，并公开两个模型。

## 2611.32037 · Online Environment Repair for Coding Agents

- Sheng Lu, Rui Mao, Zewei Chen, Chihua Ying, Beiduo Chen, Dingxin Hu, Tinghao Yu
- [Abs](https://arxiv.org/abs/2611.32037v1) · [PDF](https://arxiv.org/pdf/2611.32037v1)
- **核心问题**：程序化验证器存在缺陷与单测不全，策略可获满分却不解决任务，现有防御惩罚输出或过滤任务仍有效性问题

- **解决方案**：由执行不变量或差分模糊测试触发候选修复，经三道自动验证门确保阻断利用且保留正解，异步部署并结构化传播到各仓库

## 2611.31929 · Shuttle: Dependency-Attributed Workflow Evolution for Smart Contract Auditing

- Yue Xue, Yi Rong, Ziqiao Kong, Ronghui Gu, Dan She, Yuannan Yang, Zhiju Yang, Yuqiang Sun

## 2611.31927 · (No) Separation of Concerns: Philosophical Concerns about Agent Ethics and Implications for SE Practitioners
*（无）关注点分离：关于 Agent 伦理的哲学关切及对 SE 从业者的启示*

- Marc Cheong, Sebastian Baltes, Joanne Byrne, Haoyu Gao, Raula Gaikovina Kula, Sarita Rosenstock, Christoph Treude, Mansooreh Zahedi
- [Abs](https://arxiv.org/abs/2611.31927v1) · [PDF](https://arxiv.org/pdf/2611.31927v1)
- **核心问题**：SE 从业者多以原则主义视角看待 AI Agent 伦理，与哲学文献脱节，伦理关切难以落到编码智能体的具体实践。
- **关键困难**：哲学伦理讨论抽象，未映射到代码评审、配置、评测与需求等具体 SE 环节，从业者缺少可操作指引。
- **解决方案**：系统映射 PhilPapers 自 2023 年起的 33 篇哲学论文，主题编码得 8 个主题、85 个编码，经跨学科复核导出 7 个 SE 研究问题与 5 条团队实践建议。
- **主要结果**：33 篇论文编码出 8 主题 85 编码，导出 7 个研究问题与 5 条实践建议（小颗粒 PR、配置配检查、记录审批等）。
- **未来方向**：主张伦理关切须嵌入代码评审、配置、评测与需求环节，需跨学科合作推进。

## 2611.30405 · Optimistic Online Learning for Coding Agents with Aggregate Feedback
*带聚合反馈的编码智能体乐观在线学习*

- Hao Luan, Hao Qiu, Zhi Zheng, See-Kiong Ng, Zhiyong Huang
- [Abs](https://arxiv.org/abs/2611.30405v1) · [PDF](https://arxiv.org/pdf/2611.30405v1)
- **核心问题**：多轮编码智能体存在行为漂移，静态激活转向策略难以适配异构任务与不同执行轮次
- **关键困难**：任务级可验证反馈仅在完成时给出，单轮转向贡献不可观测，难以在线选择策略
- **解决方案**：构建带任务级延迟反馈与轮级预测提示的多臂老虎机，提示指导任务内策略选择，终止反馈校正累计奖励估计
- **主要结果**：在真实编码基准上优于静态转向策略与朴素在线自适应基线；遗憾界随提示准确率收紧

## 2611.30350 · RepoClean: Evaluating Coding Agents on Repository-Level Obsolete Code Cleanup
*RepoClean：在仓库级过时代码清理上评测编码智能体*

- Hongyixuan Yuan, Qixing Zhou, Pengcheng Huang, Qingshuo Ni, Runsong Zhao, Shaokai He, Xiangpeng Li, Deqiang Ouyang
- [Abs](https://arxiv.org/abs/2611.30350v1) · [PDF](https://arxiv.org/pdf/2611.30350v1)
- **核心问题**：编码智能体能否在仓库级别安全识别并删除冗余、过时代码，目前缺乏独立、系统的评测
- **关键困难**：必须借助仓库接口与跨文件依赖判断哪些历史代码该删、哪些当前实现须保留，且不得引入新功能
- **解决方案**：从34个流行开源 Python 仓库的历史中重建已删除代码至较新版本，保留现状实现，仅保留旧测试因此失败的案例，构成200个清理任务
- **主要结果**：7个模型中最好的 GPT-6 Astra 仅解决23%任务；未显式要求清理时，智能体删除的过时代码量明显更少
- **未来方向**：为系统研究仓库级清理难题、推进面向自主软件维护的编码智能体提供基础

## 2611.30226 · VeriWorld: A Verifiable Visual SWE-Bench for Spatial Reasoning in 3D Environments
*VeriWorld：用于3D环境空间推理的可验证视觉SWE-Bench*

- Yan Zheng, ShengYun Peng, Xuyao Liang, Xiaoyan Cong, Nuo Chen, Bangya Liu, Zihan Wang, Wenyan Cong, Zhiwen Fan, Zhangyang Wang · NeurIPS 2026
- [Abs](https://arxiv.org/abs/2611.30226v1) · [PDF](https://arxiv.org/pdf/2611.30226v1) · [Code1](https://github.com/VITA-Group/VeriWorld) · [Code2](https://huggingface.co/datasets/yanyanzheng96/VeriWorld)
- **核心问题**：现有基准多孤立测试感知与推理，难以判断失败源于视觉理解、下游推理还是二者衔接
- **关键困难**：同一任务下视觉输入、推理过程与交互协议相互混杂，缺少受控对照来定位失败原因
- **解决方案**：构建交互式3D环境基准，提供可执行动作与确定性验证器；对可三分任务在同一实例上评测视觉、结构化、组合输入，其他任务单独报告
- **主要结果**：发现视觉到结构鸿沟：显式给出对象身份/状态/位置时表现常优于从渲染场景读取；动作空间与harness设计也会改变结果

## 2611.32812 · Breaking the Joint Action Space Dependence in Distributionally Robust Multi-Agent Reinforcement Learning
*打破分布鲁棒多智能体强化学习中的联合动作空间依赖*

- Yue Wang
- [Abs](https://arxiv.org/abs/2611.32812v1) · [PDF](https://arxiv.org/pdf/2611.32812v1)
- **核心问题**：分布鲁棒Markov博弈中学习鲁棒粗相关均衡的样本复杂度随联合动作数∏_iA_i指数增长
- **关键困难**：现有生成模型保证依赖∏_iA_i，玩家数增加导致多智能体诅咒
- **解决方案**：插件式估计鲁棒backup，其平均误差与状态数无关；每轮单批样本同时作为所有玩家的bandit反馈，使复杂度仅依赖A_*
- **主要结果**：给出\widetilde O(SA_*H^5D^4/ε^4)样本复杂度，以至少1-δ概率从任意初始状态返回ε-鲁棒CCE
- **未来方向**：工作进展中（preprint）

## 2611.31880 · Multi Agent Reinforcement Learning enhanced Federated Learning for Predicting Remaining Useful Lifetime
*多智能体强化学习增强的联邦学习用于预测剩余使用寿命*

- Rajarshi Chattopadhyay, Chen-Khong Tham
- [Abs](https://arxiv.org/abs/2611.31880v1) · [PDF](https://arxiv.org/pdf/2611.31880v1)
- **核心问题**：联邦学习在丢包无线链路上交换模型易受丢包影响，导致 RUL 预测性能下降。
- **关键困难**：现有 FL 多假设可靠链路；UDP 低时延但丢包造成模型交换不完整，影响预测。
- **解决方案**：协同 MARL 为每客户端选择传输层子集并限制重传，用 QMIX 分解值函数扩展；以 GCPATr 做 RUL 预测。
- **主要结果**：CMAPSS 上 RL-FL 的 MSE 持续优于标准 FL，50% 丢包下 FD003 提升达 18%。
