## 2611.29180 · loopxDINO: Dense Visual Prediction via Iterative Latent Reasoning
*loopxDINO：通过迭代潜空间推理的稠密视觉预测*

- Xiangjing An, Zhibin Jiao, Aiting Chen
- [Abs](https://arxiv.org/abs/2611.29180v1) · [PDF](https://arxiv.org/pdf/2611.29180v1) · [Code1](https://github.com/loopxDINO/loopxDINO)
- **核心问题**：稠密视觉预测靠堆叠 6-16 层解码器提升容量，激活内存与权重带宽开销大，且计算量静态固定
- **关键困难**：深层前馈解码器反向传播激活内存高、非共享权重需高片外带宽，静态算力无法随图像区域复杂度调整
- **解决方案**：冻结 DINOv2-Base 单次前向并缓存 KV；7.96M 权重共享循环 cross-attention 解码器迭代更新 query，用 step-conditioned adaLN、流形正则与残差阻尼稳定循环，中间掩码回馈为空间注意力偏置
- **主要结果**：VOC 2012（T=2）达 85.66% mIoU、65.01% bIoU；较 54.06M 的 DINO-Trans6L 参数少 72.5%，bIoU +7.41；60% 遮挡下 +5.83% mIoU

## 2611.29745 · Agentic Root Cause Reasoning and Localization of Unsoundness in Static Call Graph Analysis
*静态调用图分析中不健全性的智能体根因推理与定位*

- Mohammad Rafieian, Michael Hicks, Shiyi Wei
- [Abs](https://arxiv.org/abs/2611.29745v1) · [PDF](https://arxiv.org/pdf/2611.29745v1)
- **核心问题**：静态调用图工具无法健全建模动态语言特性，却很少揭示结果何时、何处、为何不健全。
- **关键困难**：现有工具只显示调用缺失，缺少可验证根因、工具位置定位及对新程序的预警。
- **解决方案**：对比静态与动态调用图找运行时缺失边界边；LLM提出未建模模式与工具位置，经运行时插桩、复现测试和告警插入三重证据验证。
- **主要结果**：1459边界边直接推理10.3%（人工全确认），分组解决84.1%；告警覆盖74%-92%；代理移除64%目标模式。

## 2611.29590 · KernelShift: Benchmarking Kernel Optimization Across Evolving Hardware
*KernelShift：跨演进硬件的内核优化基准测试*

- Shuaiwei Huang, Weihua Du, Allen Wu, Ivan Fox, Manupa Karunaratne, Yiming Yang, Sean Welleck
- [Abs](https://arxiv.org/abs/2611.29590v1) · [PDF](https://arxiv.org/pdf/2611.29590v1)
- **核心问题**：编码智能体能否有效利用不断出现、可能不熟悉的CPU架构扩展来写出高性能内核
- **关键困难**：新扩展（如SME2矩阵块）引入陌生编程模型，智能体难以可靠迁移与适配
- **解决方案**：构建99个来自ncnn、llama.cpp、Arm SIMD Loops、KleidiAI的内核实例，提供目标硬件反馈环境并随库与处理器演进扩充
- **主要结果**：在Neon/SVE等成熟扩展上超越自动向量化编译器2.4-19.8x、超ncnn最多2.74x，但仅为KleidiAI的0.70x；两LLM预填加速1.3-1.6x
- **未来方向**：智能体尚不能可靠适应SME2等需陌生编程模型的新扩展

- **解决方案**：共享权重下用统一因果序列做跨智能体联合自注意力，层级语言、身份编码与本体掩码绑定各流角色、身份和本体，并以编码智能体流水线生成MA-Bench

## 2611.29242 · Edit-Induced Dependency Mismatch: Propagation Omissions, Recovery, and Evaluation Blind Spots in Coding Agents
*编辑引发的依赖不匹配：编码代理中的传播遗漏、恢复与评测盲点*

- Fei Ding
- [Abs](https://arxiv.org/abs/2611.29242v1) · [PDF](https://arxiv.org/pdf/2611.29242v1)
- **核心问题**：编码代理迭代改码时仍复用上下文中过时的依赖判断，导致后续推理出错，消费方缺陷未被原任务评测发现
- **关键困难**：现有基准只凭补丁是否通过测试打分，无法检出编辑引发的消费方传播遗漏，缺陷沿既有消费路径潜伏
- **解决方案**：在 DeepSWE、SWE-bench Verified、FeatureBench 采集执行轨迹，做盲审与补充执行校验，关联消费方代码呈现、显式依赖判断与同步动作，并测试依赖复查提示
- **主要结果**：盲审终态不匹配事件均有执行支持；同一轨迹可恢复又终态遗漏；依赖复查提示减少终态遗漏；补丁通过原评测但额外检查发现消费路径缺陷
- **未来方向**：建议分别度量任务得分、终态传播状态与恢复；未给出跨基准规模的量化统计

## 2611.29238 · GameAnything: From Any Inspirations to Playable Game Worlds
*GameAnything：从任意灵感生成可玩游戏世界*

- Wenyi Wu, Siqi Liu, Yuru Feng, Zixuan Song, Aayush Salvi, Sibo Zhu, Kun Zhou, Biwei Huang
- [Abs](https://arxiv.org/abs/2611.29238v1) · [PDF](https://arxiv.org/pdf/2611.29238v1)
- **核心问题**：现有系统与基准只针对显式开发规格，难以适配多模态参考素材，也缺乏对真实可玩体验的评测
- **关键困难**：把参考素材转成可玩交互本身很难，精确修改难以保证，且缺少面向玩法质量的评测手段
- **解决方案**：开源 agentic 平台：编码 agent 接收多模态灵感，由独立试玩 critic 反馈，结合持久开发状态与经验记忆迭代生成既有游戏的可玩扩展；并构建 GameAnything-Bench 覆盖多种参考模态、创作目标与游戏环境，用探索式试玩评估功能正确性与玩法质量
- **主要结果**：对九种编码 agent 配置的评测显示：能够适配参考内容，但可玩交互与精确修改仍吃力；多模态参考提升内容保真度，迭代精修带来提升，但幅度因 agent 而异
- **未来方向**：提升可玩交互生成与精确修改能力仍是待解问题

## 2611.29193 · Direct Feedback Policy Optimization for AI Coding Agents
*面向 AI 编程智能体的直接反馈策略优化*

- Fei Ding
- [Abs](https://arxiv.org/abs/2611.29193v1) · [PDF](https://arxiv.org/pdf/2611.29193v1)
- **核心问题**：AI 编程智能体通过多轮交互生成、修改并验证代码，需评估中间决策对任务结果的影响
- **关键困难**：现有 RL 多用稀疏终局奖励，中间决策贡献难评估；组相对方法需对每任务重复采样

- **主要结果**：在匹配基座模型与执行框架下，任务解决率高于 GSPO

## 2611.29162 · Fixed or Deleted? External Feedback Lets Cheaper AI Coding Agents Repair Rule Violations
*修复还是删除？外部反馈让更便宜的 AI 编码智能体修复规则违规*

- Laura Wynter
- [Abs](https://arxiv.org/abs/2611.29162v1) · [PDF](https://arxiv.org/pdf/2611.29162v1) · [Code1](https://github.com/CodeAssureLabs/external-feedback-coding-agents)
- **核心问题**：代码本身看不出分层约束、必需测试等规则违规，LLM 编码智能体能否借外部检查反馈更好修复
- **关键困难**：智能体常直接删除新增文件来清除缺陷，按“缺陷消失”计分会把功能删除误判为修复成功
- **解决方案**：用 CodeAssure 报告违规位置与修复目标驱动智能体，修复须通过编译并保留功能才算成功，并加入删除文件检查
- **主要结果**：修复率 39%→84%；小/中/大模型分别 26→69%、46→90%、45→93%，优于 Copilot 审查；免费工具仅检出 8/31，CA 检出 31/31

## 2611.28704 · Zero-Trust Formal Methods: AI Agents Build Verified Checkers for Untrusted Solvers
*零信任形式化方法：AI agent 为不可信求解器构建经验证的检查器*

- Tobias Philipp
- [Abs](https://arxiv.org/abs/2611.28704v1) · [PDF](https://arxiv.org/pdf/2611.28704v1)
- **核心问题**：求解器的“不可满足/最优”答案无法直接检查，且求解器与查询翻译存在健全性缺陷
- **关键困难**：现有验证把求解器与查询翻译放入可信基，且已有健全性缺陷；agent流水线默认信任验证器和求解器
- **解决方案**：Agent生成Isabelle/HOL规范、健全性证明与参考检查器，再生成镜像规范的Rust实现并用Verus验证；规范评审后冻结，求解器答案须经经验证检查器接受证书
- **主要结果**：3,726条SMT查询全认证，15,662个ASP证明通过双检查器；发现3个检查器与5个求解器的健全性缺陷

## 2611.28477 · ESM-Bench: A Benchmark for Evaluating Whether AI Agents Understand Earth System Model Physics and Code
*ESM-Bench：评估 AI 智能体是否理解地球系统模型物理与代码的基准*

- Koutian Wu, Yuxuan Cao, Gengchen Mai, Zeping Liu
- [Abs](https://arxiv.org/abs/2611.28477v1) · [PDF](https://arxiv.org/pdf/2611.28477v1)
- **核心问题**：AI编码代理修改地球系统模型（ESM）代码时须同时保住软件接口与代码中编码的物理假设，缺少可评估该能力的基准
- **关键困难**：参考补丁与文本模式检查器等局部代理证据可能给出错误的正确性判断，物理正确性难以验证
- **解决方案**：从Noah-MP、CLM5、SUMMA、ParFlow、MOM6、VIC六个仓库采集60个开发者提交任务，覆盖物理缺陷修复、过程表示修改、参数化方案选择与参数优化，配八项补丁评审规则与诊断工具
- **主要结果**：5个存档补丁diff均无法应用到给定起始文件，但3个文本模式检查器仍返回通过；ParFlow表达式重放与参考斜率不符，MOM6模式检查漏检省略的更新，VIC参考赋值覆盖植被特定反照率
