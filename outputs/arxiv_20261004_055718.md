## 2610.00425 · Code That Works, Environments That Don't: Measuring Environment Reproducibility in AI-Generated Software
*能运行的代码，不能运行的环境：测量 AI 生成软件的环境可复现性*

- Bhanu Prakash Vangala, Tanu Malik · AAAI
- [Abs](https://arxiv.org/abs/2610.00425v1) · [PDF](https://arxiv.org/pdf/2610.00425v1)
- **核心问题**：代码生成评测只看功能正确性，忽略环境依赖规范这一同等关键维度，导致依赖不一致、冗余或不完整却无法被功能测试发现
- **关键困难**：现有基准不含环境规范检查，无法定位依赖错误来源；跨 agent、语言与任务的一致性差异缺乏可测度量
- **解决方案**：设计环境规范 agent 协议，将依赖拆为声明、运行时安装、必要且充分三层分层比对，在 3 个 agent、4 种语言、50 个任务上测量依赖集一致性与层间分歧
- **主要结果**：同一任务依赖集一致率低至 7%；更新的 agent 无实质提升；最大分歧出现在声明层与运行时层之间，指向训练分布中的环境先验
- **未来方向**：需设计同时优化功能正确性与环境可移植性的训练目标和评测协议

## 2609.39081 · Coding Agents for Coding Theory
*用于编码理论的编程智能体*

- Abraham Yeung · NeurIPS 2026
- [Abs](https://arxiv.org/abs/2609.39081v1) · [PDF](https://arxiv.org/pdf/2609.39081v1) · [Code1](https://github.com/Abraham-y/coding-agents-coding-theory)
- **核心问题**：用 LLM 编程智能体寻找四字母词（如 DNA 条形码）在编辑距离下尽可能远离的大码集
- **关键困难**：中间结果写下后从不复查，被当作排除后续搜索的事实；只检查最终输出无法发现此类错误
- **解决方案**：智能体编写验证器与搜索代码，人类选定问题并设定验证协议；限定预设对称性收缩搜索空间，另一会话用更好算子重跑
- **主要结果**：E_4(6,3) 从 114 提升到 ≥120，并改进长度 6–9、距离 3–6 的另外 12 个下界
- **未来方向**：早期错误中间结论曾耗费三周并导致长度 7 的错误判断，需复查中间产物而非仅最终输出

## 2609.38983 · Approval Laundering: Systematizing Approval--Execution Binding Failures in AI Coding-Agent Harnesses
*审批洗白：系统化梳理 AI 编程智能体执行框架中的审批—执行绑定失效*

- Yang Wang
- [Abs](https://arxiv.org/abs/2609.38983v1) · [PDF](https://arxiv.org/pdf/2609.38983v1)
- **核心问题**：智能体框架默认人类批准的动作 A 就是框架执行的动作 A'，该假设从未被系统检验
- **关键困难**：已有工作只用静态语料评估风险分类器或推断隐式授权边界，不检查已批准动作是否被原样派发
- **解决方案**：在 Claude Code 的 PreToolUse 中介点做无头重复测量，统计 Bound-Gap Rate；原型 Approval Token 用密钥绑定 principal、agent_id、session、tool、arguments、scope、expiry，密钥不回传智能体
- **主要结果**：六类洗白均复现（每类 N≈20，κ=1.0）；Approval Token 消除 Delegation、Temporal 洗白（p<10^-5），Scope/Argument 无改善（p=1）
- **未来方向**：仅绑定工具调用边界的防御存在盲区：Scope、Argument 类在字段层无差异，验证器需下探到进程层

## 2609.38982 · SimEX: Simulation-Integrated Robotics AutoResearch
*SimEX：仿真集成的机器人自动研究*

- Jiaheng Hu, Roberto Martin-Martin, Peter Stone, Rocky Duan, Zhenyu Jiang, Guanya Shi
- [Abs](https://arxiv.org/abs/2609.38982v1) · [PDF](https://arxiv.org/pdf/2609.38982v1)
- **核心问题**：LLM 编码代理如何在物理世界高效获取控制真实机器人的能力，同时避免高实验成本与安全风险
- **关键困难**：直接生成方法对机器人与物理环境理解不足；真机反复试错成本高且存在安全隐患
- **解决方案**：两阶段：先在仿真中开放式试探-优化，构建鲁棒可泛化的机器人工具箱；再用少量真机试验校正仿真器，由校正后的仿真器诊断失败并筛选候选修复方案
- **主要结果**：在叠毛巾、扫码、盘子操作等真实操作任务上，无需任何示教、仅 10 分钟真机交互即可习得机器人技能

## 2609.38885 · Doing More with Less Tokens: Hierarchical Reinforcement Learning for Efficient Coding Agents

- Haobin Li, Liang Jiang, Zhenyu Huang, Mouxing Yang, Xi Peng
- [Abs](https://arxiv.org/abs/2609.38885v1) · [PDF](https://arxiv.org/pdf/2609.38885v1)
- **核心问题**：多轮交互编码 Agent 与环境频繁交互带来大量 token 开销，推高使用成本与延迟。
- **关键困难**：推理期的上下文操纵与交互次数限制会丢弃任务相关信息，难以兼顾解决率与 token 效率。
- **解决方案**：HERO 在策略优化中优先任务解决而非 token 效率，并在轨迹级和轮次级鼓励高效推理模式，利用熵相关约束削减无效行为。
- **主要结果**：在 SWE-bench Verified 与 SWE-bench Multilingual 上，相较 SOTA 编码 Agent 与 RL 方法，解决率与 token 效率的折中更优。

## 2609.38414 · Synthesis Without Training: An Inference-Only Pipeline for Tabular, Temporal, and Relational Synthetic Data
*无需训练的合成：面向表格、时序与关系型数据的纯推理流水线*

- Zilong Zhao, Abdul Raheem, Jiayu Li, Sohei Arisaka, Darius Lim Hong Yi, Milad Abdollahzadeh, Uzair Javaid, Biplab Sikdar · NeurIPS 2026
- [Abs](https://arxiv.org/abs/2609.38414v1) · [PDF](https://arxiv.org/pdf/2609.38414v1)
- **核心问题**：主流的fit-then-sample范式每个数据集都要重训模型，跨模态需专用模型，且生成模型不透明、难以在约束下检查行为
- **关键困难**：换数据集即需重新训练，不同模态各有特征工程与专用模型，模型像黑箱无法在数据约束下审阅
- **解决方案**：对源数据算确定性统计画像，把画像而非原始行交给LLM推断字段语义与完整性约束，编码agent将其编译成可执行、可审计的采样器，统一覆盖单表、时序、关系数据

## 2610.00313 · Rules to Tools: Executable Checks for LLM Agents in Scientific Computing
*从规则到工具：面向科学计算中 LLM Agent 的可执行检查*

- Jingjie Ning, Guojiang Zhao, Chen Xu, Shanshan Zhong, Xiaochuan Li, Ji Zeng, Guolin Ke
- [Abs](https://arxiv.org/abs/2610.00313v1) · [PDF](https://arxiv.org/pdf/2610.00313v1)
- **核心问题**：科学编码 Agent 只拿到文字形式的方程、边界条件与输出要求，必须自行判断修改后的程序是否满足要求
- **关键困难**：书面规则需 Agent 自行解析与验证，易漏判违规且耗费大量模型输出，缺乏可复用、一致的可执行判定
- **解决方案**：R2T 为公开科学需求提供预制可执行检查，Agent 直接调用获知是否违规；配对实验固定检查、起始程序、模型与预算，对比文本与工具两种形式
- **主要结果**：任务ID队列完全修复 26/30 文本 vs 29/30 工具，8-ID 队列 13/16 vs 15/16；PDE 任务 23/24 vs 24/24，模型输出降 31.2%
- **未来方向**：公开 CPU 开销在两个任务ID队列均上升，Agent 输出节省因队列而异
