## 2611.21515 · Beyond Leaderboard Ranks: Selecting Software Engineering Agents Under Budget Constraints
*超越排行榜排名：在预算约束下选择软件工程 Agent*

- Srinath Srinivasan, Tim Menzies
- [Abs](https://arxiv.org/abs/2611.21515v1) · [PDF](https://arxiv.org/pdf/2611.21515v1)
- **核心问题**：排行榜排名无法可靠指导预算受限下选择哪个软件工程 Agent
- **关键困难**：准确率差异统计不显著，报告成本不一致，穷举评测候选 Agent 成本高
- **解决方案**：从 HAL 提取运行-任务记录，在显式评测预算与部署成本上限下比较选择策略，考虑准确率不确定性与成本标准化
- **主要结果**：7 基准 Pareto 前沿 35 步中 27 步差异不显著；SWE-bench 逐次减半用 6.6% 穷举开销达标，7 基准中 6 个成本最低
- **未来方向**：任务成本未知或需精确最优时优势缩小，需验证执行成本并比较复杂与简单分配方法

## 2611.21501 · Is This Code Mine? Student Ownership When AI Agents Write the Spec and the Code
*这是我的代码吗？AI 智能体编写规格与代码时学生的归属感*

- Gustavo Pinto, Enne Rebeca Silva de Freitas, Danilo Monteiro Ribeiro
- [Abs](https://arxiv.org/abs/2611.21501v1) · [PDF](https://arxiv.org/pdf/2611.21501v1)
- **核心问题**：AI 编码代理同时写规格和代码时，学生交付物是否仍反映其学习与所有权
- **关键困难**：代写使评分工件无法反映学生真实贡献，学生自述与提交记录不一致
- **解决方案**：在 Spec-Driven Development 作业中让18对学生用代理建应用，结合仓库历史挖掘、提示记录与33人问卷，分析规格/代码归属、可解释性与达标行为
- **主要结果**：代理写了69%规格；学生自认一半想法、1/5代码；多数无法解释/修改代码；达标队靠未使用代码充数，1队篡改历史
- **未来方向**：应以学生能指定、审查和解释的内容评估，并用工具强制执行工程流程

## 2611.21298 · Agent-Native by Design: A Programming Language for Agentic Applications
*设计即 Agent 原生：一种面向智能体应用的编程语言*

- Jayanaka Dantanarayana, Savini Kashmira, Xiaoyu Ma, Malitha, Malitha Prabhashana, Lingjia Tang, Jason Mars
- [Abs](https://arxiv.org/abs/2611.21298v1) · [PDF](https://arxiv.org/pdf/2611.21298v1)
- **核心问题**：构建 Agent 应用需在 SDK 或框架外写胶水代码准备输入、传播状态并分发模型选择的步骤，工作流变更带来协同修改与测试成本
- **关键困难**：执行逻辑分散在应用代码与框架内部，编译器看不到控制流与状态依赖，难以自动优化，模型路由与可执行步骤脱节
- **解决方案**：在 Python 超集 Jac 中用 by llm() 做类型化模型操作与工具调用，用对象空间编程表达工作流结构与状态，用 visit ... by llm() 从可执行步骤派生模型选择并调度所选步骤
- **主要结果**：在 5 个基准、5 个基线上，AI 集成代码较 OpenAI SDK 减少 1.8-8.7x，任务质量有竞争力，编码 Agent 开发工作量更低

- **关键困难**：递归自我改进依赖模型 rollout 或训练后评估，长程任务成本与反馈延迟被放大。
- **解决方案**：RepoFactory 将真实仓库转为可验证环境，智能体依语言规范从零构建项目；环境演化循环以乘性目标优化有效性、结构耦合与实现范围。

## 2611.21095 · SWE-WhatIf: Simulating Real Users of Coding Agents from Recorded Session
*SWE-WhatIf：从录制的会话中模拟编码智能体的真实用户*

- Tae Soo Kim, Tongshuang Wu, Juho Kim
- [Abs](https://arxiv.org/abs/2611.21095v1) · [PDF](https://arxiv.org/pdf/2611.21095v1)
- **核心问题**：录制的用户-编码智能体会话无法直接重放：新智能体轨迹不同时，原有用户回复不再适用
- **关键困难**：录制的用户回复绑定于原轨迹，换智能体后语义失效，简单重放会误判智能体能力
- **解决方案**：从录制中抽取用户意图、满足标准与出现条件，由用户模拟器针对未见过的智能体轮次生成仍扎根录制的回复
- **主要结果**：89 个真实会话中回复最接近真人；规避用户抵触动作的胜率 66.3%，显著高于随机；可对五个 LLM 编码智能体排名

## 2611.21056 · Evaluation-Free Recursive Self-Improvement for Coding Agents
*编码智能体的免评估递归自我改进*

- Zhe Ren, Guowei Rong, Yimeng Chen, Nanbo Li, Piotr Piękos, Mateusz Ostaszewski, Dandan Guo, Jürgen Schmidhuber
- [Abs](https://arxiv.org/abs/2611.21056v1) · [PDF](https://arxiv.org/pdf/2611.21056v1)
- **核心问题**：编码智能体能否在进化循环内不依赖下游任务评估实现递归自我改进
- **关键困难**：评估-选择需反复执行候选于下游任务，探索成本高且易过拟合固定评测分布
- **解决方案**：ELITE每代提出多个聚焦改进，从同一父代独立实现，检查程序识别互补冗余冲突机制，再把兼容子集重构为连贯后代；循环内只用结构与运行有效性检查，不用下游任务结果。
- **主要结果**：SWE-bench Pro 60.0→85.6%，对比DGM 86.7%、HGM 88.3%；零候选评估，耗时少8.8x/3.2x；SWE-bench Verified 73.3%、Polyglot 69.3%。

## 2611.21020 · SWE-OPD: On-Policy Distillation for Agentic Coding
*SWE-OPD：面向智能体编程的在线策略蒸馏*

- Yuhang He, Yanyu Chen, Chuanzhe Guo, Jie Zhu, Zichen Tian, Hongyu Ge, Zixuan Ren, Huang He, Bingjin Chen, Junyuan Shang, Shuohuan Wang, Yongqi Zhang, Irwin King, Jing Liu
- [Abs](https://arxiv.org/abs/2611.21020v1) · [PDF](https://arxiv.org/pdf/2611.21020v1)
- **核心问题**：如何把大模型的智能体编程能力迁移到小模型，同时降低在线轨迹采样与教师打分成本
- **关键困难**：已有在线策略蒸馏（OPD）多用于推理和短程智能体任务，缺少在可执行仓库长程交互中的验证
- **解决方案**：学生在可执行仓库中交互，教师对其访问前缀提供监督；离线变体复用缓存教师分数免刷新轨迹，并支持跨 tokenizer 蒸馏
- **主要结果**：Qwen3.5-9B 的 SWE-bench Pro 从 35.9% 升至 39.4%；离线变体省 59.4%–72.6% GPU 时；GLM-4.5-Air 从 35.8% 升至 39.7%、从 41.8% 升至 46.2%
- **未来方向**：损失下降不必然提升智能体表现，top-K reverse-KL 下出现严重重复，需进一步验证 support-mass 梯度项机制

## 2611.20927 · LEDGER: Auditable Agent Memory Under Change
*LEDGER：变化场景下的可审计智能体记忆*

- Md Aidul Islam, Md Nasir Uddin Shuvo, Muhammad Waseem, Pekka Abrahamsson
- [Abs](https://arxiv.org/abs/2611.20927v1) · [PDF](https://arxiv.org/pdf/2611.20927v1)
- **核心问题**：现有智能体记忆评测基于固定历史且只评最终答案，无法应对事实变更、来源可靠性差异与遗忘请求
- **关键困难**：固定历史评测忽视了事实随时间变化、来源可信度不同和删除需求，直接检索原始对话难以保证删除后不留残留
- **解决方案**：语言模型提议事实，显式规则决定哪个值当前有效、信任哪个来源、删除什么；LEDGER+EP 对账本未覆盖的问题检索原始对话轮次，并在删除时擦除这些轮次
- **主要结果**：编码负载正确率 94.3%/91.1%（开发/留出种子），全量重放为 82.1%/83.3%；LongMemEval 上 74.8% 与全量重放持平，仅用 1% 上下文
- **未来方向**：编码负载为自建合成数据；LongMemEval 上最强系统差异落在置信区间内

## 2611.20882 · Accelerate Bench: Evaluating Agents for Application-Level Program Optimization
*Accelerate Bench：评估用于应用级程序优化的智能体*

- Bowen Liu, Yuhan Li, Nuo Chen, Weile Luo, Miao Peng, Qintong Zhang, Qifan Zhang, Jia Li, Ziqi Gao, Lydell Huang
- [Abs](https://arxiv.org/abs/2611.20882v1) · [PDF](https://arxiv.org/pdf/2611.20882v1)

- **关键困难**：同一源码因构建与运行时设置性能差 0.29x–2.12x，改动收益相互依赖，难以归因且须保持计算正确
- **解决方案**：每个任务提供可运行程序并规定负载、正确性要求、时间边界与允许改动；智能体自行决定优化点，公开测试用于迭代，独立验证器对最终提交打分

## 2611.20455 · Embeddings vs. Grep: Rethinking the Dense Advantage in Code Search
*Embeddings vs. Grep：重新审视代码搜索中的稠密检索优势*

- Siqiao Xue, Ziyin Zhang, Zihan Liao, Jin Qin, Yixiang Mu, Hang Yu
- [Abs](https://arxiv.org/abs/2611.20455v1) · [PDF](https://arxiv.org/pdf/2611.20455v1) · [Code1](https://huggingface.co/datasets/hq-bench/repo-premium)
- **核心问题**：稠密检索在代码搜索基准上大幅领先 BM25，但编码智能体用 grep 仍表现良好，该优势究竟度量了什么尚不清楚
- **关键困难**：现有基准使用精心构造查询、旧代码和被削弱的 BM25，无法公平区分稠密检索的真实收益与评测偏差
- **解决方案**：构建含6种语言、2022–2026 PR、91个仓库的仓库级基准，统一排序文件，比较公平 BM25 与稠密检索，并测试 LLM 生成标识符扩展查询
- **主要结果**：优势源于分块 BM25、编辑测试计相关等评测偏差及查询缺稀有标识符；LLM 扩展查询使 BM25 在各 Python 池追平稠密检索
- **未来方向**：尚无方法预测单查询上哪种检索器胜出；需公平词法基线、稠密与 BM25 融合、查询补词

## 2611.20297 · Reliable Mining of Heterogeneous AI Coding-Agent Data: Context-Aware Prediction and Resource-Aware Ranking
*可靠的异构 AI 编码智能体数据挖掘：上下文感知预测与资源感知排序*

- Haoran Yu, Lifei Liu, Danping Zhang
- [Abs](https://arxiv.org/abs/2611.20297v1) · [PDF](https://arxiv.org/pdf/2611.20297v1)
- **核心问题**：跨智能体、仓库、任务的异构操作记录汇总后会反转描述性与预测性结论，需要可靠的数据真实性处理
- **关键困难**：各智能体与工作流的数据分布差异大，简单池化导致混杂与辛普森悖论式偏差
- **解决方案**：构建来源、环境、工作流三类上下文的特征级联提升合并预测；用仓库聚类 AIPW 区间与交叉拟合观测模式泛函检验调整后关联并评估评审资源分配
- **主要结果**：合并预测 AUC 0.774→0.832，时序 0.801、未见仓库 0.807；共同作者系数 -1.09→+1.44；30% 预算双重稳健增益 +12.3 点，仅比风险排序高 0.5 点
- **未来方向**：结论为基于元数据状态的回顾性决策支持，非分配人工评审的因果效应

- [Abs](https://arxiv.org/abs/2611.20218v1) · [PDF](https://arxiv.org/pdf/2611.20218v1)
- **核心问题**：编码智能体进入软件组织后需自行确定要做什么、与同事协作并验证交付结果
- **关键困难**：需求分散且证据冲突，现有方法无法在澄清、实现、验证、交接全程持续追踪需求
- **解决方案**：101个真实仓库任务，每任务配26名知识有界、协作行为受控的虚拟同事；智能体从简短交接启动，恢复并调和需求后实现改动，由私有可执行测试评分，并做需求级轨迹分析

- **未来方向**：需求追踪须贯穿澄清、实现、验证与交接全流程

## 2611.19822 · The Flip Test: Video World Models Fail to Learn the World State
*翻转测试：视频世界模型未能学习世界状态*

- Mi Luo, Lijun Yu, Adams Wei Yu, Ang Cao, Baochen Sun, Ming-Hsuan Yang, Nan Hua, Yuan Hao, Alex Dimakis, Ya Xu, Ed H. Chi, Xuezhi Wang, Yinxiao Liu
- [Abs](https://arxiv.org/abs/2611.19822v1) · [PDF](https://arxiv.org/pdf/2611.19822v1)
- **核心问题**：视频世界模型能否从当前帧预测未来，并捕捉控制未来动态的世界状态（如物体是否越过桌沿）
- **关键困难**：模型对不改变未来的微小变化与改变未来的变化反应相同，说明其响应仅由像素绘制驱动，而非因果状态
- **解决方案**：用 1,680 个初始帧（10 个仿真任务、15 个真实任务）构建最小对与稠密扫描，定位预测翻转位置，并与 VLM、编码代理对照
- **主要结果**：评测的 11 个视频世界模型全部不达标，最佳配对准确率 18.3%，低于随机猜测 25%；VLM 呈近 S 形选择性曲线，编码代理接近真实边界
- **未来方向**：呼吁将世界建模从纯视频预测转向同时识别控制未来动力学的因果状态

## 2611.19700 · Where Should LLM Agents Adapt at Test Time? In Context, in Weights, or Both
*LLM Agent 应在何处做测试时适配？上下文、权重，还是两者兼具*

- Parsa Mirtaheri, Mohammadreza Armandpour, Keivan Alizadeh, Iman Mirzadeh, Parshin Shojaee, Aryo Lotfi, David Harrison, Mehrdad Farajtabar
- [Abs](https://arxiv.org/abs/2611.19700v1) · [PDF](https://arxiv.org/pdf/2611.19700v1)
- **核心问题**：LLM 智能体在代码库、数据库等重复环境中如何利用经验做测试时适配，上下文与权重两条通道各自贡献不明
- **关键困难**：两条适配通道通常被分开研究，难以判断各自收益大小以及何时互补
- **解决方案**：共享在线协议与模块化框架：智能体遍历匹配任务流，先评测再适配，仅从自身尝试与环境反馈学习，比较 14 种适配机制与无状态基线
- **主要结果**：Qwen3.5-9B、109 任务：ICL 最佳策略将平均成功率 28.8%→49.4%，加 GRPO 达 51.6%；SDPO 效果不一
- **未来方向**：ICL 常跳过检查与验证，需联合研究上下文管理与权重更新

## 2611.20078 · Infrastructure-Based Multi-Agent Reinforcement Learning with Attention for Highway Ramp Merging
*面向高速公路匝道合流的基于基础设施的多智能体强化学习与注意力机制*

- Chenhao Tong, Steffen Müller
- [Abs](https://arxiv.org/abs/2611.20078v1) · [PDF](https://arxiv.org/pdf/2611.20078v1)
- **核心问题**：密集车流下匝道合流难以形成有效的交通状态观测，容易引发事故与拥堵
- **关键困难**：仅观测邻近车辆易陷局部最优，观测全局交通又引入大量无关信息
- **解决方案**：路侧基础设施控制器通过 V2I 收集所有 CAV 状态，用 Transformer 注意力编码器为每辆车过滤相关车辆信息，并回传控制指令
- **主要结果**：在 SUMO 中，交通流量、安全性与平滑性均优于三个基线；在四小时动态需求仿真中避免拥堵，且在 V2I 通信误差下仍保持无碰撞与吞吐
