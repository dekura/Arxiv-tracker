## 2610.40565 · Gym-Anything for Robotics: Scaling physical simulations with digital agents
*Gym-Anything for Robotics：用数字智能体扩展物理仿真*

- Pranjal Aggarwal, Sean Welleck
- [Abs](https://arxiv.org/abs/2610.40565v1) · [PDF](https://arxiv.org/pdf/2610.40565v1)
- **核心问题**：现有机器人仿真仅覆盖少量真实任务与物理现象，依赖专家手工构建，难以规模化扩展
- **关键困难**：提升仿真覆盖与保真度需大量专家投入，创建成本高且无法随需求规模化
- **解决方案**：让编码智能体生成仿真与任务，按美国GDP数据选取经济价值高的物理工作，定义好坏仿真和任务标准，并用对抗式创建-审计循环逐项校验，构建RoboWorld
- **主要结果**：RoboWorld含25仿真、25测试和175训练RL环境；最强前沿模型测试平均奖励仅0.06，多种改进方法均显著提升

## 2610.40256 · When Requirements Interact: Scaling Long-Horizon Coding via Interdependent Specifications
*当需求相互交互：通过相互依赖的规格扩展长周期编码*

- Yishuo Cai, Minzheng Wang, Liang Zhao, Linghao Zhang, Lei Li, Shicheng Li, Xu Sun, Fuli Luo
- [Abs](https://arxiv.org/abs/2610.40256v1) · [PDF](https://arxiv.org/pdf/2610.40256v1)
- **核心问题**：真实长周期软件开发需同时满足接口兼容、错误处理等多维规格且不破坏既有依赖，现有任务规格数量与多样性不足。
- **关键困难**：朴素添加规格会把任务退化为清单式检查而非联合推理；验证微妙交互易漏隐藏缺陷或误拒合法方案。
- **解决方案**：以真实开发者种子为起点，合成代理迭代构建相互耦合的任务需求与测试，审查代理基于多模型解题轨迹审计测试可靠性，构建训练任务与基准。
- **主要结果**：构建 4,670 个训练任务覆盖 2,865 个仓库；RL 训练后在 DeepSWE-v1.1 上显著优于基线与现有方法；CodeSpecWeave-Bench 含 100 任务、1,044 条规格，可区分前沿模型并显露余量。

## 2610.39711 · Sandman: Building and Operating Sandboxes for Agentic Reinforcement Learning on Shared Kubernetes
*Sandman：在共享 Kubernetes 上构建与运维 Agentic 强化学习沙箱*

- Yiming Yan, Hongyang Wang, Wenbo Chen, Xuan Wang, Jingguo Liu, Xian Li, Chen Qi, Leo Fan, Siwei Li, Qianli Wu, Yichuan Li, Ruochen Wen, Qian Qu, Zheshen Wang, Benoit Dumoulin
- [Abs](https://arxiv.org/abs/2610.39711v1) · [PDF](https://arxiv.org/pdf/2610.39711v1)
- **核心问题**：Agentic RL 需在任务专用环境中反复调用工具，训练任务会在共享集群上突发创建成千上万个环境
- **关键困难**：创建突发、任务环境准备、废弃沙箱回收以及受控条件下的评测，在共享集群上都难以高效可靠地处理
- **解决方案**：训练框架提供任务镜像，Sandman 将其作为 pod 启动，并注入守护进程统一管理创建、就绪与清理；文件和进程持续保留，直到框架释放环境，同时以池化和回收应对突发
- **主要结果**：压测中维持 11,858 个并发小沙箱；2026 年 10 月四个生产 SWE-bench Verified 训练任务共创建 310 万个沙箱
- **未来方向**：将开源 Sandman 的 daemon、provider 与 pool

## 2610.39620 · Letting AI Formulate the Research Question: Autonomous Research Agents
*让 AI 自行提出研究问题：自主研究智能体*

- Ko Fujimura
- [Abs](https://arxiv.org/abs/2610.39620v1) · [PDF](https://arxiv.org/pdf/2610.39620v1)
- **核心问题**：既有 AI 科研系统由人选定研究领域并挑选展示结果，未考察 AI 自主提出研究问题的能力
- **关键困难**：开放问题构思易命中已知失败模式，缺少独立复算与评审，选择性报告掩盖失败运行
- **解决方案**：给现成编码智能体一份指令文档和两个技能：问题构思技能跨领域发散、按已知失败模式筛选候选并请另一模型批判；评审技能由异家族模型评审者依据记录复跑研究后再修稿，全部运行均报告
- **主要结果**：5 次连续运行（1 次 pilot + 4 次预注册）均从提问走到可复算修订论文，笔记本本地计算、无人工研究输入，外部 AI 评审仅读论文即评为工作坊级或接近

## 2610.39468 · Soei: Structured Observability of Evidence and Intent for Multi-Agent AI Software Engineering
*Soei：多智能体 AI 软件工程中证据与意图的结构化可观测性*

- Mohammed Nayeem Khan, K S Sarun Kumar
- [Abs](https://arxiv.org/abs/2610.39468v1) · [PDF](https://arxiv.org/pdf/2610.39468v1)
- **核心问题**：多智能体长时编程会话难以回答实际做了什么、由谁做、是否完成，缺少结构化证据与意图可观测性
- **关键困难**：现有日志事件管道不统一、本地变更面未认证，重放受体积限制，完成声明缺少独立证明
- **解决方案**：用acknowledgement-aware事件模式、哈希链本地账本、W3C PROV对齐图、校准归因与血统推断，以及将完成声明与证明分离的验证层
- **主要结果**：45会话中23.4%编辑episode无末次独立检查，57.8%完成待办无证明；账本占原始20%，验证126k events/s并检测篡改
- **未来方向**：需扩展语料，定义带证据门控的自主等级与harness指标

## 2610.39417 · Well-Specified and Well-Tested? Assessing SWE-bench-Style Datasets with a Self-Evolving Agent

- Zhonghao Jiang, Xuyang Zheng, Yanfu Yan, Zhongxin Liu, Lingfeng Bao, Shuiguang Deng

- **核心问题**：现有 SWE-bench 风格数据集存在任务清晰度与测试覆盖质量问题，人工标注成本高，LLM 标注易误报
- **关键困难**：现有 LLM 标注依赖静态、泛化 rubric，难以处理多样细粒度场景，假阳性率高
- **解决方案**：ExLabel 维护自进化经验库，将跨实例知识蒸馏为稳定且可适应的判断标准；评估新实例时检索并复用相关经验，实现上下文感知的任务清晰度与测试覆盖判断

## 2610.35488 · Benchmarking Coding Agents under Evolving Requirements
*FeatureLoop：在演进需求下评测编码智能体*

- Jia Feng, Alyssa Wu, Cuiyun Gao, Yunlong Wang, Songyuanyi Lu, Zhichao Hu
- [Abs](https://arxiv.org/abs/2610.35488v2) · [PDF](https://arxiv.org/pdf/2610.35488v2)
- **核心问题**：编码智能体在用户多轮细化需求时的持续引导与迭代能力缺乏可执行评测
- **关键困难**：仅看最终正确性无法刻画反复指导过程，失败阶段也较难在少量修正内恢复
- **解决方案**：用 61 个来自 34 个仓库、覆盖 5 种语言和 7 种软件形态的任务构建基准；在持续工作区注入演进反馈与完成反馈，用累积可执行检查验证新增行为、修复和旧功能保持
- **主要结果**：12 个前沿模型中最强在两类反馈下完成 72.1% 任务；仅 15.4% 的失败阶段能在两次修正内恢复
- **未来方向**：修复不完整、回归及反馈利用与 token 效率的模型差异是主要障碍

## 2610.36660 · The View from Nowhere: Population-Centered Agent Evolution
*无处之见：以种群为中心的智能体演化*

- Shuo Yan, Ningning Hou, Haoyu He, Haochen Pei, Shang Gao
- [Abs](https://arxiv.org/abs/2610.36660v2) · [PDF](https://arxiv.org/pdf/2610.36660v2)
- **核心问题**：现有自改进智能体只围绕选定父代及其演化经验改进，种群中其余智能体的信息基本未被利用
- **关键困难**：种群覆盖的任务成功率明显高于最佳单体智能体，说明有用能力与诊断证据散落在种群中却无法整合进领先智能体
- **解决方案**：PCE 将种群的任务记录与修改历史蒸馏成 population block，刻画反复失败、互补成功与既往自修改的效果，据此指导选定父代的 harness 改进
- **主要结果**：SWE-bench Verified 72.1%、Polyglot 96.7%，较强群体演化基线提升 3.2 与 5.9 个百分点；覆盖-最佳差距在 SWE-bench 缩小三分之一、Polyglot 上消除

## 2610.38800 · When Relevant Code Is Wrong: Runtime-Aware Context for AI Coding Agents
*当相关代码是错的：面向 AI 编码 Agent 的运行时感知上下文*

- Wesley K. G. Assunção, Ramesh Periyathambi
- [Abs](https://arxiv.org/abs/2610.38800v1) · [PDF](https://arxiv.org/pdf/2610.38800v1)
- **核心问题**：检索到的代码虽高度相关，却可能因特性开关、架构迁移或部署配置而失效，从而误导编码 Agent
- **关键困难**：语义相似度和时间新近度都无法判断证据在特定任务、部署与时刻是否仍可适用
- **解决方案**：CASE 将仓库产物与运行时配置及架构演化关联，判定证据有效、无效或未知，并生成区分可执行指导、历史理由与未解约束的上下文包
- **主要结果**：初步评测：传统检索把 16 处不兼容产物当作可执行指导，CASE 将其排除；按新近度过滤时有效召回为 0.43，去掉特性开关证据后降至 0.13
- **未来方向**：仅验证可行性，未证明提升编码正确性；需让 Agent 同时推理相关性与运行时有效性

## 2610.38799 · CARI: Cross-Boundary Adversarial Runtime Injection in Coding-Agent Workflows
*CARI：编码智能体工作流中的跨边界对抗运行时注入*

- Jie Fu, Shuang Wu, Ashish Kundu, Wendy Hui Wang, Yuan Hong
- [Abs](https://arxiv.org/abs/2610.38799v1) · [PDF](https://arxiv.org/pdf/2610.38799v1)
- **核心问题**：跨开发者、团队或服务的编码智能体工作流中，同伴组件可借运行时反馈影响另一角色智能体并触发越权操作。
- **关键困难**：同伴组件仅有诊断权限却无操作权限，现有方法未覆盖这种权限错配下的运行时反馈注入。
- **解决方案**：攻击者将恶意指令隐蔽嵌入任务相关运行时反馈，受害智能体在调试或恢复中把诊断指导转成未授权的本地文件、凭据、shell 或环境操作。
- **主要结果**：实例化10种攻击，覆盖4种语言和5个代码模型，成功率94.8%（2845/3000）；Codex达61.3%，Claude Code达58.7%。
- **未来方向**：提示级防御存在安全-效用权衡：通用警告无效，显式策略会过度拒绝合法操作。

## 2610.38617 · How Deterministic SAST and AI Security Agents Divide the Work: Coverage, Harness Policy and Cost in Snyk VulnBench 2.0
*确定性 SAST 与 AI 安全智能体如何分工：Snyk VulnBench 2.0 中的覆盖率、Harness 策略与成本*

- Liran Tal, Chris Liu, Charlotte Fereday, Sebastian Roth, Brian Clark
- [Abs](https://arxiv.org/abs/2610.38617v1) · [PDF](https://arxiv.org/pdf/2610.38617v1) · [Code1](https://github.com/snyk-labs/snyk-vulnbench)
- **核心问题**：AI 编码智能体与确定性 SAST 各自能发现对方漏掉什么漏洞，二者应如何分工
- **关键困难**：现有对比多在文件级或单一模型上评测，忽略 harness 策略差异，且定位判据宽松
- **解决方案**：构建 108 个手工标注、攻击者可触达的漏洞（62 个跨文件）基准；仅当 source 与 sink 均在两行内定位才计分；在统一盲协议下评测 9 种产品化配置
- **主要结果**：Snyk Code 82.4%（89/108）、Claude Code+Opus 5 达 79.3%（85/108），合并 101/108；AI 另报至少 7 个参考集外真实漏洞

## 2610.38521 · Security Impact of Coding Agent's Memory Files
