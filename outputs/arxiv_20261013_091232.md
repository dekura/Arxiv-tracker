## 2610.13841 · Returning to Development States: When Full Sandbox Snapshots Help Coding Agents
*回归开发状态：全沙箱快照何时帮助编码智能体*

- Daniel Thi Graviet, Tanmay Shah
- [Abs](https://arxiv.org/abs/2610.13841v1) · [PDF](https://arxiv.org/pdf/2610.13841v1)
- **核心问题**：编码智能体失败后从头重试丢弃中间环境状态，能否恢复并分支中间状态以提升解决率？
- **关键困难**：现有方法仅从单一 diff 重建进展，忽略数据库、服务等仓库外状态，长周期多服务任务恢复效果差
- **解决方案**：在 Daytona 全沙箱快照上实现 Go-Explore 搜索：保存中间环境状态，从有进展的状态恢复并分支继续，而非从头重试
- **主要结果**：全快照搜索提升解决率与效率，收益主要来自保留仓库外的数据库/服务/运行时状态，多服务长周期任务效果最好

## 2610.13668 · (When) Should a Software Factory be Lights-off? Benchmarking Code Review Agents on Bug Detection
*（何时）软件工厂应该实现无人值守？代码评审智能体的 Bug 检测基准评测*

- Chenyang Yang, Hao He, Ti-Chung Cheng, Jenna Butler, Emerson Murphy-Hill, Carmen Badea, Christian Bird
- [Abs](https://arxiv.org/abs/2610.13668v1) · [PDF](https://arxiv.org/pdf/2610.13668v1)
- **核心问题**：人类评审速度已跟不上智能体代码生成，全自主“熄灯”软件工厂是否可行，取决于评审智能体能否检测人工确认的 bug。
- **关键困难**：现有评审智能体在复杂改动与需非局部推理的 bug 上效果差，私有工业仓库因更需项目上下文而性能骤降。
- **解决方案**：构建 CRBugBench：从仓库历史挖掘人工确认 bug 并配对引入 PR 形成评审任务，含 1000 个开源任务与 800 个企业内部任务，按 top-5 评论命中率评测多个 SOTA 智能体。
- **主要结果**：claude-opus-5 配 copilot-cli 在 top-5 评论中捕获 71.9% 的 bug，五个月前 opus-4.6 为 47.7%；探索型提示以 10% 成本换最高 5.8% 提升。
- **未来方向**：复杂改动与需项目上下文场景仍表现不佳；建议按 PR 复杂度扩展评审力度、注入仓库知识、按 PR 特征分配模型并持续监控质量。

## 2610.13563 · Not All Correct Fixes Run Alike: An Empirical Study of Patch Performance in Repository-Level Issue Resolution
*并非所有正确修复都跑得一样：仓库级问题解决中补丁性能的实证研究*

- Han Peng, Xing Hu, Feifei Niu, Huan Li, Xin Xia
- [Abs](https://arxiv.org/abs/2610.13563v1) · [PDF](https://arxiv.org/pdf/2610.13563v1)
- **核心问题**：SWE-bench 等仓库级基准仅以正确性测试是否通过判定补丁，不同通过补丁的运行时性能差异基本未被考察
- **关键困难**：为每个基准实例单独设计性能工作负载成本高昂，导致补丁性能难以规模化评估
- **解决方案**：选取 SWE-bench 与 SWE-bench-Live verified split 中可测量实例，让 4 个前沿模型配 SWE-agent 生成多个正确补丁，在原生 F2P 测试上测指令数与墙钟时间，用 Welch ANOVA 做统计判别
- **主要结果**：得到 262 个含至少两个不同正确解的案例；近半数实例可区分出补丁性能差异，且补丁性能与 LLM 解决率无关，模型排名近乎相反
- **未来方向**：解决率不足以刻画仓库级问题解决能力，未来评测应同时考虑补丁性能

## 2610.13395 · ProgramGym: Scaling Training Environments for Long-Horizon Program Reproduction Agents
*ProgramGym：为长时程程序复现智能体扩展训练环境*

- Chengyi Yang, Renxu Bao, Jue Hou, Zongpei Teng, Ziheng Wang, Yujie Lin, Chengsong Huang, Junnan Zhu, Delai Qiu, Yining Wang, Shengping Liu, Fei Long, Jinsong Su
- [Abs](https://arxiv.org/abs/2610.13395v1) · [PDF](https://arxiv.org/pdf/2610.13395v1)
- **核心问题**：缺少可扩展、可验证的训练环境，让智能体自行发现需求并决定系统设计，而非仅在仓库内修 issue 或按需求文档生成仓库
- **关键困难**：现有智能体工作流无法支撑长时程开发，即先探索参考程序再进行实现；可验证训练环境稀缺
- **解决方案**：Program-Env 用反馈驱动环路修复运行时沙箱构建与黑盒测试质量，生成 1648 个覆盖 C/C++/Go/Rust 的环境；Program-Agent 以角色隔离工作流加修订管理支持编译检查与失败恢复
- **主要结果**：ProgramBench 上 SFT 将 Qwen3.8-27B 从 34.87% 提至 42.84%，Program-Agent 将 base 与 SFT 模型提至 55.71% 与 56.25%，超过部分旗舰模型

## 2610.13361 · AgentSWE: Can Coding Agents Build the Agent You Actually Want?
*AgentSWE：编码智能体能构建你真正想要的智能体吗？*

- Jiahao Wang, Hongjin Qian, Yuyang Hu, Jiajun Zhang, Zheng Liu
- [Abs](https://arxiv.org/abs/2610.13361v1) · [PDF](https://arxiv.org/pdf/2610.13361v1) · [Code1](https://github.com/VectorSpaceLab/AgentSWE)
- **核心问题**：编码智能体被委托构建贴合用户工作流的智能体，却无基准检验交付物是否真正满足需求，而非只是看似满足
- **关键困难**：现有基准不测试该假设；智能体易过拟合可见示例、留下空洞运行时、并声称已完成
- **解决方案**：AgentSWE 覆盖创建、编辑、优化三阶段的智能体开发生命周期；任务写成委托而非考试，验收时冻结提交，用覆盖完整需求的留出用例，按需求推导的 rubric 硬性通过/失败，优化阶段则用源基准目标
- **主要结果**：跨模型与 harness 的编码智能体无一接近满足需求；演示与交付之间的差距是常态而非个例；失败轨迹显示过拟合可见用例、空洞运行时、无依据的完成声明等反复出现的失败模式
- **未来方向**：这些失败模式可作为信号，让编码智能体学会构建被要求的智能体

## 2610.13356 · SWE-Critix: Post-Training Generalist Verifiers for Assessing Coding-Agent Trajectories
*SWE-Critix：面向编程智能体轨迹评估的后训练通用验证器*

- Jiajun Hu, Chun Yong Chong
- [Abs](https://arxiv.org/abs/2610.13356v1) · [PDF](https://arxiv.org/pdf/2610.13356v1)
- **核心问题**：端到端软件工程任务常缺乏现成的 oracle 评估器，需要能可靠判定并解释编程智能体行为的验证器
- **关键困难**：轨迹极长，含数百次与代码库及外部工具的交互；现有方法或无专门训练，或专职 critic 仅输出标量奖励
- **解决方案**：在 CodeForge-Preview 轨迹上对 30B 模型先做 SFT 再做 RL，使其同时输出完成标签与解释判断的自然语言分析
- **主要结果**：留出测试集分类准确率由 base Qwen3-30B-A3B 的 57% 提升到 SFT 后 66%、RL 后 78%；开源模型、数据集与训练代码

## 2610.13166 · Scaling Agentic Data for Long-Horizon Terminal Intelligence
*扩展智能体数据以实现长时程终端智能*

- Shun Zou, Ziyu Ma, Yi Zou, Yong Wang, Lin Chen, Zehui Chen, Guanhua Chen, Xiangxiang Chu, Feng Zhao
- [Abs](https://arxiv.org/abs/2610.13166v1) · [PDF](https://arxiv.org/pdf/2610.13166v1)
- **核心问题**：短轨迹只能展示命令与工具调用，无法体现智能体通过探索积累证据、依反馈调整策略并把中间结果变成最终交付物的过程
- **关键困难**：环境合成会提前完成或简化这些行为模式背后的关键工作，从而消除本应由智能体完成的探索、实现与验证环节
- **解决方案**：以真实专业工作为起点，用独立执行识别构建时被省略的关键工作，用所得证据指导环境重建；并在同一目标下逐步扩展任务，加入依赖前序结果、需要进一步探索与改进的新需求
- **主要结果**：构建 1.5K 任务环境并 SFT Qwen3.5-27B 得到 TerminalHorizon-27B，在编码智能体、真实生产智能体任务与通用推理共 12 个基准上全面提升；12 小时预算的 RSI 案例显示可持续迭代改进

## 2610.13152 · Quality, Not Just Outcome: A Structural Scoring Framework for Selecting Coding-Agent Trajectories for Supervised Fine-Tuning
*质量而非仅结果：为监督微调选择编码智能体轨迹的结构化评分框架*

- Sida Li, Yuanxin Liu, Shicheng Li, Linli Yao, Xu Sun, Haoli Bai, Xiaohui Li
- [Abs](https://arxiv.org/abs/2610.13152v1) · [PDF](https://arxiv.org/pdf/2610.13152v1)
- **核心问题**：现有做法只按最终补丁是否通过测试筛轨迹，忽略过程质量，低效交互模式仍被纳入模仿目标
- **关键困难**：成功轨迹也可能含重复文件查看、工具使用不稳、延迟修改等低效模式，直接被 SFT 学走
- **解决方案**：提出 TQS，直接在轨迹结构上计算围绕结构化收敛的信息聚焦、意图-行动对齐与策略动态信号，按分排序筛选子集再微调编码智能体
- **主要结果**：SWE-Bench-Verified 上，用 TQS 高分轨迹训练的智能体持续优于随机或低分子集训练的模型

## 2610.13065 · TestSuiteBench: Coding Agents Struggle to Generate Strong Test Suites from Specifications
*TestSuiteBench：编码智能体难以从规格说明生成强测试套件*

- Kazuki Egashira, Niels Mündler-Sasahara, Mark Niklas Müller, Martin Vechev
- [Abs](https://arxiv.org/abs/2610.13065v1) · [PDF](https://arxiv.org/pdf/2610.13065v1)
- **核心问题**：现有测试生成基准只覆盖单个函数或缺陷修复，缺乏为复杂软件从规格从零生成完整测试套件的基准。
- **关键困难**：前沿编码智能体生成的测试套件突变分数低于60%，缺少相关输入组合且规模小于参考套件。
- **解决方案**：构建TestSuiteBench：165个应用各含结构化规格、参考实现、参考测试套件与平均74个单需求突变体，73%突变体仅被一个参考测试杀死，用于评测规格到测试生成。
- **主要结果**：前沿编码智能体突变分数<60%，88%测试通过参考实现，实现通过82%参考测试；生成套件缺少输入组合且更小。

## 2610.13025 · Evo$^2$: Evolving the Evolver through Weight-Harness Co-Evolution
*Evo$^2$：通过权重-Harness 协同演化来演化演化器*

- Chejian Xu, Shujian Zhang, Wenxuan Zhou, John Lambert, Beck Chen, Bo Li, Andrew Hard, Rajiv Mathews
- [Abs](https://arxiv.org/abs/2610.13025v1) · [PDF](https://arxiv.org/pdf/2610.13025v1)
- **核心问题**：自演化智能体只沿权重更新或 harness 改写单一方向改进，忽略了模型权重与 agent harness 之间的关系
- **关键困难**：权重更新与 harness 改写彼此割裂、缺少连接机制，自演化不连贯且效果受限
- **解决方案**：统一双角色流水线：同一策略既写 harness 编辑，又诊断效果并指导修订；EvoTIDE 用编辑抽取与前缀续写恢复可用轨迹，再用 SFT 与交替 GRPO 联合训练两个角色
- **主要结果**：Polyglot 82.1% vs 最强基线 62.6%，SWE-bench Verified 48.3% vs 41.0%；演化后 harness 跨任务迁移并跨基准排名第一；GPT-5-mini agent 由 24.4% 提升至 48.3%

## 2610.13022 · Don't Guess, Just Ask: Evaluating Interactive Requirement Clarification for Repository-Level Software Development
*别猜，直接问：评估仓库级软件开发的交互式需求澄清*

- Mingyu Chen, Zhiqing Zhong, Manyi Wang, Linxi Liang, Rouyu Chen, Pinjia He
- [Abs](https://arxiv.org/abs/2610.13022v1) · [PDF](https://arxiv.org/pdf/2610.13022v1)
- **核心问题**：现有基准只评测完整或欠明确规格下的实现，忽视编码前需求澄清，且澄清研究多局限于函数级任务
- **关键困难**：用户以模糊意图起步，仓库级误解会传播放大造成高成本返工，函数级澄清结论难以迁移到仓库级
- **解决方案**：ReqClarifyBench 含 341 个游戏、小程序、网页任务，配以真实对话衍生的多角色 LLM 用户模拟器，从澄清有效性与生成需求文档质量两方面评测六个 LLM
- **主要结果**：澄清有效性更强不必然带来更高需求文档质量，表现随用户角色差异显著，编码 agent harness 相较其基座 LLM 未提升需求文档质量

## 2610.12849 · Co-Modifying Application Code and Deployment Infrastructure: A Causal Study of AI Agent Pull Requests
