## 2610.36188 · Skill Dreaming: Evolving Repository Skills through Pull Request Streams
*Skill Dreaming：通过 Pull Request 流演化仓库技能*

- Xinyuan Song, Hasibul Haque, Jay Somasundaram, Ryan Turner, Bowen Zhu, Liang Zhao
- [Abs](https://arxiv.org/abs/2610.36188v1) · [PDF](https://arxiv.org/pdf/2610.36188v1)
- **核心问题**：仓库专用技能需随代码结构、实现约定与维护需求演化，PR 中积累的经验未被系统复用
- **关键困难**：新 PR 需遵循仓库实现模式、同步修改相关组件并保持既有测试通过，通用技能难以覆盖
- **解决方案**：从已验证 PR 提取可执行知识构建仓库技能库，随新 PR 持续更新；串联 PR 分析、技能管理、代码执行与 CI 形成闭环
- **主要结果**：构建端到端工作流，将学习到的技能用于仓库变更，并把后续 PR 结果回流更新技能；摘要未给出定量结果

## 2610.36153 · Stratum: Repository Memory for Coding Agents Beyond the Context Window
*Stratum：超越上下文窗口的编码智能体仓库记忆*

- Yuvraj Sehgal, Mahsa Panahandeh, Naser Ezzati-Jivan
- [Abs](https://arxiv.org/abs/2610.36153v1) · [PDF](https://arxiv.org/pdf/2610.36153v1)
- **核心问题**：编码智能体每次会话都无历史记忆，重复读文件、重试失败方案、遗忘已定位的根因
- **关键困难**：瓶颈在知识选择而非容量：47% 共编辑文件对无结构连通，KV 缓存存储代价高 10^4–10^5 倍
- **解决方案**：把经验感知的持久记忆与仓库共存，按层存储索引文本，通过明确说明返回内容、剩余内容与代价的页安全工具服务检索
- **主要结果**：8 个真实缺陷多会话实验中，继承他模型会话记忆的新智能体 24 次中 21 次定位根因文件，检索基线仅 6/24（Fisher p<1e-4），中位 token 成本低 4.5 倍；八项调查笔记合并后仍 8/8

## 2610.36015 · Do Coding Agents Still Need a Debugger? Frontier-Model-Based Fault Localization at the Accuracy Ceiling
*编码智能体还需要调试器吗？准确率天花板下基于前沿模型的故障定位*

- Christoph Daxerer, Johann Glock, Christian Macho, Rudolf Ramler, Martin Pinzger, Josef Pichler
- [Abs](https://arxiv.org/abs/2610.36015v1) · [PDF](https://arxiv.org/pdf/2610.36015v1)
- **核心问题**：编码智能体仅凭源码能否准确进行故障定位，调试器辅助能带来多少提升、代价多大，以及可选时智能体是否使用调试器。
- **关键困难**：早期智能体不擅长静态执行追踪和调试器操作，且调试器交互成本高；变换后程序可能破坏定位，前沿模型下是否仍需调试器不明。
- **解决方案**：向144个LeetCode解答注入610个单行故障，并用5种行为保持变换重写；让Sol 6.1、Luna 6、Qwen 3.8智能体在无/可选/鼓励调试器下定位，记录准确率与token。
- **主要结果**：无工具原始/变换程序定位98.2–99.9%/96.7–99.9%；鼓励调试器消除Luna 6和Qwen 3.8剩余变换错误63%/61%，提升2.1/1.3点，token为14.7–27倍；可选时仅0.2–6.2%运行用调试器仍增益1.5/1.3点。
- **未来方向**：仅限短小且规格精确的程序；未涉及大型仓库、多行故障和真实开发流程。

## 2610.36010 · CIVER: Causal Intervention Verification for Reliable Code Review
*CIVER：面向可靠代码评审的因果干预验证*

- Xinyuan Song, Hasibul Haque, Jay Somasundaram, Ryan Turner, Bowen Zhu, Liang Zhao · WWW 2026
- [Abs](https://arxiv.org/abs/2610.36010v1) · [PDF](https://arxiv.org/pdf/2610.36010v1)
- **核心问题**：LLM 代码评审常产生冗长、含大量误报且缺乏证据的不可靠审查意见
- **关键困难**：现有评审无法区分可行动缺陷与无证据声明，误报会误导开发者与下游编码代理
- **解决方案**：评审模块评估发现，干预模块生成修复导向扰动，验证模块打分；专家迭代联合优化，使真缺陷在针对性修复下响应，无关改动下稳定
- **主要结果**：SWE-Review-Bench 正确识别 77% 真缺陷；跨项目与下游修复评测显示可泛化并提升编码代理成功率

## 2610.35992 · Before the First Edit? Measuring When Coding-Agent Guidance Actually Arrives
*在首次编辑之前？测量编码智能体指导实际何时到达*

- Thupakula Sai Varun
- [Abs](https://arxiv.org/abs/2610.35992v1) · [PDF](https://arxiv.org/pdf/2610.35992v1)
- **核心问题**：编码智能体框架声称在首次源码编辑前提供指导，但实际拦截的是哪个事件、指导是否真先于首次修改缺乏可验证证据
- **关键困难**：公开轨迹缺同步文件系统状态，无法定位首次突变；规定动作比较也无法反映智能体收到计划后如何继续执行
- **解决方案**：在公开软件 issue 上运行本地 Qwen2.5-Coder 14B 智能体，对每个已执行动作前后哈希 Python 文件，做 76 臂 pilot 研究并辅以后验局部目标与回归选择器测试
- **主要结果**：15 臂跨 7 任务 3 仓库修改 Python 源码；指导均先于首次变更，但未达预注册 20 臂覆盖目标；7 个变更臂通过选择器，其中 4 个回归列表不完整
- **未来方向**：数据未证明规划提升修复正确性，也未覆盖 shell 首写；需同步文件系统状态并扩大覆盖

## 2610.35987 · PROBE: Frontier Coding Agents Find Different Bugs Than Maintainers Fix
*PROBE：前沿编程智能体发现的 bug 与维护者修复的不同*

- Marco Paina, Mark Niklas Müller, Niels Mündler-Sasahara, Martin Vechev
- [Abs](https://arxiv.org/abs/2610.35987v1) · [PDF](https://arxiv.org/pdf/2610.35987v1)
- **核心问题**：编码智能体已广泛用于软件工程，但其在整个仓库范围内找出人类维护者会修复的全部 bug 的能力尚未被研究
- **关键困难**：缺少以维护者实际修复为参考、覆盖整仓库的 bug 发现基准，无法同时衡量召回与精度
- **解决方案**：将 20 个 GitHub 仓库 18 个月内修复的全部 2457 个 bug 作为部分参考集，设计候选发现与参考集的匹配方法，评测前沿模型智能体的召回、精度及发现分布
- **主要结果**：召回低于 21%、精度低于 9%；更强模型召回由 8% 升至 17%，精度未提升；85% 候选发现被 LLM 与人工评为有效；各智能体发现分布相近，但显著不同于维护者修复的 bug 分布
- **未来方向**：参考集仅为部分 bug 集合，评测止于召回与精度，未给出提升 bug 发现能力的训练方法

- **关键困难**：安全关键汽车软件需逐变更审查、需求追溯并符合MISRA/AUTOSAR，且领域数据稀缺，通用LLM不熟悉分层架构与接口约定

## 2610.35980 · UnityBench-Mini3D: Evaluating LLM Agents for 3D Game Development in Unity

## 2610.34847 · Ethics by Configuration: AI Ethics Principles in Coding Agent Instructions

## 2610.35971 · Continue or Restart? The Limits of Early Failure Prediction in Coding Agents
*继续还是重启？编码智能体早期失败预测的局限*

- Srinath Srinivasan, Lunxiao Li, Tim Menzies, Wesley Assunção
- [Abs](https://arxiv.org/abs/2610.35971v1) · [PDF](https://arxiv.org/pdf/2610.35971v1)
- **核心问题**：编码智能体能否在早期可靠预测失败并提前停止，从而节省算力
- **关键困难**：早期前缀对同任务内失败判别接近随机，跨任务排序提升不等于可停止决策
- **解决方案**：对比预执行上下文与5k–20k早期前缀，测试线性计数、初始轮嵌入、任务条件排序器和微调Qwen3-0.6B监控器；在共享token预算下回放重启与继续并做代数分解
- **主要结果**：20k token同任务AUC约0.50；75k上限下学习重启仅比随机重启高≤1.98pp，继续在四设置中解率更高且token更省
- **未来方向**：需建立尝试级判别并证明相对持续运行的净算力节省

## 2610.34763 · The Physical Cost of Context: Quality-Constrained Resource Accounting for Coding Agents
*上下文的物理成本：面向编码智能体的质量约束资源核算*

- Zhongming Yu, Yitong Ma, Hengjia Yu, Boqin Yuan, Xiangye Lin, Hejia Zhang, Jishen Zhao · NeurIPS 2026
- [Abs](https://arxiv.org/abs/2610.34763v1) · [PDF](https://arxiv.org/pdf/2610.34763v1)
- **核心问题**：现有上下文策略只看省下的提示词 token，忽视调用次数与前缀复用对实际执行成本的影响
- **关键困难**：更短提示词若重写缓存历史反而更贵，单看 token 无法反映预填充、能耗等真实开销
- **解决方案**：质量门控协议：执行预填充=逻辑提示词−复用前缀，测量 KV 驻留、时间、能耗，并对比预加载检索块、锚定历史压缩、按需检索与历史裁剪策略
- **主要结果**：Eager 比 Grep 少 35.7% 调用、33.2% 能耗代理；开启前缀缓存后未缓存预填充降 67.7%；Mask-5 省 33.3% token 却使未缓存预填充增 608.5%

## 2610.34654 · Thinking-in-Bets at Test Time Reduces Sycophantic Revisions in LLM Agents
*测试时 Thinking-in-Bets 减少 LLM 智能体的谄媚式修订*

- Nghi D. Q. Bui
- [Abs](https://arxiv.org/abs/2610.34654v1) · [PDF](https://arxiv.org/pdf/2610.34654v1)
- **核心问题**：智能体被用户质疑时倾向放弃正确工作，而简单要求坚持又会忽略真实错误
- **关键困难**：读过投诉后智能体会低估自己先前的检查，为迎合用户而改错；事后补记录收益很小
- **解决方案**：读取用户反馈前私有记录主要主张、支持检查与置信度形成 Claim Checklist；受质疑时据此保留已验证工作，只复查不确定或被新质疑部分，并按不确定性门控记录以省 token

## 2610.34613 · Do AI Coding Agents Write Infrastructure as Code Like Humans? An Empirical Study of GitHub Pull Requests
*AI 编码智能体写基础设施即代码是否像人类？基于 GitHub Pull Request 的实证研究*

- Amine Barrak, Emna Ksontini, Charles Wehbe
- [Abs](https://arxiv.org/abs/2610.34613v1) · [PDF](https://arxiv.org/pdf/2610.34613v1)
- **核心问题**：AI 编码智能体提交的 IaC PR 与人类、自动化机器人有何差异，维护者如何评审，是否带来不同的可持续性问题
- **关键困难**：现有研究缺乏对智能体来源的细粒度区分，未控制仓库与变更类型差异，难以判断合并率与可持续性气味是否源自智能体
- **解决方案**：分析 49,241 个仓库的 349,156 个 IaC PR，按作者类型分层，比较规模、修改模块与合并率，并在同仓库内及 2,645 对匹配的 Terraform PR 上对比可持续性气味
