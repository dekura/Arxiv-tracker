## 2610.23782 · Enforcing Code Reasoning in Agentic Scaffold for More Effective Issue Resolution
*在 Agentic Scaffold 中强化代码推理以更有效地解决 Issue*

- Changshu Liu, Ji young Kim, Alireza Ghazanfari, Saanvi Nallu, Reyhaneh Jabbarvand
- [Abs](https://arxiv.org/abs/2610.23782v1) · [PDF](https://arxiv.org/pdf/2610.23782v1)
- **核心问题**：ReAct 编程代理是否以及如何对代码进行推理尚不明确，且推理过程基本缺乏引导。
- **关键困难**：代理定位易停留在表面症状，难以细化接近正确的补丁，并忽略需求与边界用例。
- **解决方案**：DeskCheck 分阶段引导代码推理：模拟执行路径定位根因，模拟候选补丁细化接近正确的补丁，按需求审计补丁，并在生成测试前推理边界输入与预期输出。
- **主要结果**：在 731 个 SWE-bench-Pro 实例上，相较 mini-SWE-Agent 与 Claude Code 解决率提升 6.29%–10.53%，每实例平均增加 $0.14；McNemar p<10^-10。

*MobileInject：评估基于 MLLM 的移动智能体在跨模态一致性注入下的推理到行动安全*

- Songping Wang, Peiyang Li, Yi Huang, Fengting Li, Xuhao Ran, Yueming Lyu, Chao Feng, Caifeng Shan
- [Abs](https://arxiv.org/abs/2610.23307v1) · [PDF](https://arxiv.org/pdf/2610.23307v1)
- **核心问题**：MLLM 移动智能体易受跨应用多模态间接注入，推理到行动安全缺乏系统评测
- **关键困难**：桌面与网页注入研究不覆盖移动跨模态特性，现有安全分析有限
- **解决方案**：构建含 11 场景、9 类风险、108 个可执行实例的交互评测框架，并加入多角色协作欺骗、推理伪装注入与推理安全诊断
- **主要结果**：移动智能体普遍易受多模态注入攻击，许多失败源于早期推理劫持

## 2610.23255 · Sample, Mix, or Verify? Allocating Test-Time Compute under Imperfect Verifiers
*采样、混合还是验证？在不完美验证器下分配测试时计算*

- Srinivasan Iyengar
- [Abs](https://arxiv.org/abs/2610.23255v1) · [PDF](https://arxiv.org/pdf/2610.23255v1)
- **核心问题**：固定预算下该采样多少、从哪些模型采样、花多少在验证上，目前仅凭经验规则决定
- **关键困难**：真实验证器会误收错答、误拒正解且错误相关，使验证带来的增益难以预测
- **解决方案**：推导 accept/reject 与 top-score 选择下提交正确答案的精确概率公式，刻画任务难度、跨模型共同盲点与验证器重复调用的相关性，再用经验贝叶斯从小规模标注试点拟合，并对未见任务分配预算
- **主要结果**：在7个基准、26个模型、175个智能体系统上，SPLIT 与事后最优分配仅差0.02–0.8个百分点，而各固定规则在某场景至少损失2.5个百分点
- **未来方向**：已公开报告失效情形；在验证器封顶成功率时作为预测器优于幂律拟合，但适用范围仍受限

## 2610.23241 · Towards Agentic Proof Harness Engineering
*迈向智能体化证明夹具工程*

- Rohith Kumar Shanmuganathan, Cedric Richter, Heike Wehrheim
- [Abs](https://arxiv.org/abs/2610.23241v1) · [PDF](https://arxiv.org/pdf/2610.23241v1)
- **核心问题**：真实项目形式验证中，proof harness 工程（符号输入、初始化代码、依赖建模）高度依赖人工，阻碍验证自动化
- **关键困难**：夹具既要形式可靠又要足够精确，依赖抽象容易过度近似或不足近似，手工构造成本高且难以复用
- **解决方案**：给定软件项目与验证目标，编码智能体自动构造 verifier-ready harness；formal soundness 与 precision 守卫验证生成的抽象，并指导其迭代精化
- **主要结果**：在 curl 与 libuv 的历史断言违规案例上，智能体生成的 harness 使 CBMC 检出全部 3 个违规，并初步展示 harness 在其他验证工具上的复用潜力
- **未来方向**：将 harness 复用到更多验证工具并扩大案例评估

## 2610.23134 · MetaCurate: Evolving Curation Filters for High-Quality Agentic Coding Data
*MetaCurate：进化式筛选过滤器用于高质量智能体编码数据*

- Donghoon Kim, Seunghyuk Oh, Kevin Galim, Minseo Kim, Minjae Lee, Younghyun Kim, Wooseok Seo, Hyung Il Koo, Wonjun Kang
- [Abs](https://arxiv.org/abs/2610.23134v1) · [PDF](https://arxiv.org/pdf/2610.23134v1)
- **核心问题**：智能体轨迹 SFT 中，成功轨迹可能推理低效、失败轨迹仍含有用步骤，如何自动筛选高质量训练样本
- **关键困难**：筛选规则设计依赖大量人工经验，反复训练评估验证改进成本高，人工规则难以兼顾成功与中间步骤价值
- **解决方案**：从空白过滤器出发，以过滤器排序与 LLM 判断偏好的不一致为定向反馈，联合进化规则、rubric 与聚合策略；最终过滤器独立打分，仅在搜索阶段做成对比较
- **主要结果**：在自建未筛选轨迹池与 Nemotron v3 SWE 数据上做受控 SFT，SWE-Verified 平均分高于随机选择、人工规则过滤及训练回路基线（其搜索成本为 3.5 倍）

## 2610.23044 · Where Does the Performance Go? Understanding and Recovering Performance Regressions in C-to-Rust Translation
*C-to-Rust 翻译中的性能去哪了？理解并恢复性能回退*

- Zhiqiang Yuan, Chong Wang, Zhenhao Zhou, Junwei Liu, Xin Peng
- [Abs](https://arxiv.org/abs/2610.23044v1) · [PDF](https://arxiv.org/pdf/2610.23044v1)
- **核心问题**：C-to-Rust 转译器能保持程序行为，但翻译后的 Rust 相比原 C 出现明显性能回退，缺少系统性归因与修复手段
- **关键困难**：行为保持不等于性能保持；回退根因分散在残留运行时开销、错失的编译优化与 C 风格源码模式中，通用改写难以定位
- **解决方案**：对比 C 与 Rust 版本的执行成本剖析、优化后 LLVM IR 与优化备注，归纳九类性能问题及优化方向；用规则匹配热函数，LLM 检查重写前置条件，仅保留通过功能与性能验证的改写
- **主要结果**：19 个操作中 12 个比原 C 慢，最高慢 62.2%；12 个留出项目 41 个操作全部保持 C 输出，40 个加速，18 个快于原 C；37 个可比操作中 31 个优于 Codex，41 个中 34 个优于无规则引导变体

## 2610.22039 · WEAVE: Weaving Real-World Code Evolution into Dependency-Structured Tasks for Benchmarking and Training Code Agents
*WEAVE：将真实世界代码演化编织成依赖结构化任务，用于代码智能体的基准测试与训练*

- Weihao Li, Zihang Xu, Zhongqiu Wang, Songwei Yu, Wenqiang Zhu, Yuechen Luo, Jingxuan Xu, Yanan Wu, Haoyang Huang, Aerial Deng
- [Abs](https://arxiv.org/abs/2610.22039v2) · [PDF](https://arxiv.org/pdf/2610.22039v2)
- **核心问题**：多数可执行仓库级基准以单个issue/PR为任务单元，多PR设置靠粗粒度聚合与结构无关评测，掩盖改动间依赖
- **关键困难**：长程代码智能体的进度难以度量、学习信号不足，改动依赖被掩盖，长程任务进展无法被忠实评估
- **解决方案**：用仓库校准的类型化变更位点把相关PR组织为有界DAG，统一实例化为可执行任务；Graph Credit基于测试确定性度量依赖一致的部分进度，提供稠密可验证奖励

## 2610.22987 · From Approval to Abuse: Privilege Escalation Attacks on Harness-Protected Coding Agents
*从批准到滥用：对受 Harness 保护的编码智能体的权限提升攻击*

- Xianglin Yang, Yechao Zhang, Jiahao Liu, Yulin Chen, Yuxin Cao, Bryan Hooi, Jiaheng Zhang
- [Abs](https://arxiv.org/abs/2610.22987v1) · [PDF](https://arxiv.org/pdf/2610.22987v1)
- **核心问题**：执行框架的 allow-rule 审批机制可被不可信上下文操纵，造成权限提升并在后续静默执行恶意动作
- **关键困难**：现有 harness 只拦截沙箱外动作并信任用户批准的规则，未考虑规则内容可被仓库上下文诱导而过度宽泛
- **解决方案**：在仓库植入对抗上下文，使智能体在常规任务中提出看似合理但语义过宽的 allow-rule；用户批准后规则持久化，harness 不再提示，攻击者据此静默执行原需审批的恶意操作
- **主要结果**：在 Claude Code 与 Codex CLI 上，58% 实验实例成功诱导目标 allow-rule；规则覆盖 56.9% 类别能力测试；获批后 47/58（81.0%）实例静默完成目标

## 2610.22881 · No One-Size-Fits-All: Adaptive Code Editing with Feature-Based Strategy Selection
*没有万能方案：基于特征策略选择的自适应代码编辑*

- Jun Wan, Zhongxin Liu, Dajun Chen, Wei Jiang, Yong Li, Xiaoxue Ren · Proc. ACM Softw. Eng. 3, ISSTA, Article ISSTA143 (October 2026)
- [Abs](https://arxiv.org/abs/2610.22881v1) · [PDF](https://arxiv.org/pdf/2610.22881v1)
- **核心问题**：现有 LLM 代码编辑系统对各类任务固定使用同一种编辑策略，且缺乏策略与任务关系的系统研究
- **关键困难**：任务在代码规模、修改类型与范围、语义复杂度上差异大，单一策略无法普遍最优，策略选择也缺乏可解释依据
- **解决方案**：构建 CEBench（500 条 SWE-bench 真实任务），对比 one-step、search-replace、plan-apply 三种策略并归纳四类关键特征，再训练 LLM 学习特征到策略的映射并输出选择理由
- **主要结果**：CEBench-verified 上 Pass@1 较最佳基线 AutoCodeRover 提升 21.7%，token 消耗降低 27.3%；策略选择准确率 72.6%，理由准确率 69.9%（κ=0.807）

## 2610.22791 · Self-Evolving Coding Agents via Harness-Policy Optimization
*通过 Harness-Policy 优化实现自进化编码智能体*

- Zhepei Wei, Wenlin Yao, Baolin Peng, Danqing Wang, Qianhui Wu, Hao Cheng, Yu Meng, Jianfeng Gao
- [Abs](https://arxiv.org/abs/2610.22791v1) · [PDF](https://arxiv.org/pdf/2610.22791v1)
- **核心问题**：编码智能体性能由策略与 harness 共同决定，二者需协同进化，但现有方法通常只优化其中一个
- **关键困难**：固定 harness 限制策略学习轨迹；旧 harness 针对旧 checkpoint，难匹配更新策略的失败模式
- **解决方案**：每轮策略先分析自身失败并生成 harness 候选（H-step），再在选定 harness 下用 RL 更新策略（P-step），训练中的难题作为下一轮 harness 搜索集
- **主要结果**：三个编码基准上平均 resolve rate 由 57.8% 升至 64.8%，超过仅优化 harness 或仅优化策略，且迁移到 OOD
